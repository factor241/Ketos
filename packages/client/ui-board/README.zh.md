# @deepseek-ai/dsh-client-ui-board

[English](README.md) | 中文

## 概述

board 是 dsh 网页客户端的一个空间化主面板：一块由可移动、可缩放、可叠放的 agent 窗口组成的无限画布，每个窗口拥有一个 Harness 会话与聊天 composer。车道把每次工具调用渲染为一张卡片（终端、读取、差异、搜索、引用、待办、图片、提问转录），显示已用秒数、本地化的失败或已停止状态，读不出的调用折叠为 JSON 块；待处理的审批会先显示横幅，再导航到主面板的应答 composer。dock 列出窗口，Omnibox 把提示词送进当前聊天，小地图镜像窗口布局。它使用共享主题绘制 `board` 面板。

## 使用本包

通过侧栏面板列表中的 board 图标打开该面板；画布填满主面板并从空开始。拖动背景平移，滚轮缩放（0.2–2.0，以指针为中心），用 dock 的加号按钮在当前视图中心添加 agent 卡片（右键点击加号会打开目录菜单：agent、连接器与设置窗口）。窗口交互遵循同一约定：拖动标题栏移动，拖动边缘手柄缩放单轴，拖动角手柄按比例缩放窗口（两轴同一系数，对角固定），按住 Shift 拖动可关闭 24 px 网格吸附；点击窗口将其提到 z 序最前，关闭按钮移除窗口。按住 Space 拖动或用中键拖动可在看板任意位置平移——浮动浮层上同样有效，中键拖动手柄时平移而非缩放——`Ctrl/Cmd+0` 重置平移与缩放。滚轮落在窗口车道上滚动该车道，落在画布或浮动浮层上则以指针为中心缩放。当前窗口的八个缩放手柄也会画在浮动浮层之上，因此滑到 dock、Omnibox 或小地图下方的窗口边缘依然可以抓取。手柄环落在窗口外框之外，因此画布缩小时标题栏控件即使被缩放到比条带还薄，也依然可以点击。离开可见画布的窗口停止绘制——其车道、草稿、附件与聊天面板保持存活——视图返回时原样恢复；全屏窗口的邻居同样让位。每次按 Escape 只执行一个动作，顺序为菜单、聚焦的编辑器、元素选择、聊天面板、全屏。窗口绝不会小于创建时的尺寸（agent 窗口的默认聊天尺寸 552×648）——composer 的各行无法在更小的空间内排布——而宽度、高度或对角方向的放大不受限制。窗口整体比应用放大一档：标题、车道文本、芯片、控件与 composer 都读取声明在看板根节点上的一组度量（`--board-font-*` 以及控件、内边距与间距值），因此外框与其内容一同变大，而 dock、Omnibox、小地图与 portal 菜单保持应用的尺寸。标题栏的聊天按钮会从窗口左缘滑出面板（左缘无空间时改用右缘）：它是窗口管理项目与聊天的控制面。项目层列出所有含可见聊天的工区，外加未分组一档；其标题栏可注册文件夹（浏览器按层列出目录、面包屑可点击、可创建嵌套文件夹，然后把选中的目录注册为项目；宿主挂载的是原生选择器时不提供目录列表，该层随即把选择交给原生选择器并注册它返回的目录）、打开搜索框，以及打开分组与排序菜单（按项目或单一列表；手动或按更新时间）。每行尾部都有菜单——项目可重命名、上移下移、删除（只删注册，聊天与文件保留）；聊天可重命名、从最近完成的回合创建分支（窗口随后显示子会话）、移动与归档——在行上拖动同样会提交移动。聊天层列出某个项目的聊天及其相对时间与运行标记；选择其中一个会让窗口指向它——若另一个窗口已显示该聊天，则把那个窗口带到前台而不改动本窗口——其标题栏可在该项目内新建聊天（仅在没有其他窗口显示时复用项目的空白聊天）。面板是画布之上独立的一层：默认 300px 宽，拖动外缘可在 260–420px 之间调整（永不超过外框留出的空间），高度与外框一致，并随窗口移动、缩放、平移或缩放画布而跟随。折叠时——以及从未打开过它的每个聊天窗口——同一边缘保留一条 44px 的紧凑导轨，让面板一键可开；面板自身的标题栏承载再次收起它的按钮。面板打开时看板的整个浮动浮层——dock、Omnibox 与小地图——一起让位；面板折叠为导轨后浮层随即返回，此时导轨不再遮挡任何东西。因此没有根级浮层会压住面板的外缘、缩放手柄，或 overlay 呈现下窗口的下缘。Escape 先关面板，再退出全屏。进入全屏后，面板贴着看板面板左缘成为普通侧栏，聊天在它旁边以 768px 列居中排布。在 dock 或小地图中选择窗口会聚焦它并把视图居中到其上，唯一的例外是当前窗口在 dock 中的行——点击它只聚焦。dock 的每一行都会解析窗口标题、窗口类型，以及其会话通道报告的状态——会话缺失、待创建或等待会话列表时为「创建中」或「恢复中」，回合执行时为「执行中」，创建、提示词、回合或会话消失导致的失败时为「错误」，其余为「空闲」——行的本地化无障碍名称把标题与状态并列；右键点击行会打开经 portal 渲染的菜单，提供重命名（就地编辑器）与关闭窗口，关闭会移除窗口，而其聊天仍存活并留在列表中。在加号按钮下方，dock 的克隆迷你面板逐行列出部署中的克隆（每行一个紧凑条目），点击某行会打开该克隆的编辑器窗口——若已打开则带到前台；标题栏与 dock 用聊天标题命名窗口，聊天还没有标题时回退到该类型经本地化的模板名，并跟随聊天重命名或重新绑定；点击标题栏中的名字——或双击 dock 行——可编辑窗口自己的名字，该名字覆盖聊天标题，直到被清空。窗口首次渲染时会创建自己的会话（该会话出现在侧栏列表中，聚焦窗口会使其成为当前会话）；从已保存布局恢复的窗口则重新附着到它当时显示的聊天，而宿主不再列出的聊天会让窗口停留在「缺失」状态——车道说明情况并提供「新建会话」与「选择聊天」，直到该聊天回归或选了另一个。Omnibox 在按 Enter 或 Send 时发送：它会去除草稿首尾空白，由桥把文本作为排队回合送进当前聊天窗口的会话，当前窗口不是聊天窗口时改开一个 agent 窗口；桥会等待会话创建完成，因此窗口刚打开就发送也不会丢失。其 `+` 菜单包含「新建窗口」一节——agent、连接器、设置与任务会打开真实的看板窗口，「新建克隆」会创建一条克隆记录并打开其编辑器窗口，仪表板则给出其本地化的「MVP 暂不提供」提示——「克隆」一节列出已存储的克隆记录（选择一条会打开其编辑器窗口，或把已在编辑它的窗口带到前台），「最近的聊天」一节列出最近更新的六个聊天及其目录（重新打开遵循同一「带到前台」规则），以及能力条目：附件把文件选择器命令路由到被寻址窗口的 composer，听写把语音转写切换进 Omnibox 草稿并在浏览器无法启动听写时给出提示，网页搜索说明在此 MVP 中没有从客户端通往宿主侧 web 能力的路径，选择元素则启用检查器；看板的所有菜单都经 portal 渲染，并开在空间更充裕的一侧。检查器激活时点击元素会捕获一个确定性的 `tag:nth-of-type(n)` 选择器路径——锚定在看板表面，或锚定在 `body`——以及一段语言无关的描述，涵盖元素的标签、所在窗口的类型与标题、`data-board-action`、无障碍名称、工具提示，以及 60 字符的文本摘录，并把本地化的芯片追加到被寻址窗口的 composer 草稿，寻址规则与 Omnibox 相同，即当前聊天窗口，否则新建 agent 窗口；浮层让指针通过，在捕获阶段取得点击，因此其下方的控件绝不会被激活，遇到打开中的菜单时让位，按 Escape 取消。composer 与主聊天一致：`+` 打开操作菜单（文件与图片、目标、计划、反馈、压缩、权限、导出），`/` 按输入过滤斜杠命令并显示参数提示与描述，`@` 提示文件、目录与会话，芯片行可切换权限预设（完全访问走风险确认）以及模型与其推理等级，圆环显示上下文占用——提供方首次报告前显示空态破折号，随后为正常、警告（超过 80%）与严重（超过 95%）三态，圆弧与读数同时着色，提示以 `% · used / window` 的紧凑单位显示——麦克风按钮在引擎提供语音识别时把语音转写写入草稿；以已知命令开头的行会带着参数对会话执行——连同草稿中的图片与已上传文件，因此不接受附件的命令由宿主以自己的原因拒绝——图片遵循宿主投影出的上限（超过数量、单张大小或总大小的批次会连同本地化原因被拒绝），其他文件后台上传并以回执随行；卡片还接受拖入的文件与粘贴进输入框的文件；agent 预设芯片是 composer 中唯一的设置芯片（工作目录由窗口的聊天面板承载），面板的文件夹动作会把选中的目录注册为新聊天的项目文件夹；新窗口以看板记住的预设启动——在芯片或 Omnibox 的「预设」条目中的最后一次选择会成为默认值、随布局保存，并应用到窗口新建的空白会话——宿主拒绝预设时会在 composer 下方给出本地化原因，会话已开始时芯片禁用并在提示中说明原因，无法组合会话的预设绝不会出现在菜单里；模型芯片的提示会说明当前模型与推理等级，并指出切换会保存为新会话的系统默认值；模型目录加载失败会在模型菜单内显示，窗口保持可用。Enter 发送，Cmd/Ctrl+Enter 引导正在执行的回合，Shift+Enter 换行，圆形按钮停止；每次发送都会在宿主准入之前先在车道中注册本地回声，草稿及其芯片在宿主拒绝提示时恰好原样返回一次（用户已继续输入的 composer 保留其更新的文本，并把被拒草稿作为新段落追加）；排队的消息连同其附件渲染在卡片上方的队列条中，并提供编辑（仅文本）、移除，以及回合运行时的引导，仍未等到对应队列行的排队回声渲染为「发送中」行，被拒绝的队列变更在队列条中显示宿主给出的原因，取消则保留宿主将按顺序恢复的排队工作；插话纠正——待定与持久——在车道中渲染为各自的用户气泡，持久的回合失败渲染为一张本地化卡片，其可展开详情携带提供方消息与错误码，重试操作重发失败回合的提示，而通道的通用失败行只在没有任何卡片承载该失败时出现；卡片会自行测量宽度，在窗口变窄时隐藏芯片文字或换行工具栏，因此发送控件在任何尺寸下都可达；`Load earlier turns` 以一次补偿性滚动写入（原生滚动锚定已禁用，避免调整叠加）把更早的回合拉入车道，保持读者的位置并在加载期间禁用自身；车道把每次工具调用渲染为自己的卡片，并在运行中的调用执行期间保持其已用秒数可见，卡片表读不出的调用回退为折叠的 JSON 块，已落定的结果所属调用落在已加载窗口之外时保留其不可用行与重试控件，而空、创建中、失败、运行与受阻状态各自渲染自己的本地化行；标题栏的全屏按钮让窗口铺满看板面板，按 Escape 或再点同一按钮即可返回；全屏期间其他窗口以及 dock、Omnibox、小地图都会让位，返回时恢复的是窗口保存的矩形。任务窗口按最新在前列出部署中的克隆自主任务，每行给出状态胶囊、目标与相对时间；待启动任务提供「开始」（创建任务随后运行的会话），待启动与执行中的任务都可取消，带有会话的任务可在聊天窗口中打开该会话，执行中的任务显示其已进入的目标回合数与任务上限。从克隆的「自动驾驶」表单打开的窗口默认只显示该克隆的任务——筛选行可在「此克隆」与「全部」之间切换——并带有「目标」表单，无需离开窗口即可存储并启动任务；行内的「报告」开关展开任务的 Markdown 摘要，以及从其会话记录中折叠出的文件产物。只要列表中仍有待启动或执行中的任务，主体每 750ms 重新读取一次任务列表，并在最后一个活动任务结束后停止。

克隆窗口编辑一条克隆记录，并在其档案被草拟期间承载草拟它的访谈。窗口状态携带该记录的 `cloneId`（随布局持久化，因此恢复的克隆窗口会重新打开对应的克隆），标题栏与主体之间有一条三页签条带：「档案」渲染卡片表单——名称、角色、简介、角色设定、方法论、首选模型路由与生命周期状态（`draft`、`interviewing`、`ready`）——旁边是修订指示与记录的更新时间。方法论字段按四个规范章节读取实时草稿，把每节标为已填写、空或无，在提示中列出缺口，并在字段为空时提供「插入模板」。技能区按行列出技能——名称与其描述，或名称不合 kebab 语法、重名、描述仍为空时的警告——行尾菜单提供编辑与删除，沿用聊天面板的行菜单约定；添加按钮打开的模态窗校验 kebab-case 名称、唯一性、100 个技能上限与各长度边界。「访谈」在与其他聊天窗口相同的对话主体中渲染窗口自己的 Harness 会话，因此访谈就是一场带普通 composer 的普通聊天，「记忆」把窗口主体切到 `clone-memory` 并渲染该克隆经 `/api/ketos.memory` 存储的记忆：`active`、`candidate` 与 `archived` 三个状态筛选胶囊、一个把查询拆成词元并按带引号前缀匹配的搜索框及其清除按钮、每条记忆一行并显示其状态、来源会话（没有来源时为「用户」）、更新时间、内容与标签、针对内容、标签与状态的就地编辑器，以及需要一次确认的删除；路由拒绝的读取会渲染带重试的失败行，而不是空的记忆列表；每次被接受的变更都会重新读取列表，宿主随即重建克隆 agent 的记忆快照，因此它的下一个回合能看到用户刚留下的改动。「开始访谈」（档案已存在时为「重新访谈」，旧草稿会保留到新保存取代它）按表单读到的修订号把克隆标记为 `interviewing`——在那里被拒绝就是整次失败，因此不会留下任何启动到一半的东西——然后创建会话、以访谈角色绑定它，并把该会话交给这个窗口，窗口随即切到「访谈」页签；宿主把访谈指令与草稿保存工具组合进那一个会话，并以一个开场轮次开启对话，状态为 `interviewing` 期间条带显示简短指令与已作答的交换条数。通过 `/api/ketos.clones` 保存卡片仍然按修订号校验：卡片已在别处修改时界面给出「已在别处修改」并重新读取记录，因此再次保存会覆盖更新的修订；克隆已离开名册时，窗口停留在缺失状态。每当访谈轮次落定，看板都会重新读取克隆名册，因此 agent 保存的档案会出现在表单中；被存储记录移动过的字段标为「智能体已更新」，用户未发布的文本始终保留，脏草稿把存储的修订号保留为一行待处理项，一键即可应用。访谈进行中克隆变为 `ready` 会升起一条检查提示，点击会打开「档案」页签。表单未保存的文本在 agent 修订后依然保留：存储的值会停在待处理行中，直到用户应用它们，而用户自己的保存绝不会显示为 agent 修订。删除只需一次确认，随后移除记录、其会话绑定及其编辑器窗口；表单下方的已绑定会话列表会打开任一绑定——窗口自己的访谈则改为把本窗口切到其「访谈」页签。首选模型选择器提供部署的模型目录与「部署默认」，把选择存为 `provider/model` 路由，新建的访谈会话会以它启动；该模型选择同时保存为 `agent-default-model` 系统默认值，模型芯片的提示已说明这一点。外框与 dock 以克隆命名该窗口——访谈会话生成的标题绝不会重命名该记录的窗口——直到用户重命名它。表单未保存的文本与 agent 变更标记在各页签之间保留：它们存放在看板 store 中，因此切换主体绝不会丢弃它们。

## 理解实现

**Runtime invariant:** 无已发布的 companion。面板条目把 `main` 槽位连同唯一的 engine store 一起注册，并声明它渲染的各个层；条目的销毁证明移除，同时可通过 `board.*` 槽位声明独立观察。

<details>
<summary>实现细节 — 点击展开</summary>

唯一的注册面：`apply` 以槽位方式组合看板。`main` 面板条目声明 `board.canvas`、`board.dock`、`board.omnibar`、`board.minimap` 并通过 `renderSlot` 渲染它们；canvas occupant 声明 `board.windows`；窗口层声明 keyed 的 `board.window`（每个窗口类型一份注册——实例经由 owner props 传入，因此一个 occupant 服务该类型的全部窗口）与 keyed 的 `board.window.body`（每种 body kind 一份注册），并把 body 分发器交给每个窗口外框；同一个 `apply` 还注册 `sidebar.panellist` 图标。keyed 的键就是 `WindowKind` 与 `WindowBodyKind` 联合类型，因此为未知键注册是编译错误。board 状态是一个在面板条目上声明的 `dsh-client-store` engine store——平移、缩放、视口盒、窗口映射、z 序与元素选择标志——配合纯 draft action（`setPan`、`setZoom`、`zoomTowardPointer`、`setViewport`、`addWindow`、`openWindow`、`moveWindow`、`resizeWindow`、`setWindowBodyKind`、`focusWindow`、`centerOnWindow`、`setWindowFullscreen`、`exitFullscreen`、`closeWindow`、`hydrate`、`setSelectingElement`）。持久化布局是宿主的 `ui-board` settings 命名空间：`board-settings.ts` 持有带版本的 schema，`client/board-layout.ts` 把 store 捕获为线上文档并修复已存文档，`client/board-persistence.ts` 采纳首帧缓存，并通过共享的 settings describe 镜像采纳服务器文档，且在修订版 CAS 之下以防抖方式写回变更。窗口 z-index 区间被限制在浮动浮层之下，且提起窗口只写入该窗口的取值，因此其他窗口保持各自的状态身份。每个层与外框都通过框架 `useStore` 席位读取同一个 handle；组件自身不持有任何订阅——标题栏拖动与每个缩放手柄都是自行读取手势起始缩放的叶子组件，因此画布缩放不会重渲染窗口 body，聊天面板也只在展开时订阅视图变换。可见文案由 locale 接管：`apply` 通过 `ctx.locale` 注册 `board` 命名空间词典，每个承载文案的条目声明该命名空间，从而在其组件上放置类型化的 `t` 席位。样式直接读取共享主题：每个组件在自身旁边拥有一个 CSS Module，内联样式只承载放置与随平移/缩放计算的度量，规则只引用 `--dsw-*` 语义别名——浮层面板使用主题的 layer-2 填充与 elevation 发丝描边（聚焦窗口重绑到业务强调色），内部分隔线为 0.5 px 发丝线，画布点阵跟随边框色阶。交互外框来自 `ui-primitives`：标题栏关闭按钮与 composer 动作使用 Harness 图标，dock 行与 composer 动作包在 `Tooltip` 中，Omnibox 的操作菜单是共享的 `Menu`，dock 控件位于 floating-fill token 上。因此看板与其他面板一样跟随外壳的明暗偏好。手势只有一个归属：每次拖动（画布平移、标题栏、窗口缩放、面板缩放、行重排）都经过 `pointer-gesture.ts`，它在 pointerup、pointercancel 或宿主组件卸载时结束，因此不会留下监听器或指针捕获。看板根节点持有唯一的非被动 wheel 监听器：跳过窗口车道与展开的聊天面板，其余位置缩放；画布容器上的 `ResizeObserver` 是已测量视口的唯一归属；离开画布的窗口通过 `culling.ts` 以 `content-visibility` 隐藏——绝不卸载。窗口会话位于 apply 侧的桥（`session-bridge.ts`）：窗口 id → 会话的映射、`sessions.create()`/`open()`/`binding()` 序列，以及 chat/会话订阅全部留在插件闭包中，绝不进入 store；每个窗口的车道状态——组装后的聊天、聊天标题、历史标志、运行中的调用、图片上限，以及回合与发送失败——通过每窗口一个身份稳定的 channel 重新发布；关闭窗口会丢弃它的桥记录，而会话本身保持存活并仍在列表中。该映射是持久的：桥在离散事件（创建、重绑、关闭）上把它交给持久化层，settings 段以 `bindings` 承载它并以整节替换的方式写入，因此关闭窗口的配对确实会离开分节，每次采纳都会恢复每个窗口的聊天；`sessions.list` 是权威，把已绑定窗口在「恢复中」「就绪」「缺失」之间移动，并让回归的聊天重新附着；一个会话只属于一个窗口——`bind` 返回 duplicate、same、unknown 结果，面板与 Omnibox 的最近聊天列表会把持有窗口带到前台，而不是打开第二个。外框与 body 注册把该 channel 暴露为 keyed hook `useWindowSession(windowId)` 以及 composer 回调（`ensureWindowSession`、`sendPrompt`、`cancelPrompt`、`loadOlderTurns`、`executeCommand`、`uploadFile`），因此一个注册即可服务所有窗口，组件只接收普通数据；`uploadFile` 通过宿主的后台上传服务暂存非图片文件，并把回执交给 composer，由提示或命令随行携带。看板外框共享寻址与放置规则：`open-window.ts` 解析命令作用于哪个聊天窗口（`resolveChatWindow`——当前聊天窗口，否则新建 agent 窗口），store 中的 `composerIntents` 队列携带追加文本与打开文件选择器两类命令，直到 `ComposerBar` 消费它们（文件选择器会等到 composer 能接受文件，窗口关闭则丢弃其排队命令），`element-capture.ts` 构造检查器芯片背后的确定性选择器与语言无关描述，`menu-placement.ts` 是每个看板浮层共用的单一规则，让列表开在更宽裕的一侧。Omnibox 的发送经过桥的 `whenReady` 等待，它在窗口拥有会话（或创建失败）时落定，因此窗口打开瞬间提交的提示词不会丢失。

</details>

## 模型体验

无模型体验：board 是纯浏览器画布，不注册任何工具、提示词段落或会话事件，渲染的一切都是 board 本地视图状态。

#### KV Cache 效果

无效果；board 不向任何模型请求添加内容，也不消费会话日志。

## 已知限制与暂缓事项

<a id="known-limitations-and-deferred-work"></a>

这些限制属于当前包的约束。

- **窗口车道渲染正文、插话、工具卡片与回合失败** —— assistant 文本以 Markdown 呈现且流式文本可见；每次工具调用都渲染为自己的卡片（`bash`/`pwsh`/`terminal_send` 显示为终端，`read` 显示为文件窗口，`write`/`edit`/`str_replace_editor` 显示为差异，`grep`/`glob` 显示为搜索结果，`web_search`/`web_fetch` 显示为引用，`todo_write` 显示为待办清单，`read_image` 显示为图片预览，`ask_user_question` 显示为已作答的转录），而卡片表读不出的调用——未知工具、畸形的结果、落在已加载窗口之外的调用头——回退为折叠的 JSON 块。运行中的卡片显示其已用秒数，并落定为成功、失败或已停止状态，本地化失败行下方是提供方自己的错误文本。该范围之外的转录节点——压缩检查点、达到输出 token 上限的回合，以及模型重试——目前什么都不渲染。
- **待处理的审批或提问会给窗口打上横幅并导航到主面板（为 MVP 决定）** —— 应答 UI（允许或拒绝、提问流程）位于主面板的 composer 中，因此窗口显示一条本地化的 `Confirmation required`（或 `Answer required`）横幅，其按钮选择会话并把主区域切回 Conversation；在请求得到解决之前，窗口自己的 composer 保持惰性，并以横幅的标题作为其原因。随后当看板面板回来时，看板会把发起窗口带到前台并短暂高亮。窗口内不渲染任何内联审批表面。
- **看板的文件芯片只存在于草稿期间** —— 非图片文件经宿主的上传服务暂存，并在其窗口存活期间以回执随行；芯片只保留名字与重试，不保留字节或上传进度，回执在窗口关闭后无法再次发送。`@` 提及插入纯文本而非编辑器芯片。
- **窗口 composer 保有自身的提交策略（在此决定）** —— Enter 排队，Cmd/Ctrl+Enter 引导，且不读取提交偏好设置：`ui-conversation` 的 `busyEnter` 偏好位于该插件的设置命名空间，且只映射裸 Enter 手势，而看板的窗口按文档在两个手势上保留排队/引导组合。
- **命令的失败行可能使用宿主原文** —— 处理程序被拒或附件被拒时，错误在「Command failed:」之后按宿主自己的措辞显示，而未匹配的行显示看板自己的未知命令文案；失败信息保留到下一次发送。看板的命令列表在宿主注册表之外补上自己的 `/file` 与 `/model` 条目（文件选择器与模型菜单）。
- **队列编辑只替换文本** —— 宿主的编辑动作只接受非空纯文本替换，因此其他内容块本来重要的排队消息会丢失它们；行的图片缩略图通过会话范围的对话缓存解析，读取失败时保留占位符；回合失败卡片的重试操作会排队一个新回合，因为客户端没有暴露原地重试回合的 API。
- **被拒绝的队列变更会留在屏幕上，直到下一次队列操作或发送** —— 队列条在其行下方渲染宿主给出的原因；没有逐行的错误状态。
- **助手 Markdown 保持应用的正文字号** —— 共享的 Markdown 表面读取应用的字体大小设置，因此只有窗口自身的 chrome、转录文本与 composer 采用窗口缩放；要放大助手正文请调高应用的字体大小。
- **聊天面板没有取消归档，也没有删除会话** —— 归档聊天是单向的，客户端根本没有删除会话的能力，因此聊天行菜单中的删除条目是空操作；删除项目只删除注册，绝不动它的聊天与文件。
- **面板的文件夹浏览器只读取 browse 选择器** —— 挂载平台原生选择器的宿主不提供目录列表，此时该层会说明这一点，并把选择交给原生选择器；这类宿主上没有应用内浏览。
- **聊天面板打开时 dock 与小地图让位** —— 面板是管理界面，否则它们的条带会压住面板外缘与缩放手柄；把面板折叠为导轨后它们就会返回，外框的聊天按钮可再次展开面板。
- **面板打开时整个浮动浮层让位** —— 展开的聊天面板是管理面，dock、Omnibox 与小地图一起停止渲染，因此不会有根级浮层压住面板的外缘、缩放手柄，或 overlay 呈现下窗口的下缘；面板折叠为导轨后浮层返回。
- **缩放手柄随当前窗口升到浮层之上** —— 手柄环只为被聚焦的窗口绘制，因此当窗口边缘落在 dock、Omnibox 或小地图下方时，仍需要先点击该窗口外框任意位置，其手柄才会升到这些层之上。
- **窗口数量超出面板高度后 dock 会滚动** —— 每窗口一行在 900px 面板中大约十来个窗口后便放不下，因此导轨改为滚动，而不是裁掉行以及添加／重置控件。
- **裁剪使用固定的世界边距** —— 窗口超出可见画布 480 世界单位后，其内容停止绘制与命中测试，与其尺寸无关；它的盒子仍在布局中占位，该边距覆盖手柄与展开的聊天面板，隐藏期间窗口保持自身状态。
- **每窗口设置来自 composer** —— agent 预设芯片只在会话仍然空白时可切换（芯片会说明该原因），看板会记住最后一次选择作为新窗口的默认值，模型芯片可切换模型与其推理等级；模型选择还会保存为 `agent-default-model` 系统默认值，芯片提示会说明这一点。预设不会固定模型：模型是会话属性，因此同一个预设的两个窗口可以运行不同模型。已启动的会话保留其工作目录，只有仍然空白的会话才能在重新选择文件夹后重建。
- **外框的 body 分发器是 owner prop** —— 窗口层是 `board.window.body` 的唯一声明者（槽位核心允许每个键只有一个声明者），因此它向每个外框传入 `renderBody` 回调，而不是外框自己的 `renderSlot` 席位。
- **布局通过 `ui-board` settings 命名空间持久化，并带有 MVP 规模的限制** —— 窗口、其几何与顺序、平移/缩放、当前窗口、聊天面板状态以及窗口 → 聊天绑定都存放在用户设置文档的 `ui-board` 段中，因此能挺过页面刷新与进程重启；同一文档的 localStorage 副本用于绘制首帧。写入带防抖（最后一次手势后 600ms，每秒至多一次），因此在该窗口内崩溃会丢失最后一次手势；同时打开两个标签页时，写入失败的一方会重新读取版本，最后由最后写入者生效。全屏仅限会话，视口尺寸只测量、不恢复。文档带 `version: 1`；无法识别的版本，或未通过 schema 的布局，会被忽略并给出警告；MVP 不做迁移——未来版本会从空白看板重新开始。绑定在每次采纳时与布局对账——布局已不再持有的窗口其配对会被丢弃——会话已消失的配对则保留，以便窗口报告情况并在聊天回归时重新附着。关闭窗口同样会移除其配对：看板写入整节而非合并补丁，因为 settings 服务会深度合并补丁，合并永远无法删除该键。
- **编辑器会保存技能，但存活会话保留其已注册集合，直到会话重建** —— 克隆表单写入存储的技能列表，而模型保留会话创建时注册的技能；注册集合何时变化由 [`@ketos/clone-core`](../../ketos/clone-core/README.zh.md) 拥有。
- **完成通知需要窗口观察到这次转换** —— 「访谈完成」由在持有访谈会话期间看到存储状态转为 `ready` 的克隆窗口升起；在没有窗口观察到的情况下发生的完成（窗口已关闭，或之后页面被重新加载）会显示就绪的档案，但不带该通知。
- **访谈报告状态与规模，而非主题进度** —— 条带显示克隆是否处于 `interviewing`、指令以及已作答的交换条数；覆盖了清单中的哪些主题留在对话里，看板不跟踪它们。
- **访谈会话只能通过其克隆窗口的「访谈」页签抵达** —— 在聊天面板中选择该聊天会把克隆窗口带到前台但不切换页签，页签条带是唯一能做到切换的控件；窗口拥有会话之前该页签处于禁用状态。
- **一个聊天只属于一个窗口，消失的聊天不会被替代** —— 另一个窗口已显示的聊天绝不会被绑定两次：选择它会把持有窗口带到前台。宿主不再列出的聊天会让其窗口停留在「缺失」状态，提供「新建会话」与「选择聊天」；MVP 从不自动创建替代会话，客户端也不提供删除会话，因此这两个动作是车道仅有的恢复途径。
- **工具与设置窗口只有外框没有内容** —— dock 的 `+` 目录与 Omnibox 的「新建窗口」一节会打开 agent、连接器与设置窗口，其主体仍为空；仪表板窗口在 MVP 中没有创建入口。真实的每窗口字段随拥有它们的阶段到来，而 Harness 本身并没有客户端 system prompt 编辑器。
- **dock 状态是窗口会话通道的粗略四态投影** —— 创建中、执行中、空闲或错误，不提供逐工具的进度；创建、提示词或回合失败都显示为错误。
- **dock 的重命名与关闭位于行的右键菜单中** —— 没有可见的逐行关闭按钮，右键点击行才会打开该菜单。
- **检查器芯片是普通草稿文本** —— composer 没有编辑器芯片，因此捕获的芯片以文本形式随行，携带 DOM 描述与 `:nth-of-type` 选择器，而不是截图。
- **工作目录与项目管理收拢在窗口聊天面板中** —— 会话创建后工作目录不可更改（核心引擎约束）；新聊天继承项目的文件夹或使用默认工作目录。composer 不再包含文件夹芯片；项目创建、文件夹注册、路径展示与快捷动作（「复制路径」、「在文件管理器中打开」）全部由窗口聊天面板承载。
- **任务窗口只在打开期间轮询，任务产物来自客户端自己持有的记录** —— 只要列表中仍有待启动或执行中的任务，任务列表每 750ms 重新读取一次，因此在没有任务窗口打开时结束的任务会在下次打开时显示最终状态；报告的产物列表折叠的是此浏览器持有的会话记录，因此窗口从未打开过的任务会话不会报告任何产物。
- **会话产物纯粹派生自已落定的工具结果** —— 看板不扫描文件系统，也不实现完整的文件管理器。产物列表动态汇总会话回合中成功的文件访问与修改工具调用（`write`、`edit`、`str_replace_editor`、`read`），按路径去重并遵循修改优先规则（编辑优先于读取）。每条产物提供路径复制以及通过 `session.openWorkspacePath` 在系统文件管理器中定位。
- **用户主目录与 Ketos 运行时状态隔离** —— 在 `~/.ketos` 或 `$DSH_HOME` 之内注册或设置工作目录在宿主和客户端均会被拦截并返回本地化校验错误；选择根目录（`/`、`C:\`）或整个用户主目录时需要用户二次确认。
- **Omnibox 的网页搜索与仪表板窗口以本地化的「此 MVP 不可用」提示作答** —— 这些表面属于宿主或后续阶段。
- **上下文圆环保留状态与读数，不提供组成面板** —— 它与主面板的 `ContextMeter` 对同一会话使用相同的占用值与公式，提示以紧凑单位显示 `% · used / window`，但看板窗口没有可点开的组成面板。所选模型窗口占用超过 80% 时圆弧进入警告色，超过 95% 时进入严重色；提供方尚未报告用量时显示空态破折号。
- **MVP 以十个同时流式输出的窗口为验证范围，建议最多保持 20 个活动聊天** —— 每个打开的 agent 窗口都会保持其会话订阅，并在回合运行时持续绘制流式文本（克隆窗口只在访谈运行时持有会话，其「档案」页签不持有会话）；实测看板在 10 个窗口、5 路并发流下保持 60 FPS（`docs/ketos/perf-baseline.md`）。超过 20 个活动聊天后，共享传输与逐窗口的会话订阅成为成本中心，因此请关闭当前不用的窗口——关闭窗口不会删除其会话与列表行。
- **记忆编辑以最后写入者为准** —— 记忆行没有修订号，因此用户在记忆主体中的编辑与 agent 的 `clone_memory_remember` 写入以最后落地者为准；主体在每次变更后都会重新读取列表。
