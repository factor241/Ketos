## 1. Итог этапа

На доске появился первый настоящий вид элемента — заметка. Из меню «+» дока группа «На доску» создаёт заметку в центре видимой безопасной области при любом пане и масштабе, сразу выделяет и открывает её для правки; заметка рисуется простым текстом выбранным шрифтом (обычный, с засечками, моноширинный), размером (S/M/L) и масштабом (50–300%), её собственная прокручиваемая область удерживает колесо, а `Ctrl/Cmd+колесо` зумит доску. Владелец правит текст без потерь: черновик живёт в компоненте, поток и снимки его не перетирают, запись идёт одной операцией `patch { data: { text } }` через 400 мс после последнего ввода, при выходе и на `pagehide`/скрытой вкладке — немедленно, с `keepalive`; чужая заметка доступна только для чтения и без кнопки настроек. Всё сохраняется в `board.db` и переживает перезагрузку страницы и перезапуск Кетоса. Ветка `stage-29-notes`, worktree `/Volumes/Projects/Ketos bot.worktrees/stage-29`. Следующие этапы получают данные `NoteData`/`noteTextMax`, соглашение `create:<вид>` группы «На доску», `editingBoardElementId` и образец тела вида с кнопкой в `board.element.toolbar`.

## 4. Отклонения

- **`BoardLimits.noteTextMax` — обязательное поле, поэтому изменились проводные потребители.** Декодер `isBoardSnapshot` (`ui-board/board-doc-api.ts`), двойник `createBoardBench`, спецификации `store-elements`/`element-frame`/`board-doc-api` и лимиты `routes`/`events`/`service`/`ops` получили `noteTextMax`. Общие тесты операций (`ops.spec.ts`) остаются видонезависимыми: их `createOp` теперь создаёт `todo` (у `stroke`/`todo` пока общая проверка), а правила `note` живут в `note.spec.ts`; `data.spec.ts` проверяет каждый вид его данными.
- **Правило байтового бюджета для заметки осталось перед разбором полей.** `validateElementData('note')` сначала применяет общий лимит `elementBytesMax`, затем `parseNoteData`; поведение прежних тестов байтового бюджета сохранено.
- **Живой браузер вскрыл дефект двойного щелчка, который jsdom не воспроизводит.** `ElementFrame` захватывает указатель на `pointerdown` (`setPointerCapture`), и браузер перенаправляет производные `click`/`dblclick` на рамку, а не на тело заметки; в jsdom захват — заглушка, поэтому модульные тесты этого не видели. Двойной щелчок перенесён на рамку (`onEdit` у `ElementFrame`, передаётся слоем только для `note`), обработчик с тела заметки убран; интеграционный тест и живой прогон подтверждают вход в правку. Enter на выделенной заметке работал и работает.
- **Создание и патч элементов — новые глаголы внедрения.** У этапа 28 не было операций создания/патча: добавлены `createElement` и `patchElement` в `BoardElementInjected`, `patchBoardElement`/`setEditingBoardElement` в стор; док и тело заметки получают один и тот же набор глаголов. Отказ любой из операций по-прежнему показывает `element.saveFailed`/`element.deleteFailed` и перечитывает снимок.
- **`keepalive` ограничен браузерным телом 64 КиБ.** README `ui-board` (обе стороны) уточняет: при дефолтном `noteTextMax` (20 000 единиц UTF-16) обычный текст укладывается в предел; если развёртывание поднимет `noteTextMax` сильно выше, `keepalive`-сброс на `pagehide` может не пройти, и текст донесут только дебаунс-запись и запись при выходе. Это осознанная граница платформы, а не дефект этапа.
- **`test:web`**: 166 наборов зелёных, 1 красный — известные средовые `plugin-install-github.e2e.ts` (2 теста), зафиксированные в отчётах этапов 27–28; 645 тестов зелёных, 16 skipped.
- **`pnpm run duplication` красный на базе линии** — те же 4 старых клона (`WindowFrame.tsx`, `tool-card-labels.ts` ×2, `pack-ru.ts`), новых файлов этапа среди них нет (задача `ketos-7bs`).
- **Upgrade guide не нужен**: вид `note` — новый; формат `board.db` и версии схемы не менялись; `pnpm --silent run verify-persistence-changes --json` → `"changes": []`.
- **`~/.ketos` не трогали**: все живые серверы, GIF и проверки — на свежих `DSH_HOME` во временных папках (`/tmp/ketos-stage29-home…`, порты 3199/3207/3215/3223/3231); после проверок сервер остановлен.
- **GIF — реальный сервер ветки без модельного раунда.** Снят с полного `pnpm run build` рабочего дерева (принятая ветка `stage-28-board-elements` плюс незакоммиченные изменения этапа — по правилу плана), на свежем `DSH_HOME` без ключа провайдера; онбординг-окна закрыты штатными кнопками `Continue`/`Configure later`; заметке модельный раунд не нужен.
