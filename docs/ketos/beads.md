# Ketos: рабочее отслеживание задач в Beads (bd)

Beads (`bd`, gastownhall/beads) — распределённый граф-трекер задач для агентов на Dolt; в этом репозитории он используется как **инструмент разработки** (отслеживание этапов и задач), а не как продуктовая подсистема `@ketos/beads` из Ф2 мастер-плана.

## Расположение и режим

- БД: `.beads/` в основном рабочем дереве (`/Volumes/Projects/Ketos bot`), backend — embedded Dolt.
- Каталог исключён из git локально (`.git/info/exclude`: `.beads/`, `**/RECOVERY*.md`, `**/SESSION*.md`) — upstream-синхронизация не затрагивается; при желании режим переключается на tracked (см. доки bd).
- Все git-worktree этапов автоматически используют **одну и ту же БД** из main-репо (проверено: `bd` из `/Volumes/Projects/Ketos bot.worktrees/stage-NN` видит общие задачи); конкурентный доступ защищён блокировками Dolt.
- Роль репозитория: `maintainer` (`git config beads.role maintainer`). Без этого bd определяет HTTPS-fork как «contributor» и уводит записи в `~/.beads-planning`, а локальная БД становится read-only.
- Префикс issues: `ketos-<hash>`. Dolt remote: `origin` → `github.com/factor241/Ketos.git` (для `bd dolt push/pull`).

## Модель: план → beads

- Зависимости: эпик этапа N+1 заблокирован эпиком этапа N; первая задача этапа N+1 — за последней задачей этапа N; подэтапы внутри этапа — последовательная цепочка («порядок подэтапов обязателен»). ## Рабочий цикл агента (в worktree этапа)

1. `bd prime` — контекст и правила (SSOT); `bd ready` — доступная работа (первый незакрытый подэтап).
2. `bd update <id> --claim` — атомарный захват подэтапа.
3. Работа по описанию подэтапа; всё, что не входит в подэтап, оформляется новым issue (`bd create`) с зависимостью `discovered-from:<id>`.
4. `bd close <id> --reason "…"` после подтверждения критериев подэтапа; следующий подэтап становится ready автоматически.
5. Хэндофф без git-самодеятельности: отчитаться о статусах, изменённых файлах и предложенных командах (commit/push/`bd dolt push` — только по явному указанию).

## Переход к следующему этапу

1. Перед слиянием: `bd backup sync` (внешний бэкап-каталог обновляется только явной командой) и проверка зависших захватов — `bd list --status=in_progress`; при необходимости снять: `bd update <id> --status open`.
2. Все задачи подэтапов этапа закрыты; критерии приёмки этапа подтверждены (Definition of Done §II.4).
3. Ветка этапа влита в `main` (`git merge --no-ff stage-NN-<slug>`), worktree удалён.
4. Эпик этапа закрыт: `bd close <epic-id> --reason "Принят и влит в main"`.
5. Эпик следующего этапа сам становится ready (снят блокирующий dep) — работа начинается с его первого подэтапа; новый worktree создаётся по решению 47.

## Команды

```sh
bd prime                                  # контекст (запускать в начале сессии/после компакции)
bd ready                                  # что можно делать сейчас
bd list --status=open                     # открытые задачи
bd show <id>                              # детали + зависимости
bd update <id> --claim                    # захват
bd close <id> --reason "…"                # завершение
bd create "…" -t task -p 2 --json         # новая задача
bd dep add <issue> <depends-on>           # зависимость (issue зависит от depends-on)
bd epic status                            # прогресс эпиков
bd graph --all                            # граф зависимостей
```

## Обслуживание

- Бэкап: `bd backup sync` (назначение — `file:///Volumes/Projects/Ketos bot.beads-backup`, настроено), статус — `bd backup status`; офф-машинный вариант — `bd dolt push` (в `origin`, только по явной команде).
- Автобэкап bd (throttled, раз в 15 мин при записях) пишет во внутренний `.beads/backup`; внешний каталог обновляется **только** явным `bd backup sync` — вызывать на границах этапов (см. «Переход к следующему этапу»).
- Рост истории: `dolt.auto-commit=on` создаёт коммит на каждую запись; на границах этапов полезно `bd compact --days 30 --force`. `bd prune`/`gc` не запускать без необходимости — они удаляют историю закрытых issues.
- Диагностика: `bd status`, `bd config show`, `bd memories`; `bd doctor` в embedded-режиме не поддерживается; `bd hooks list` показывает «installed» для pre-commit/pre-push ошибочно (это проверка существования файлов, а git использует `core.hooksPath`).
- Телеметрия bd включена по умолчанию; отключается `bd metrics off`.
- Git-хуки bd **не устанавливаются**: репозиторий использует `core.hooksPath = .git/dsh-hooks` (lefthook, ставится `postinstall`), поэтому bd-хуки из `.git/hooks` игнорировались бы и создавали конфликт; идентификационные трейлеры коммитов не критичны для MVP.
- Интеграции агентов: opencode — секция в `AGENTS.md`; Claude Code — глобальный SessionStart-хук `bd prime --hook-json` в `~/.claude/settings.json` (покрывает main и worktrees; вне beads-репо возвращает пустой контекст; проектный `.claude/settings.json` не используется, чтобы не дублировать инъекцию); Codex — скилл `.agents/skills/beads/SKILL.md` + нативные хуки `.codex/`; `bd setup codex --check` может показывать ⚠ по секции в AGENTS.md — блок сознательно консолидирован в один, это косметика.
