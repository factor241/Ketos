## 1. Итог этапа

Окна переживают перезагрузку страницы и перезапуск процесса: карта `windowId → sessionId` пишется в закладку `bindings` секции `ui-board` на дискретных событиях (создание, перепривязка, закрытие), восстанавливается при каждом принятии раскладки (кэш первого кадра и серверный документ), а `sessions.list` стал источником согласования — окно само привязывается к перечисленной сессии, честно показывает состояния «восстановление» и «сессия пропала» с действиями «создать» и «выбрать чат» и возвращается к жизни, если сессия появилась снова. Введено правило «одна сессия — одно окно»: `bind` возвращает различимый результат (`bound`/`same`/`duplicate`/`unknown`), выбор чата из панели или OmniBox поднимает уже показывающее его окно, OmniBox получил список недавних чатов с заголовком и каталогом, а проектная пустая сессия переиспользуется только пока её не показывает другое окно. Закрытие окна освобождает подписки и не удаляет сессию; поздние результаты create/fork не воскрешают закрытое окно и не перетирают выбор пользователя. Решение этапа — Agent Note [2026-09-19-ketos-board-session-restore.md](../../../.agents/notes/implemented/architecture/2026-09-19-ketos-board-session-restore.md).

## 4. Отклонения

- **Два дефекта найдены живой перепроверкой и исправлены в этапе.** (1) Первая версия guard'ов после `await` сравнивала `record.sessionId !== undefined`, из-за чего восстановление пропавшей сессии через «Новая сессия» молча теряло созданный чат (два осиротевших файла сессий в scratch-доме). Guard'ы `create`/`createChat`/`createChatTarget` теперь сравнивают `sessionId` с его значением до `await`; добавлен регрессионный тест «replaces a missing session when the window starts a new chat». (2) Карта `bindings` только росла: клиент писал её через `remote.settings.update`, а сервис settings глубоко мержит патч (`mergeLayers`), поэтому `bindings: {}` не удалял ключи закрытых окон — живой цикл из десяти окон оставил в `settings.yaml` одиннадцать пар при пустом `windows`. Запись секции переведена на `remote.settings.replace` (доска владеет всем неймспейсом и формирует полную секцию), добавлены регрессионные тесты на удаление ключа при `replace` (host) и на отсутствие удалённой пары в записываемой секции (client). Живой прогон после правки: закрытие одного из двух окон оставляет ровно пару выжившего, пять циклов — пустую карту.
- **Скриптовый аудит `audit.mjs` не писался.** §4.10 требует пополнять скриптовый аудит для этапов, меняющих геометрию, шкалу или слои; этап 9 таких изменений не вносит. Вместо скрипта — живой MCP-прогон с машинными проверками (`audit.json`/`audit-verdict.json`) и QA-кадрами; при переносе проверок в следующий геометрический этап сценарий переносится копией.
- **GIF не записан.** PR ещё не создавался, а видимое изменение этапа — состояния восстановления/пропажи; кадры и вердикты сохранены в каталоге этапа. При публикации PR GIF снимается по skill `record-browser-gif`.
- **Покрытие `ui-board` — исключение MVP-форка.** `pnpm run test:coverage` (CI-гейт per-file 100 %) в этапе не запускался; `packages/client/ui-board/src/**` исключён политикой MVP-форка в `vitest.config.ts` («MVP-fork coverage policy»), как на этапах 3–8.
- **Новых пакетов нет.** Манифесты, ростер и генераторы не менялись (кроме перегенерированного `slot-catalog.ts` — в нём поехали только номера строк `slots.ts`); `pnpm run doc-sync`, `pnpm run build`, `pnpm run hygiene` прогнаны.
- **Живой прогон не проверил стриминг после восстановления.** В scratch-доме нет провайдера моделей, поэтому «продолжают стримить» подтверждено архитектурно (открытая сессия сохраняет свой `SessionEventStream`; `open()` идемпотентен), а не наблюдением токенов.
- **Вне этапа (не закрыто):** `ketos-c1g` (промоушен пары глифов fullscreen), `ketos-bmz` (доменный граф соседних пакетов) — существующие открытые задачи, этап их не касается.
