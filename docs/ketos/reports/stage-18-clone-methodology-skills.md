# Этап 18. Методология и навыки клона

Отчёт по §II.4 общего плана: выполненные подэтапы, подтверждённые критерии, отклонения и следующий шаг. Источник — `stage-18-clone-methodology-skills.md` (ревизия 17).

## 1. Итог этапа

Методология клона стала структурой, а навыки — подключаемыми единицами: канонические четыре раздела (`Принципы`, `Порядок работы`, `Критерии качества`, `Чего не делать`) проверяются парсером в окне клона, интервью заполняет их по инструкции, а навыки хранятся объектами `{ name, description, instructions }`, управляются из окна клона и регистрируются рантаймом в собственном слое skill-регистра агента, откуда модель видит их в каталоге и вызывает инструментом `skill`. Ветка — `stage-18-clone-methodology-skills`, worktree — `/Volumes/Projects/Ketos bot.worktrees/stage-18`, база — принятая `stage-17-clone-memory`. Схема БД поднята до `user_version = 4` шагом v4, который переписывает легаси-массив имён навыков в объекты. Финальный коммит — в конце этапа.

## 3b. Независимая перепроверка (аудит)

Этап перепроверен двумя независимыми аудитами (хост-пакет и клиентский слой) с попытками опровержения; каждая находка воспроизведена до исправления. Найдены и закрыты:

| Находка | Что было не так | Исправление |
|---|---|---|
| Merge превышал лимит навыков | `saveDraft` проверял только входящий список: 100 сохранённых + 100 новых = 200 навыков в записи и в каталоге | После merge — отказ `ketos/invalid-draft` при превышении `skillCount`; тесты на 100+1 (отказ, запись не меняется) и 99+1 (ровно 100) |
| Описание инструмента противоречило поведению | `clone_draft_save` сообщал, что заменяет навыки, тогда как репозиторий делает merge | Текст инструмента: «…replaces … and merges the skills into the clone's list by name» |
| Граница длины имени не проверялась на проводе | Тест «слишком длинное имя» падал по грамматике, а не по лимиту 64 | Тесты: имя ровно 64 принимается, 65 — 400; проверено подменой константы |
| Строка навыков в профиле расходилась с регистрацией | Живой scope обновляет текст профиля, но не регистрации: профиль обещал навык, который `skill` не мог загрузить | Строка навыков убрана из `profileSectionText`; единственный модельный список — каталог `tool-skill`; тесты на отсутствие имён в профиле |
| Регистрация не проверяла длину имени | Легаси-имя 65+ символов регистрировалось, хотя запись/редактор его отвергают | `registerableSkill` учитывает лимит 64; тест в `composition.spec.ts` |
| Меню строки навыка было привязано к индексу | При принятии новой ревизии, пока меню открыто, Delete/Edit попадали в другую строку | Меню адресуется именем навыка, действие разрешается по живому списку; тест «новая ревизия заменила список» |
| Хранимо-невалидный навык без предупреждения | Имя 65+ символов и дубликаты после нормализации не подсвечивались, сохранение всё равно отклонялось 400 | Строка предупреждения учитывает длину и сравнение по trim; тесты |
| Дубликаты правились целиком | Правка одной из двух одинаковых строк заменяла обе | Правка заменяет только адресованную запись; тест «renames one of two duplicates» |
| Фантомная метка агента после своей же правки | Хранимое имя с пробелами не совпадало с обрезанным на проводе, и сохранение пользователя выглядело как правка агента | `toDraft` нормализует имена навыков; тест «padded name save marks nothing» |
| Stale-чтение версии в раннере миграций | `PRAGMA user_version` читался до `BEGIN IMMEDIATE`, повторный opener мог прогнать шаги на устаревшей версии | Версия читается под write-lock |
| `application_id` при неудачной миграции | Штамп ставился до транзакции: чужой файл с конфликтующей таблицей оставался помеченным как наш | Штамп ставится после COMMIT миграций; тест «leaves a foreign file unlabelled» |

## 3c. Повторная перепроверка (финальный diff)

После исправлений этап перепроверен заново теми же двумя независимыми агентами на замороженном дереве; повторные находки классифицированы и либо закрыты, либо отложены с записью:

- Закрыты в этапе: лимит длины в `registerableSkill`, штамп `application_id`, устаревшее чтение версии, индексное меню как источник правок, отсутствие предупреждения для 65+ имён, правка дубликатов целиком, фантомная метка, а также клан `updatedLabel`/`relativeAge`, из-за которого `pnpm run duplication` был красным.
- Отложено осознанно: `PRAGMA busy_timeout` для одновременного первого открытия `clones.db` — пре-существующее, вне диффа этапа, заведено задачей Beads `ketos-fc3`; отсутствие focus-trap у общего `Modal` в `ui-board` (пре-существующее свойство примитива, влияет на все его потребители); смешанный легаси-массив `skills_json` миграция не чинит — такую строку ловит decode-guard (правило «рукописные данные падают громко»); зеркальные `CLONE_LIMITS` клиента не пиннятся тестом к `CLONE_TEXT_LIMITS` хоста (прецедент этапа 15).

## 4. Отклонения

- **Формат `skills_json` изменён на объекты** — шаг v4 forward-only раннера; легаси-имена сохраняются как объекты с пустыми описанием и инструкциями, порядок сохраняется. Обновление схемы не добавляет таблиц, поэтому `clone_tasks` этапа 19 станет следующим шагом (README поправлен: «a later step»).
- **«Пустой навык» — черновое состояние, а не ошибка**: пустые `description`/`instructions` разрешены на запись; навык без описания не регистрируется и помечается в редакторе предупреждением. Это симметрично мягкой валидации методологии.
- **`clone_draft_save` теперь merge, а не replace** навыков — иначе сохранение интервью стирало бы навык, добавленный человеком параллельно.
- **Строка «Skills you may rely on» удалена из `clone:profile`** — дублировала каталог и расходилась с живым scope; единственный модельный список навыков — каталог `tool-skill`.
- **Обновление навыков на лету не делается** — изменение записи доходит до живой сессии только пересозданием scope/агента; ограничение зафиксировано в README, Agent Note и §3a.
- **Покрытие**: `packages/ketos/clone-*/src/**` и `packages/client/ui-board/src/**` остаются в исключениях MVP-политики (`vitest.config.ts`); вместо процентов — поведенческие сьюты, перечисленные выше. Комментарий политики не менялся.
- **Новых пакетов нет**; новых задач Beads, кроме отложенной `ketos-fc3`, не создавалось.
- **Редактор и его секции — тела общего каркаса.** Методология и навыки добавлены в существующую форму окна клона; список навыков использует порядок и меню строки панели «Чаты», модалка — общий примитив `Modal`; новых компонентов-оболочек, `WindowKind` и окон не вводилось.
