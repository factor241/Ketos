# Agent Note: Clone methodology is four canonical sections, and clone skills are record objects registered into the agent's own skill-registry layer

Status: implemented

[English](2026-09-22-ketos-stage-18-clone-methodology-skills.md) | 中文

## 问题

阶段 17 之后，克隆携带了角色设定、一段自由形式的方法论和一个记忆，但它写下的任何内容都既不结构化也不可调用：方法论是一整块文本，没有任何信号指出某一节缺失；记录的 `skills` 是一串光秃秃的名称，既没有描述也没有指令；harness 中也没有任何部分消费它，模型从不知道克隆有哪些技能，也无法调用其中任何一个。本阶段必须让方法论结构化、让技能成为经撰写且可调用的单元，并让两者都能由人在克隆窗口中管理，同时不为每个克隆生成 preset、不使用技能文件、不引入第二个数据库，也不让普通聊天看到另一个克隆的技能。harness 已经有这个机制：skill 注册表（`ctx.skills`）按 scope 分层，而 agent 本身就是自己的 scope 键，因此一次写入 `agent.ctx` 的运行时注册恰好只对该 agent 可见。

## 决策

**方法论词汇住在 `packages/ketos/clone-core/src/methodology.ts`，并且是浏览器安全的。** `METHODOLOGY_SECTIONS` 命名四个规范二级标题：`Принципы`、`Порядок работы`、`Критерии качества`、`Чего не делать`；`METHODOLOGY_TEMPLATE` 是同样四个标题配空正文；`methodologySections(text)` 报告每个标题是否存在、是否为空，`methodologyGaps(text)` 收集缺失或为空的那些。解析器只读取二级标题，因此三级标题或形似的标题不算一节。该模块不导入任何东西、不持有状态，因此编辑器在运行时导入它，客户端 bundle 把它内联（包导出 `./methodology`，`tsconfig.base.json` 映射该说明符）；宿主持有词汇，浏览器那一半读取它。

**访谈写出结构，编辑器柔和地显示缺口。** 访谈者指令列出四个 `## <heading>` 章节，并要求每节给出具体内容；对每个技能要求一个 kebab-case 名称、一段简短描述与指令。编辑器解析实时草稿，把每节标为 `filled`、`empty` 或 `missing`，显示一条缺口提示，并在字段为空时提供模板插入。校验按设计保持柔和：缺口是警告，绝不是拒绝保存的理由，因为进行中的档案本就预期带有空洞。档案段落按原样注入存储的方法论 markdown。

**一个克隆技能是 `{ name, description, instructions }`，以对象形式存储在 `skills_json` 中。** schema 步骤 v4 把遗留的名称数组改写为带空描述与空指令的对象，保持顺序，且不触碰对象数组。持久化解码守卫只强制对象形态，不强制名称语法，也不强制唯一性，因此在该语法被强制之前写入的数据库依然可读；路由与 `clone_draft_save` 是强制该语法（`^[a-z0-9]+(?:-[a-z0-9]+)*$`，至多 64 字符，在克隆内唯一）、各字段边界（描述至多 500 字符，指令至多 20000 字符，至多 100 个技能）的写入边界，并以 `ketos/invalid` 与 `ketos/invalid-draft` 拒绝违规。空描述与空指令是合法的草稿状态：编辑器会标记没有描述的技能，而不是阻塞表单。

**`clone_draft_save` 按名称合并技能，而不是替换它们。** 访谈未提及的存储技能保留原位，同名的技能在原位替换，新名称按草稿顺序追加。人可以在访谈进行期间添加技能，而不会在下一次草稿保存时被丢掉；工具描述说明了这种合并，因此不会让模型误以为遗漏即删除。

**注册是 agent 内部的又一个 scope，绝不是 preset，也不是文件。** 对绑定到克隆的 agent，clone-core 通过一个单独的 `agent.ctx.inject(['skills'], …)` 注册每个可注册的技能（其名称匹配注册表语法、不超出写入路径强制的长度上限，且描述非空），并使用 `source: 'runtime'` 与注册表的默认调用策略（`modelInvocable` 与 `userInvocable`）。单独注入是刻意的：没有 skill 注册表的部署会让 skills fiber 保持待定，而档案段落、记忆工具与访谈模式照旧安装。注册属于该 agent 的 scope，并随它一同消亡；一次注册失败是一条记录在日志中的警告，而不是未处理的 rejection。模型通过 `tool-skill` 在每一步发布的目录认识这些技能，每个技能一条带描述的条目，并用 `skill` 工具加载其中一个；`clone:profile` 段落刻意不列出任何技能名，因为存活 scope 的已注册集合无法改变，而档案中的一行会宣传该存活 agent 无法加载的技能。

**编辑克隆只有在重建时才到达存活 agent 的技能，本阶段接受并记录这一点。** 对账会为不同的克隆或不同的访谈模式重新安装 scope，否则就地刷新档案与记忆文本，因此人对方法论的编辑会在下一次组装时到达运行中的会话，而技能编辑要等 scope 被重新安装或 agent 被重建。把会话钉到某个克隆修订号不在 MVP 范围内；记录的 `revision` 与 `updatedAt` 会呈现在编辑器中，让人能看见一次保存已经落地。

**编辑器仍然是克隆窗口的一个主体。** 方法论字段新增了实时结构条带、缺口提示，以及仅在字段为空时可用的模板动作；新的技能区列出草稿的技能，并带有技能不完整的警告，通过模态窗添加与编辑（校验语法、唯一性、数量与长度），通过聊天面板已在使用的行菜单删除，并标出宿主将拒绝或不会注册的存储名称。没有引入新的窗口种类、包装层组件或文档。

## 考虑过的替代方案

- **为每个克隆生成一个 agent preset。** 否决：preset 名册属于部署配置，而且计划的阶段背景已经确立，注册进 agent 自身的 scope 完全不需要生成 preset。
- **每个克隆目录下的技能文件（`customSkillDirs`）。** 否决：克隆的技能是记录数据，而记录旁边的文件会需要自己的生命周期、在重命名与删除时清理，以及编辑器的第二个真源。
- **把 `skills` 保持为名称并添加一个查找工具。** 否决：仅凭名称无法把模型路由到技能（目录需要描述），也无法给出指令（技能正文需要指令），因此记录仍会缺少那些经撰写的字段。
- **在持久化解码中强制 kebab 语法。** 否决：本阶段之前的数据库可能持有任意名称，而在解码时抛错会让整份克隆列表不可读；改为由编辑器标出名称、注册跳过它。
- **在写入时要求描述非空。** 否决：人可能先给技能起名、之后才写描述，而为一份不完整的草稿阻塞表单，比可见的警告与跳过的注册更糟。
- **在每次克隆数据变动时重新注册技能。** 否决：本阶段已经固定了这个被接受的简化，即存活 scope 保留其已注册集合；档案与记忆文本仍会刷新，而重建会应用新列表。
- **在档案段落中列出技能名称。** 否决：它会重复目录，并在存活 scope 保留旧注册集合的那一刻变得陈旧，让模型得知一个 `skill` 工具会拒绝加载的技能。
- **为每个方法论章节各用一个 textarea（共四个），而不是一个 markdown 字段。** 否决：记录是 markdown，未知章节必须能往返留存，而一个编辑表面加一条解析出的结构条带，让存储格式与审阅辅助保持分离。

## 后果

克隆的方法论现在有了访谈者填写、编辑器审计的规范形态，而克隆的技能是经撰写的单元，模型在克隆自己的会话中从目录里看到它们并用 `skill` 工具调用；人在克隆窗口中添加、编辑与删除它们，记录的修订号与更新时间显示一次保存做了什么。接受的代价：存活会话保留它在安装时注册的技能，直到被重建；会话不会被钉在它启动时所用的记录修订号上；没有描述或名称遗留的技能会留在模型目录之外，直到编辑器修正它；方法论的四个章节是一种约定，编辑器对它发出警告，而不是存储强制执行的校验。schema 版本 4 只进不退；本构建写入的数据库会被更早的构建拒绝，遗留的名称数组会以对象形态的草稿保留下来。
