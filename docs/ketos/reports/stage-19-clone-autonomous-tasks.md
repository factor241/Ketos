# Этап 19. Автономные задачи клона

Отчёт по §II.4 общего плана: выполненные подэтапы, подтверждённые критерии, отклонения и следующий шаг. Источник — `stage-19-clone-autonomous-tasks.md` (ревизия 17).

## 1. Итог этапа

Клон выполняет задачу автономно: человек формулирует цель на карточке клона или в окне задач, хост создаёт сессию, привязывает её к клону, создаёт штатный goal и передаёт тому бюджет раундов, а смонтированный `goal-round-driver` сам добавляет ход за ходом, пока агент простаивает. Клон завершает задачу инструментом `clone_task_report`, статус и отчёт видны в окне задач, отмена работает и durable-записана в лог цели. Хранилище — `clones.db`, шаг схемы v5 (`clone_tasks`), маршрут `/api/ketos.tasks`; никакого своего цикла ходов, второго процесса и второго рантайма не появилось. Ветка — `stage-19-clone-autonomous-tasks`, worktree — `/Volumes/Projects/Ketos bot.worktrees/stage-19`, база — принятая `stage-18-clone-methodology-skills`. Финальный коммит — в конце этапа.

### Находка живой проверки и исправление

Первый прогон показал: после вызова `clone_task_report` в середине хода модель получала `Error: unknown tool "clone_task_report"` при повторном вызове — координатор снимал scope задачи сразу при терминальном статусе, и инструмент исчезал под ещё идущим ходом. Исправлено: `settle` откладывает реконсиляцию scope до `turn/end`, если агент в этот момент `running` (вне хода — снимает сразу); повторный вызов теперь получает доменный отказ (`ketos/invalid-state`), а инструмент исчезает после завершения хода. Добавлены тесты `task-runner.spec.ts`: «keeps the report tool through the turn that completes the task», «withdraws the tool immediately when the task settles outside a turn». Повторный чистый прогон: 1 вызов инструмента, один завершённый ход, 0 ошибок консоли.

## 4. Отклонения

- **Шаг миграции — `stepV5`, версия 5.** План называл «шаг v3 (`CURRENT_SCHEMA_VERSION = 3`)», но схема `clones.db` уже была на `user_version = 4` после этапа 18; задача добавлена следующим шагом того же forward-only раннера, как и фиксировал этап 18.
- **`goals` читается через `ctx.get('goals')`, а не через корневой `inject`.** Клоны, память и интервью не зависят от goal-сервиса, и добавление его в корневой инъекционный список заставило бы безголовые композиции держать весь пакет в PENDING; отсутствие сервиса даёт громкую ошибку только при попытке запустить задачу. Прецедент — постмортем о `ctx.get` для опциональных сервисов.
- **Терминальный статус откладывает снятие scope до конца хода** (см. §3a) — иначе инструмент исчезает под выполняющимся вызовом.
- **Отмена — только `block`.** План перечислял `block` и `pause + session.cancel()`; выбран `block` как durable-запись, `disarm` и `clear` отклонены по причинам, названным в плане (нет записи в лог / tombstone).
- **Автопродолжение после рестарта не реализовано** — план относит его к post-MVP; вместо этого при первом открытии таблицы незавершённые задачи переводятся в `failed` с пометкой «the process restarted before the task finished» (риск этапа, митигация из плана).
- **Прогресс-подсказка читается из цели, а не из счётчика в `clone_tasks`** — второй счётчик разошёлся бы после рестарта; `roundsStarted` уже есть в проекции цели.
- **Поллинг окна задач (750 мс) вместо форварда `goal/changed` в браузер** — план фиксирует поллинг и SLA ≤ 1 с, форвард host-событий — post-MVP; новых подписок в браузере нет.
- **Покрытие**: `packages/ketos/clone-*/src/**` и `packages/client/ui-board/src/**` остаются в исключениях MVP-политики (`vitest.config.ts`); вместо процентов — перечисленные поведенческие сьюты. Комментарий политики не менялся.
- **Новых пакетов нет**; новых задач Beads этап не создавал.
