# Этап 16. Бутстрап-интервью клона

Отчёт фиксирует завершение этапа по §II.4: выполненные подэтапы, подтверждённые критерии, отклонения и следующий шаг.

## 1. Итог этапа

Клон создаётся полуавтоматически: в окне клона запускается интервью, агент-интервьюер задаёт по одному вопросу, а в финале вызывает инструмент `clone_draft_save`, который сохраняет структурированный профиль (роль, описание, персонаж, методология, навыки) в `clones.db` и переводит клона в статус `ready`; пользователь видит черновик в форме, правит и подтверждает. Ветка этапа — `stage-16-clone-interview`, worktree — `/Volumes/Projects/Ketos bot.worktrees/stage-16`, базовый коммит — `8263238` (принятый этап 15).

## 3b. Независимая перепроверка (аудит)

Этап перепроверен двумя независимыми аудитами (хост-пакет и клиентский слой); каждый нашёл подтверждённые дефекты, все закрыты в том же этапе. Исправленное:

| Находка | Что было не так | Исправление |
|---|---|---|
| Утечка памяти координатора | `chains`/`opened` хранили запись на каждый созданный агент (включая обычные чаты) до конца процесса — рост памяти на сессию, нарушение бюджета «память процесса при 20 сессиях» | Цепочка удаляется по `agent/disposed`, идентификатор открытой сессии — тоже; `opened` наполняется слушателем `session/event` |
| Двойной kickoff / потерянный kickoff | Процессная защёлка `opened` не снималась, поэтому отменённый turn оставлял сессию без вступления; при этом пара `agent/created`+`agent/session-start` запускала две сверки и могла поставить два вступления | Триггеры собираются в микрозадачный батч (одна сверка на публикацию), а решение опирается на ожидающий inbox и журнал сессии — отменённый kickoff ставится снова, записанный не дублируется |
| Запись профиля не проверяла режим | `saveDraft` писал поверх клона с любым статусом, если scope ещё не снят: подтверждённый пользователем профиль мог быть перезаписан агентом | В хранилище: роль привязки `interview` обязательна (`ketos/not-a-clone-session`), статус `interviewing` обязателен (`ketos/clone-not-interviewing`) |
| Неограниченные аргументы инструмента | Схема инструмента не выражает `maxLength`/`maxItems`, поэтому многострочный «метод» или тысячи навыков писались в БД и уезжали в UI | Границы полей проверяются в `saveDraft` (`ketos/invalid-draft`) |
| Ленивое открытие БД нарушено | Сверка режима открывала `clones.db` на каждом `agent/created`, включая обычные чаты | БД открывается только когда клоны релевантны: по мутации маршрута или при восстановлении сессии (`source: 'resume'`) |
| Ссылка на неактивный scope | `await scope` не гарантирует активацию фибера: при отсутствии `tools`/`systemPrompt` scope считался установленным, а kickoff уходил в сессию без инструмента | Сервисы объявлены в `inject` плагина |
| Уведомление маршрута могло превратить запись в 500 | Колбэк вызывался внутри `try`, отображающего неизвестные сбои в `500` | Уведомление вызывается с узким `try/catch` и логом: запись уже зафиксирована, ответ не зависит от подписчика |
| Заказ интервью: сессия утекала, статус зависал | Сессия создавалась до записи статуса; при отказе статуса оставалась пустая непривязанная сессия, при отказе привязки клон навсегда оставался `interviewing` | Порядок: статус (шаг, который отказывает) → сессия → привязка; при отказе привязки статус возвращается под записанную ревизию |
| Восстановление закрытого окна | `bridge.adopt` после сетевых раунд-трипов возрождал запись закрытого окна и привязывал к нему сессию | Перед `adopt` проверяется, что окно ещё открыто |
| Статус от собственного жеста помечался как «изменено агентом» | Запуск интервью сам двигал `status`, и эффект следования записи помечал поле, а при грязном черновике поднимал баннер «применить версию агента» | Успешный старт перебазирует `base`/`revision` для записанного им статуса |
| Текст, набранный во время сохранения, терялся | Продолжение сохранения записывало снимок как весь черновик | `base` берётся из принятого ответа, живой черновик сохраняется |
| Форма не перечитывала ростер при открытии окна | Профиль, сохранённый агентом в закрытом окне, показывался устаревшим до следующей ошибки сохранения | `openClone` вызывает `refreshClones()` |
| Записи черновиков не ограничены | `cloneEdits` рос на каждый отредактированный клон | Запись удаляется при закрытии окна клона |
| Тест правила имени не различал | В тесте у окна не было сессии, поэтому старая и новая лестница имён давали один результат | Тест запускает интервью и держит сессию с заголовком; добавлены тесты отказа старта и «свой жест не помечается» |
| Редактор перерисовывался на каждый чанк | `useWindowSession` без селектора в теле клона | Читается только `sessionId` |

## 4. Отклонения

- **Статусы клона сузились до трёх.** Пара `active`/`archived`, введённая на этапе 15 как спекулятивная (её никто не читал), заменена на `draft | interviewing | ready`; шаг схемы v2 переводит существующие записи (`active` → `ready`, `archived` → `draft`), не удаляя ни одной строки и не трогая остальные поля. Решение зафиксировано в Agent Note этапа.
- **Окно клона получило второе тело `conversation`.** Отмена решения этапа 15 «окно клона — никогда не чат»: интервью-сессия живёт в окне клона (требование плана 16.3), переключение — вкладками «Профиль»/«Интервью» в каркасе окна. Прежнее исключение остаётся верным для вкладки «Профиль» и покрыто тестом `tests/open-window.client.spec.ts`.
- **Маршрут клонов получил уведомление о записи.** `registerCloneRoutes` принимает необязательный колбэк, который вызывается после принятой мутации: браузер создаёт сессию раньше привязки, поэтому ни одно событие жизненного цикла агента не видит привязку, и режим интервью включается только по этому уведомлению.
- **Инструмент сохраняет профиль без пользовательского CAS-подтверждения.** Запись агента — это и есть черновик, поэтому она применяется к текущей ревизии (last writer wins); от затирания пользовательский текст защищает форма (грязный черновик сохраняется, сохранённая ревизия показывается отдельной строкой и применяется только по кнопке). Ограничение зафиксировано в README пакета и Known Limitations доски.
- **Прогресс интервью — статус и число обменов, без чек-листа тем.** Осознанный MVP-выбор из плана 16.3: не выдумывать прогресс; отложено в Known Limitations.
- **Комментарий MVP-политики покрытия в `vitest.config.ts` приведён в актуальный вид** (в нём утверждалось, что пакетов `@ketos/clone-*` ещё нет). Сами исключения не менялись.
- Новых задач Beads не создавалось; открытых вопросов, требующих решения пользователя, нет.
