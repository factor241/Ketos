## 1. Итог этапа

Окно чата доведено до продуктового вида во всех состояниях: каркас остался один (`WindowFrame` + `features`), лента честно показывает пусто/создание/ошибку создания/ошибку хода/выполнение/заблокировано/загрузку ранних ходов и строки инструментов (включая бегущие вызовы) отдельным компонентом, заголовок окна следует за названием чата при перепривязке и переименовании и перелокализуется при смене языка, композер исполняет команды с аргументами, соблюдает спроецированные лимиты вложений, принимает файлы (диалог, drag&drop, вставка) и показывает блокировку с причиной. Найден и закрыт живой дефект 6.5: экранное кольцо ручек ресайза перекрывало контролы заголовка при зуме 0.2. Решение этапа — Agent Note [2026-09-18-ketos-chat-window-states-titles](../../../.agents/notes/implemented/feature/2026-09-18-ketos-chat-window-states-titles.md).

## 4. Отклонения

- **Кольцо ручек вынесено за границу окна (находка 6.5).** Первый живой прогон аудита забраковал клик по имени окна при зуме 0.2: экранно-пространственные полосы кольца (6 px) толще масштабированного заголовка (≈7 px) и перекрывали контролы. Вместо скрытия кольца на малых зумах (`HandleRing.tsx`) его восемь прямоугольников сдвинуты полностью наружу от бокса окна: полосы по-прежнему лежат над плавающим хромом и служат целью ресайза, но не съедают контролы. Тест `tests/slots.client.spec.tsx` обновлён на новую геометрию.
- **`session.command(line)` заменён на `remote.commands.execute` для строк композера.** `session.command` возвращает только `{ matched }` и терял бы исход выполнения; `execute` отдаёт `CommandResult`, из которого композер показывает «Command failed: <текст хозяина>». Существующие вызовы бриджа (`selectPermission`, `exitPlanMode`) остались на `runCommand` — у них нет пользовательской поверхности ошибки.
- **Файл как `Blob` в бридже.** Живой прогон показал, что путь `Uint8Array` в `ctx.fileUpload.upload` уходит в Remote-фолбэк `remote.fileUploads`, который падает без `inject` на классе рантайма (`cannot get property "remote.fileUploads" without inject`). Бридж оборачивает байты в `Blob` — тот же носитель, что и у главного композера (фоновый воркер), и живая проверка `55-file-upload-ready` зелёная. Дефект самого пакета `client/file-upload` не трогался (вне этапа).
- **Тул-окна без собственных контролов (6.1).** Решение: `features` остаётся швом (`panel`, `fullscreen`), но `connectors`/`settings`/`dashboard`/`tasks` не получают «обновить»/«настройки», пока их поведение не появится: контрол без действия — декоративный хром. Тест фиксирует отсутствие чат-контролов у тул-окон.
- **`pickWorkspace` удалён.** Колбэк не имел потребителя (чип рабочей директории удалён на этапе 4); решение зафиксировано в Agent Note, устаревший JSDoc `ComposerBar` про чип каталога исправлен, мёртвые ключи `rail.agentBadge`/`agent.composerPlaceholder` удалены из zh/en/ru.
- **Политика отправки осталась собственной.** Решение и обоснование — README (ограничение) и Agent Note: `busyEnter` — настройка чужого плагина, покрывающая один жест из двух.
- **Вне этапа (не закрыто):** `ketos-md8` (шаблоны тул-окон, этап 7.2), `ketos-c1g` (промоушен пары глифов fullscreen), `ketos-bmz` (доменный граф соседних пакетов) — существующие открытые задачи, этап их не касается.
