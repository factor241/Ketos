# Agent Note: Board window states, naming, and composer intake

Status: implemented

English | [中文](2026-09-18-ketos-chat-window-states-titles.zh.md)

## Problem

Stage 4 gave every board window a real Harness session and the full composer, but left the states around it unfinished. The lane rendered settled text and one-line tool names only: a running call was invisible, a result whose call fell outside the loaded window showed a raw id, and turn failures, refused prompts, and blocked composers arrived as raw server text or not at all. The lane followed the tail unconditionally, so prepending earlier turns moved the reader. Window titles froze the locale the window opened in and never followed the chat the window was rebound to; the rename affordance did not exist. The composer offered images without limits, non-image files not at all, no drag-and-drop or paste intake, and a command line with arguments went out as an ordinary prompt, so `goal`, `plan`, `feedback`, and `permission` never ran. Finally, the active window's resize ring straddled the frame border with 6–14 screen-pixel strips: at a zoomed-out canvas the header is shorter than the strip, so the ring covered the header controls and they became unclickable.

## Decision

**One channel carries every window fact that renders.** `BoardSessionBridge` keeps republishing one identity-stable channel per window; it now carries the chat title (`SessionSummary.displayTitle`), the history flags (`hasMore`, `loadingOlder`), the running calls (`ChatSnapshot.legacy.runningCalls`), the image limits (the `imageLimits` projection), and the turn and prompt failures kept apart from the creation failure (`lastAgentError`, `promptError`). The frame and the body read it through the keyed `useWindowSession(windowId)` hook; no component subscribes to an observable itself.

**The window names itself from a three-step ladder.** `window-title.ts` resolves the user's own window name (`customTitle`), then the chat title with its session, then the localized template label for the window kind. The state stores the window's ordinal, not a rendered string, so the fallback re-resolves at render time and follows a locale switch instead of keeping the locale the window opened in (`ketos-1lx`). The header name is a button that edits `customTitle` in place; a double click on a dock row edits the same value. Clearing the field drops the override and the chat title returns. The chats-panel rebind path needed no change: the title arrives with the channel.

**The lane renders each state through its own localized line, and one component owns a tool row.** `window/ToolRow.tsx` takes name, failure flag, running flag, unavailable flag, and a repeat callback; the lane decides which rows exist. Running calls render from `legacy.runningCalls` with a marker; a settled result whose `call` is `null` (the call fell outside the loaded event window) renders as unavailable with a repeat control that asks for the earlier turns again. Empty, creating, creation failure, turn failure, refused prompt, and running each have a dictionary line and a stable `data-board-lane-state`; blocked renders in the composer (`data-board-blocked`), which is where the block acts. Earlier-turn loading captures the lane's scroll height and its leading row before requesting, and re-anchors only once that leading row changes: a streamed chunk or a running call landing below the reader cannot consume the anchor, and the repeat control appears only while an older page remains. The tail follow runs only while the reader is within 24px of the bottom, and the jump-to-latest control is an absolute overlay that cannot change the lane's height (no flicker).

**The composer enforces the host's limits and stages files through the host's upload seam.** Image intake mirrors the main composer: the projected `imageLimits` decide count, per-image size, and total size, and a batch that would break one limit is refused whole with the localized reason. Non-image files stage through `ctx.fileUpload`; the bridge wraps the bytes in a `Blob` so the upload takes the background carrier instead of the remote fallback, and the prompt or command carries the staged receipt. Pick, drop, and paste share one intake path. A line that leads with a command from the session's catalog executes through `remote.commands.execute` with its arguments and the draft's attachments; a command that does not accept attachments is refused by the host, whose text the composer shows after a localized label. The palette adds the board-owned `/file` (picker) and `/model` (model menu) entries to the host registry it lists. Escape dismisses the palette for the current draft without closing the chats panel or clearing the draft, including when the key arrives on a focused palette row: that handler stops its own propagation, because the board's Escape ladder would otherwise close the panel behind the open palette. The drop hint and the file picker obey the same blocked/ready gate as sending, so a blocked composer never promises an intake it will discard.

**The submission policy is decided here, not inherited.** Plain Enter queues (or sends when idle), Cmd/Ctrl+Enter steers. The `ui-conversation` `busyEnter` preference lives in that plugin's settings namespace, is registered by that plugin, and maps only the bare-Enter gesture; reading it would couple the board to a sibling feature plugin's settings for one gesture and still leave the board owning the accelerated pair. The board keeps its documented policy and the README says so.

**The resize ring sits outside the frame.** `HandleRing.tsx` now places its 6px strips and 14px corners just outside the window box instead of straddling the border. The ring is screen-space, so its thickness cannot scale with the canvas; an inward strip covers the header once the window is zoomed out far enough. Outside, the strip still provides the same above-chrome grab target and never eats a control. The frame's own handles keep their half-in geometry.

**The composer keeps no unused workspace callback.** `pickWorkspace` re-created a blank session in a picked directory but had no caller after the working-directory chip left the composer in stage 4; the panel registers projects through `createWorkspace` instead, and the dead callback plus its bridge method are removed. Removing it is a cleanup, not a decision reversal: a window adopts a directory by joining a project or creating its chat in one.

**Tool windows keep the shared frame and invent no controls.** `WindowFrameFeatures` stays the seam (`panel`, `fullscreen`), but `connectors`, `settings`, `dashboard`, and `tasks` render no extra control until a stage owns its behavior; a refresh or settings glyph with nothing behind it would be chrome theater. `AgentCard` remains the only feature-carrying wrapper, so there is still exactly one frame implementation.

## Alternatives considered

- **Read the `ui-conversation` busy-enter setting.** Rejected: the setting is one gesture of a policy the board does not otherwise share, and reaching into another feature plugin's settings namespace at runtime is the cross-plugin coupling the export discipline forbids; the decision and its reason are recorded in the README limitation.
- **Editor chips for `@` mentions.** Rejected for this stage: chips are the conversation package's editor (a CodeMirror-based input the board does not mount); the board inserts plain text and never breaks the draft's line breaks, and the limitation says so.
- **Put command execution on `session.command(line)`.** Rejected: it drops the execution result, so the composer could not show a refusal or an unknown command; `remote.commands.execute` returns the outcome the failure line needs.
- **Show a retry that re-runs the tool.** Rejected: Harness has no client-side tool retry; the honest repeat is requesting the earlier turns again, which is what can actually restore the missing call metadata.
- **Keep the ring half-in and hide it at low zoom.** Rejected: hiding loses resize reachability exactly where the window is smallest; moving the strips outside keeps both the controls and the handles.
- **Add a data attribute and leave the ring geometry.** Rejected: the finding was a real interaction defect at zoom 0.2 (`56-rename-clickable-at-min-zoom` in the audit), not an automation problem.
- **Mount the ui-conversation composer into the window.** Rejected: the board composer is its own component with its own draft state and container-query layout; sharing the editor would need a slot the conversation package does not define.

## Consequences

Every lane and composer state is observable and localized, the header and dock follow the chat after any rebind or rename, and the composer can carry files and run commands with arguments. The board now injects `fileUpload`, so a profile that composes the board must compose the upload service; the web bundle already does. Receipts are host-memory per session and the chips keep only the name and retry, so a failed upload cannot be resumed after a host restart, and a receipt cannot be re-sent once its window closes. `@` mentions stay plain text. Tool windows still open only from tests until the stage that owns them adds templates. What it gives up: the ring's outward strips take panel space just beyond the frame (a window flush against the board edge loses the outermost pixels of its handles), and the window is renamed through the name itself or a dock double click rather than a dedicated affordance.
