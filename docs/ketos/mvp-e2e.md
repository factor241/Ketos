# Ketos: E2E-сценарий MVP

Документ фиксирует один непрерывный сценарий приёмки MVP: **доска** (часть A) и **клон** (часть B). Он исполняется на живом стенде (`pnpm ketos web`): продуктовый домашний каталог — `~/.ketos`, а приёмочный стенд поднимается скриптом `.playwright-mcp/stage-20-mvp-acceptance/stand.sh` на чистом `DSH_HOME` (`/tmp/ketos-stage20/home`); шаги, ожидаемые результаты и машинные проверки совпадают с аудитом `.playwright-mcp/stage-20-mvp-acceptance/audit.mjs` (фазы `one`, `two`, `native`). Примеры проекта для части B — в `examples/ketos-mvp/`.

Стенд приёмки: `DSH_HOME` — чистый каталог (`/tmp/ketos-stage20/home`), `DEEPSEEK_BASE_URL` указывает на локальный SSE-стаб `.playwright-mcp/stage-20-mvp-acceptance/sse-stub.mjs` (сценарий не расходует внешний API), `SSH_CONNECTION` выставлен намеренно — адаптивный пикер каталога резолвит `browse` при SSH-запуске, и мини-браузер папок доступен сценарию (на локальном macOS тот же профиль монтирует нативный выбор, который скрипт вести не может; фолбэк проверяется фазой `native`).

## Часть A — доска

| # | Действие | Ожидаемый результат |
|---|---|---|
| A1 | Иконка «Доска» в списке панелей боковой колонки | Панель доски активна; док, миникарта и омнибокс на месте; кнопка дока «Add agent» создаёт окно агента 552×648 |
| A2 | Хедер окна (закрытие, «Чаты», заголовок, полный экран), лента, композер | Восемь ручек ресайза; чипы пресета, разрешений и модели, кольцо контекста, диктовка, `+`-меню (`Файл`, `Голосовой ввод`, `Цель`, `План`, `Отзыв`, `Сжать`, `Разрешения`, `Экспорт`), `/`-палитра (8 команд); промпт уходит через хост и лента отвечает |
| A3 | Панель «Чаты»: развернуть из рейла, зарегистрировать папку через мини-браузер (крошки, «Новая папка», «Использовать эту папку»), создать в проекте чат, отправить промпт, переименовать, создать ветку, архивировать, переключить группировку/порядок, найти поиском | Проект `ketos-mvp` появляется строкой сразу после регистрации (в том числе пустым); чат создаётся в проекте, его строка переименовывается, ветка даёт вторую строку, архив убирает строку; меню «Группировка и порядок» переключает все четыре режима; поиск по названию оставляет совпавшие строки и очищает список на несовпадающем запросе; `@`-палитра показывает `contracts`, `договоры-2026` и текущий чат |
| A4 | Уменьшить окно ребром, вырастить углом | Ребро упирается в стартовый размер 552×648; угловая ручка растёт пропорционально (552×648 → 720×864, отношение сохранено); отправка доступна на всех размерах |
| A5 | Кнопка полного экрана, затем Escape | Окно растягивается на панель (1320px), хром и соседи уходят; Escape закрывает панель, второй Escape выходит из режима и возвращает прежний прямоугольник 720×864 |
| A6 | Перезагрузка страницы | Окно, его прямоугольник, pan/zoom и привязанный чат восстановлены из settings-неймспейса `ui-board` |

## Часть B — клон

| # | Действие | Ожидаемый результат |
|---|---|---|
| B7 | Омнибокс `+` → «Новый клон»; имя «Юрист-аналитик», роль «Юрист»; сохранить карточку | Окно клона открывается на карточке, запись сохраняется (ревизия растёт) |
| B8 | «Начать интервью»; 10 ответов человека | Интервью идёт в том же окне обычным чатом (обменов: 10); агент вызывает `clone_draft_save` и переводит клон в `ready`; профиль показывает персону, методологию из четырёх канонических секций и навык `contract-risk-review` |
| B9 | Вкладка «Память»: запись, оставленная интервью, редактируется | Список содержит запись со статусом `Активная`; правка содержимого сохраняется и перечитывается списком |
| B10 | «Автопилот» с целью «Проанализируй файл договора в папке проекта и составь список рисков» | Задача создаётся и стартует без человека; окно задач открывается на этом клоне; статус уходит из `pending` сам |
| B11 | Дождаться `done`; раскрыть «Отчёт»; «Открыть сессию» | Отчёт — текст, который клон вернул инструментом `clone_task_report` (четыре риска и рекомендация); в сессии задачи видна карточка вызова `read`; раздел «Артефакты» перечисляет прочитанный файл договора |
| B12 | Уточняющий вопрос в сессии задачи («Напомни, что для тебя главное в отчёте по договору?») | Ответ приходит в той же сессии; в запросе к модели на этом ходу нет инструмента `clone_task_report` (задача завершена), но есть секция профиля, методология клона и снимок памяти |
| B13 | Перезагрузка страницы, затем перезапуск процесса | Окно клона, окно задач, память и терминальный статус `done` восстановлены; чаты окон на месте |

## Машинные проверки

Аудит `.playwright-mcp/stage-20-mvp-acceptance/audit.mjs` исполняет те же шаги против живого хоста:

```sh
.playwright-mcp/stage-20-mvp-acceptance/stand.sh start /tmp/ketos-stage20/home 3200
AUDIT_PHASE=one    node .playwright-mcp/stage-20-mvp-acceptance/audit.mjs "<url>"   # части A и B, перезагрузка страницы
.playwright-mcp/stage-20-mvp-acceptance/stand.sh restart /tmp/ketos-stage20/home 3200
AUDIT_PHASE=two    node .playwright-mcp/stage-20-mvp-acceptance/audit.mjs "<url>"   # восстановление после перезапуска процесса
AUDIT_PHASE=native node .playwright-mcp/stage-20-mvp-acceptance/audit.mjs "<url>"   # фолбэк нативного пикера (хост без SSH-маркера)
```

Вердикты — `audit/audit-verdict-<phase>.json`, кадры — `audit/shots/`, доказательства «что видел модель» — `requests-summary.jsonl` стаба (по строке на запрос: роли, каталог инструментов, наличие секций профиля, методологии и памяти); файл перезаписывается приёмочным прогоном. Аудит проверяет, что запрос продолжения несёт профиль, методологию и память, а инструмента `clone_task_report` в нём нет (проверки `B12 the follow-up carries profile, methodology and memory` и `B12 the report tool is withdrawn after the task` в `audit/audit-one.json`). Номера проверок в отчёте этапа 20 ссылаются на имена этих проверок.
