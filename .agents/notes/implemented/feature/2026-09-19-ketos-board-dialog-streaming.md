# Agent Note: Board window dialog parity — optimistic echo, streaming, queue, and failures

Status: implemented

English | [中文](2026-09-19-ketos-board-dialog-streaming.zh.md)

## Problem

Stage 9 gave every board window a durable chat, but the window's dialog still behaved like an early prototype. A submitted prompt showed nothing until its durable `user/message` event arrived, so a slow host looked like a lost message; the composer cleared its draft unconditionally, so a refused prompt threw the text and its attachments away; the queue strip rendered previews only, with no editor, no attachments, and no steering, while the lane ignored steering corrections entirely; and a turn failure was one raw line taken from the session's latest agent error, which could sit beside the transcript's own durable turn-error row and report the same failure twice. The window's inject face also had no way to cancel an admission round trip or to learn whether a prompt was accepted, so the composer could not restore what the host refused. Finally, the history anchor worked in unit tests but lost the reader live: the browser's native scroll anchoring applied the prepend adjustment a second time on top of the lane's own compensation.

## Decision

**A window submission is the main panel's submission, through the same object-layer path.** The bridge registers a local echo with `session.beginSubmission({ mode, text, attachments })` before it calls `prompt(content, mode, signal, requestId)`; the echo carries the draft's image previews and the durable references of its staged files. The inject face's `sendPrompt` returns whether the host accepted the prompt and accepts an `AbortSignal` for the complete admission round trip, so the composer aborts in-flight admissions when it unmounts. A refused prompt retires its echo by the same identity, and a carrier rejection abandons it explicitly — the window never leaves a phantom message behind.

**The composer clears optimistically and restores on refusal exactly once.** The draft leaves the composer at the submit gesture, because the local echo is already the acknowledgement; waiting for the host before clearing would stall the queue flow (three messages queued behind a running turn) behind a network round trip. When the prompt is refused, the text and every chip return: an untouched composer gets the draft back verbatim, and a composer the user has typed into keeps its newer text and gains the refused draft as a new paragraph, so a refusal never loses or overwrites what was written. An accepted send owns its staged bytes, so their retry sources are dropped only then.

**The echo renders where its durable counterpart will.** The bridge republishes the session snapshot's `pendingSubmissions` as `pending`, excluding any identity an admitted queue occurrence already advertises (`rpcId`), and the lane renders transcript and steering echoes as user bubbles until their durable node arrives; the lane additionally hides an echo whose `rpcId` is already in the loaded transcript, which closes the one-animation-frame overlap the controller tolerates. Queued echoes render in the queue strip with a localized sending status and no actions.

**The queue is split by surface, and every mutation is the wire action.** The strip lists queued occurrences and queued echoes (count header, per-row edit/remove/steer, attachments as file chips and session-cached image thumbnails); steering occurrences and pending steering echoes render in the lane as user bubbles, replaced by the durable steering node when it arrives. Steering is offered only while a turn runs, mirroring the host's rule. An edit is text-shaped on the board's face (`{ kind: 'edit', text }`) and translated at the bridge into the wire's non-empty content replacement (`{ kind: 'edit', content: [{ type: 'text', text }] }`); a refused mutation publishes `queueError`, which the strip renders, so a queue change can no longer fail silently on a cast.

**Cancel keeps the queue.** The host owns the rule — a cancelled turn stops and pending queued work remains in FIFO order for the next turn — and the window does nothing to contradict it: `cancelPrompt` only calls the session face, and the queue projection keeps publishing the same rows. The bridge test and the live audit pin that the rows survive the cancel.

**A turn failure is one card.** Durable `turn-error` nodes render as a card that carries the localized title, the localized copy a known code owns (`AUTH`), the sanitized provider message and code behind an expandable detail, and a repeat action that re-sends the failed turn's prompt when that prompt is still in the loaded window. The channel's generic latest-agent-error line renders only when the transcript does not already carry that failure — a durable failure at the transcript tail is its own card, so the two never report one failure twice.

**Streaming keeps committed rows mounted, and history keeps the reader's place.** Lane rows are memoized leaves that take primitive props (kind, text, labels), so a chunk republish re-renders only the streaming partial; rows are deduplicated by event `seq`, so a history page that repeats an event cannot double a row. The prepend compensation is one JS write (`scrollTop += scrollHeight - anchor.height`, moved only by an actual prepend or by a shrink above the reader — the load-earlier affordance leaving once history is exhausted), and the lane disables the browser's native scroll anchoring (`overflow-anchor: none`) because otherwise the browser applied the same adjustment a second time and pushed the reader past the page they were holding. The tail-follow rule is unchanged: the lane follows while the reader stays within 24px of the bottom and leaves the offset alone once they scroll away.

## Alternatives considered

- **Wait for the durable event and block the send control until it arrives.** Rejected: it trades the echo's immediacy for a busy control, and it breaks the queue flow the stage owns (three queued messages behind a running turn). The main panel answers with the same echo, and parity is the stage's goal.
- **Clear the draft only after the host accepts.** Rejected: every queued message would wait a round trip before the next could be typed, and the composer would need a busy state to prevent duplicate submits. The optimistic clear plus exactly-once restore keeps both properties.
- **Restore a refused draft over whatever the composer holds.** Rejected: it silently deletes text the user typed while the prompt was in flight. Appending the refused message keeps both.
- **A separate `editQueueItem` callback beside `updateQueueItem`.** Rejected: one discriminated action union mirrors the wire `QueueAction`, keeps the inject face minimal, and makes the edit's text payload explicit at every call site.
- **Carry steering occurrences in the queue strip.** Rejected: steering is already part of the turn being executed, not of the wait queue, and its transcript node is where the conversation reads it; the strip stays the queue for turns that have not started.
- **Cast the board's edit action to the wire shape (`action as never`) and keep the failure silent.** Rejected by the live audit: the wire rejects `{ kind: 'edit', text }`, and a silent failure is worse than no editor. The translation now lives at the bridge and the refusal is visible.
- **Keep native scroll anchoring and drop the JS compensation.** Rejected: the browser anchors whatever element it picks; only the lane knows the leading row the reader was holding, and the live audit showed the two adjustments doubling.
- **Render a turn-error card for every historical failure and keep the generic line unconditional.** Rejected: the same failure appears as both a durable row and an agent error event, so the card owns the transcript tail and the line remains the fallback for failures with no durable row.

## Consequences

The window now reads and behaves like the main panel for the dialog's whole cycle: instant echo, streamed prose, a synchronous queue strip with edit/remove/steer, a cancel that keeps queued work, and one localized failure card per failure. The accepted costs: the queue edit replaces the row's text only (other content blocks are dropped by the host's non-empty text-only replacement rule); the queue strip's image thumbnails resolve through the session-scoped conversation cache, so an image whose read fails keeps its placeholder; the repeat action queues a fresh turn rather than retrying in place, because the client exposes no turn-retry API; and the lane still renders prose, steering, tool names, and turn failures only — compaction checkpoints, model retries, and output-token caps keep their existing surfaces and the tool cards belong to stage 12. The board's model chip stays empty because the window session's model-selection projection is not materialized; the host's default model still drives every turn, and that surface belongs to stage 11.
