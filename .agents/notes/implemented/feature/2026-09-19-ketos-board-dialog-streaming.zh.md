# Agent Note: Board window dialog parity — optimistic echo, streaming, queue, and failures

Status: implemented

[English](2026-09-19-ketos-board-dialog-streaming.md) | 中文

## Problem

阶段 9 让每个看板窗口拥有了持久聊天，但窗口的对话行为仍像早期原型。提交的提示在其持久的 `user/message` 事件到达之前什么都不显示，因此慢速宿主看起来像丢消息；composer 无条件清空草稿，被拒绝的提示会连同附件一起丢失；队列条只渲染预览，没有编辑器、没有附件、也没有插队，而信息流完全忽略插队纠正；回合失败则是一行取自会话最新 agent 错误的原始文本，可能与转录自身的持久 turn-error 行并排出现，把同一个失败报告两次。窗口的 inject 面也没有取消准入往返或得知提示是否被接受的手段，因此 composer 无法恢复宿主拒绝的内容。最后，历史锚点在单元测试里有效，实机却丢失读者位置：浏览器原生滚动锚定在车道自身的补偿之上又应用了一次预置调整。

## Decision

**窗口提交就是主面板的提交，走同一条对象层路径。** bridge 在调用 `prompt(content, mode, signal, requestId)` 之前先用 `session.beginSubmission({ mode, text, attachments })` 注册本地回声；回声携带草稿的图片预览与已暂存文件的持久引用。inject 面的 `sendPrompt` 返回宿主是否接受该提示，并接受一个用于整个准入往返的 `AbortSignal`，因此 composer 卸载时会中止在途准入。被拒绝的提示按同一身份退休其回声，载体拒绝则显式 abandon——窗口永远不会留下幻影消息。

**composer 乐观清空，并在拒绝时恰好恢复一次。** 草稿在提交手势上离开 composer，因为本地回声本身就是确认；等宿主接受后再清空会把队列流（运行中的回合后排队三条消息）卡在一次网络往返之后。提示被拒绝时，文本与每个附件芯片都会回来：未被触碰的 composer 原样取回草稿，用户已经输入的 composer 保留新文本并把被拒草稿作为新段落追加，因此拒绝绝不丢失也绝不覆盖已写内容。被接受的发送才拥有其暂存字节，只有那时才丢弃重试源。

**回声渲染在持久对应物将出现的位置。** bridge 把会话快照的 `pendingSubmissions` 重新发布为 `pending`，排除已由已准入队列发生项声明过的身份（`rpcId`）；车道把 transcript 与 steering 回声渲染为用户气泡，直到它们的持久节点到达；车道还会隐藏 `rpcId` 已存在于已加载转录中的回声，以此关闭控制器容忍的那一帧重叠。排队中的回声在队列条中渲染，带本地化的发送状态且没有任何操作。

**队列按表面拆分，每个变更都是 wire 动作。** 队列条列出 queued 发生项与 queued 回声（计数头、每行编辑/移除/插队、附件以文件芯片与会话缓存图片缩略图呈现）；steering 发生项与待定 steering 回声在车道中以用户气泡渲染，并在持久 steering 节点到达时被替换。仅在回合运行时提供插队，与宿主规则一致。编辑在看板自己的面上是文本形状（`{ kind: 'edit', text }`），在 bridge 处翻译为 wire 的非空内容替换（`{ kind: 'edit', content: [{ type: 'text', text }] }`）；被拒绝的变更发布 `queueError`，队列条渲染它，因此队列变更再也不会因一次类型转换而静默失败。

**取消保留队列。** 规则归宿主——被取消的回合停止，待处理的排队工作按 FIFO 留给下一个回合——窗口不做任何与之相悖的事：`cancelPrompt` 只调用会话面，队列投影继续发布同样的行。bridge 测试与实机审计都固定了这些行在取消后存续。

**回合失败是一张卡片。** 持久的 `turn-error` 节点渲染为一张卡片，携带本地化标题、已知错误码（`AUTH`）拥有的本地化文案、位于可展开详情之后的净化提供方消息与错误码，以及在该失败回合的提示仍在已加载窗口时重发它的重试操作。通道的通用 latest-agent-error 行只在转录尚未携带该失败时渲染——位于转录尾部的持久失败就是它自己的卡片，因此两者绝不会把同一个失败报告两次。

**流式保持已提交行挂载，历史保持读者位置。** 车道行是以原始 props（kind、text、labels）为参数的 memo 叶子，因此一次分块重发布只重渲染流式部分；行按事件 `seq` 去重，因此重复某事件的历史页无法重复一行。预置补偿是一次 JS 写入（`scrollTop += scrollHeight - anchor.height`，仅当前导行确实变化时才消费），并且车道禁用浏览器原生滚动锚定（`overflow-anchor: none`），否则浏览器会把同一调整再应用一次，把读者推过他们原本持有的页面。跟随尾部的规则不变：读者停留在距底部 24px 以内时车道跟随，一旦滚开就不再改动偏移。

## Alternatives considered

- **等待持久事件并阻塞发送控件直到它到达。** 拒绝：它以回声的即时性换取一个忙碌控件，并破坏本阶段拥有的队列流（运行中回合后排队三条消息）。主面板用同样的回声作答，而对齐是本阶段的目标。
- **只在宿主接受后清空草稿。** 拒绝：每条排队消息都要等一次往返才能输入下一条，composer 还需要忙碌状态来防止重复提交。乐观清空加恰好一次恢复同时保住了两者。
- **把被拒草稿覆盖回 composer 当前内容。** 拒绝：这会静默删除用户在提示在途期间输入的文字。追加被拒消息则两者都保留。
- **在 `updateQueueItem` 之外另设 `editQueueItem` 回调。** 拒绝：一个可辨识的动作联合与 wire `QueueAction` 对应，让 inject 面最小，并让编辑的文本载荷在每个调用点都显式。
- **把 steering 发生项放进队列条。** 拒绝：steering 已经属于正在执行的回合，而不是等待队列；它的转录节点才是对话读取它的位置，队列条只留给尚未开始的回合。
- **把看板的编辑动作强转成 wire 形状（`action as never`）并保持失败静默。** 被实机审计拒绝：wire 拒绝 `{ kind: 'edit', text }`，而静默失败比没有编辑器更糟。翻译现在位于 bridge，拒绝可见。
- **保留原生滚动锚定并去掉 JS 补偿。** 拒绝：浏览器锚定它自己挑选的元素；只有车道知道读者持有的前导行，而实机审计显示两次调整会叠加。
- **为每个历史失败渲染卡片并保持通用行无条件渲染。** 拒绝：同一个失败既作为持久行又作为 agent 错误事件出现，因此卡片拥有转录尾部，而通用行仍是没有任何持久行的失败的兜底。

## Consequences

窗口现在在对话的整个循环上与主面板一致：即时回声、流式文本、带编辑/移除/插队的同步队列条、保留排队工作的取消，以及每个失败一张本地化卡片。接受的代价：队列编辑只替换该行的文本（其他内容块被宿主的非空纯文本替换规则丢弃）；队列条的图片缩略图通过会话范围的对话缓存解析，读取失败的图片保留占位符；重试操作排队一个新的回合而不是原地重试，因为客户端没有暴露回合重试 API；车道仍只渲染散文、steering、工具名与回合失败——压缩检查点、模型重试与输出令牌上限保留各自既有表面，工具卡片归阶段 12。看板模型芯片仍为空，因为窗口会话的模型选择投影尚未物化；宿主的默认模型仍驱动每个回合，而该表面属于阶段 11。

验证：`tests/composer.client.spec.tsx`（每次提交一个提示且乐观清空、被拒草稿的文本与芯片恢复、已输入文本的保留、卸载中止、队列条的附件/编辑/移除/插队/禁用插队/队列错误），`tests/conversation-body.client.spec.tsx`（回声渲染与按 `rpcId` 退休、回声附件、待定/队列/持久 steering、带详情与重试的 turn-error 卡片、本地化 AUTH 文案、失败行去重、重复 seq 去重、跨分块的已提交行身份、车道与 composer 的运行状态一致、滚开后的流式偏移），`tests/session-bridge.client.spec.ts`（回声注册与请求身份、拒绝与载体放弃、带附件与 rpcId 去重的队列/pending 投影、wire 编辑翻译、queue-error 发布与清除、排队图片解析、取消保留队列），以及实机审计 `.playwright-mcp/stage-10-gif/audit/audit.json`（9 项检查，`ok: true`，针对带 OpenAI 兼容 SSE 桩的实机 `pnpm ketos web`；本阶段发现并修复两个缺陷：编辑的 wire 形状与双重滚动补偿）。
