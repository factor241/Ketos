## 1. Итог этапа

Оболочка доски замкнута: док показывает по каждому окну отображаемый заголовок, вид и статус из канала окна и умеет центрировать, фокусировать, переименовывать и закрывать строки (сессия при закрытии остаётся живой и в списке), OmniBox доводит текст до сессии активного окна через мост окна и создаёт окна всех шаблонов с честными ответами на недоступные виды, миникарта проецирует окна любого вида и уступает панели «Чаты» и fullscreen, а инспектор превращает выбранный элемент в чип черновика активного окна. Общие правила вынесены в одного владельца: `resolveChatWindow` выбирает адресата команды, `menu-placement.ts` размещает любой поповер доски, а лестница Escape «меню → редактор → выбор элемента → панель «Чаты» → fullscreen» покрыта интеграционными тестами и живым аудитом. Это снимает Known Limitation «OmniBox не связан с сессией» и закрывает перенесённую задачу `ketos-md8` (шаблоны тул-окон) вместе с `ketos-0iy` (развёрнутая панель «Чаты» уводит весь плавающий хром, поэтому ни один слой корня её не перекрывает). Решение этапа — Agent Note [2026-09-18-ketos-navigation-shell.md](../../../.agents/notes/implemented/feature/2026-09-18-ketos-navigation-shell.md).

## 4. Отклонения

- **Асимметрия дока `+` (принята).** Левый клик по `+` остаётся прямым добавлением агента, правый открывает каталог agent/connectors/settings; полный каталог, включая недоступные виды, живёт в OmniBox. Так закрыт пункт плана «создание окон из OmniBox и дока»: док — быстрый вход в одно действие, OmniBox — полный список с локализованными ответами; обоснование — комментарий `SessionRail.tsx` и README.
- **Чип инспектора — текст черновика, а не чип редактора.** У композера доски нет редактор-чипов (ограничение этапа 4), поэтому захват приходит локализованной строкой `inspector.chip` в черновик; формат и ограничение зафиксированы в README.
- **Веб-поиск остаётся недоступным с локализованной причиной.** Возможность `web` — хост-половина, и инжектить её в клиентский плагин нельзя; план 7.2 допускал именно явное «недоступно», поэтому пункт меню отвечает заметкой `menu.unavailable.webSearch`, а не молчанием.
- **`ketos-0iy` закрыта согласованием лестницы, а не переносом панели.** План 7.5 называл структурный вынос панели на слой корня; вместо этого развёрнутая панель «Чаты» уводит весь плавающий хром (док, OmniBox, миникарта) со сцены — тот же приём, которым этап 4 уводил док и миникарту, — и ни один слой корня больше не перекрывает кромку панели, её ручку ресайза и низ окна в overlay-представлении. Панель сохраняет рендер в `BoardWindowLayer` (внутри трансформации канваса) и документированное поведение: ширину, высоту, масштабирование и меню. Критерий задачи про `elementFromPoint` подтверждён аудитом `73-panel-bottom-edge-hit`; причина отказа от переноса — Agent Note (альтернативы).
- **Покрытие `ui-board` — исключение MVP-форка.** `pnpm run test:coverage` (CI-гейт per-file 100 %) в этапе не запускался; `packages/client/ui-board/src/**` исключён политикой MVP-форка (`vitest.config.ts`, комментарий «MVP-fork coverage policy»), как на этапах 3 и 5 — см. §5а.
- **Новых пакетов нет.** Манифесты и генераторы не трогались; `pnpm run build` прогнан в составе `pnpm run test:web` (238 клиентских артефактов, 3 публичных значения), `pnpm run hygiene` — в финальном прогоне (см. §5).
- **Вне этапа (не закрыто):** `ketos-c1g` (промоушен пары глифов fullscreen), `ketos-bmz` (доменный граф соседних пакетов) — существующие открытые задачи, этап их не касается.
