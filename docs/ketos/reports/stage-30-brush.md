## 1. Итог этапа

На доске можно рисовать и стирать своими штрихами. В доке появились режимы «Кисть» и «Ластик» и выбор толщины (тонкая/средняя/толстая); в режиме кисти перетаскивание рисует плавную линию цветом владельца точно под курсором при любом масштабе — включая зум колесом посреди штриха, потому что каждая точка переводится по актуальному виду, — и сохраняется одной операцией `create`; ластик вырезает части только своих штрихов одним пакетом `remove` + `create` за проход, с живым предпросмотром; свой штрих выделяется по линии, двигается одним `patch { x, y }` без переписывания точек и удаляется клавишей Delete; штрихи — нижний слой (ранг 0 из этапа 28), одинаковые данные рисуются одинаковым путём на любом Кетосе (опции `getStroke` — функция только от `width` и `pen`), а 50 штрихов по 500–2000 точек не опускают пан и зум ниже 60 кадров/с при бюджете 55. Ветка `stage-30-brush`, worktree `/Volumes/Projects/Ketos bot.worktrees/stage-30`. Следующие этапы получают `StrokeData`/`STROKE_SIZES`/`parseStrokeData`/`strokeBounds`/`simplifyStroke`/`eraseStroke`, `stroke-path.ts`, `tool`/`brushWidth`/`setTool`, ступень инструмента в лестнице Escape и бенч `board-strokes.perf.ts`.

## 4. Отклонения

- **`StrokeDraft` живёт в `canvas/`, а не в `elements/`, как в плане.** `pnpm run verify-client-domain-graph` держит форк-пакеты под строгим правилом: `canvas/` не может импортировать `elements/`. Живой черновик — часть слоя канваса (рисуется между элементами и окнами), поэтому файл перенесён; Agent Note фиксирует причину.
- **`validateElementData` получил четвёртый параметр — рамку элемента, а `BoardLimits.strokePointsMax` — обязательное поле.** Правило `stroke` требует рамку (относительные точки), поэтому обновлены `ops.ts` (`assertValidElement`), декодер `isBoardSnapshot` (`ui-board/board-doc-api.ts`), двойники и фикстуры тестов `ui-board`, лимиты тестов `board-doc` и `data.spec.ts` (штрих больше не проходит общей веткой).
- **Один пакет ластика ограничен `maxOpsPerRequest` (64 по умолчанию).** Очень длинный проход по десяткам штрихов отвергается хостом (`ketos/invalid`) с уведомлением и свежим снимком; на несколько POST проход не разбивается, потому что план требует «один пакет за проход». Это осознанная граница, а не дефект.
- **Общая механика жестов вынесена в `tool-gesture.ts`.** Первая версия кисти и ластика дала два новых клона `jscpd`; общий стартер (захват, coalesced-сэмплы, rAF-кадр, один конец) и хелперы `boardToolWorldPoint`/`strokeSpecFromBounds` убрали их — `pnpm run duplication` снова показывает только 4 базовых клона (`ketos-7bs`), новых нет.
- **`.eraserRing` получил `corner-shape: round`.** Гейт `packages/client/ui-theme/tests/corner-shape-styles.client.spec.ts` требует пару к любому `border-radius: 50%`; без неё `test:gui` был красным.
- **Upgrade guide не нужен.** Формат `board.db` и версия схемы не менялись (`pnpm --silent run verify-persistence-changes --json` → `"changes": []`); ужесточение разбора `stroke` — внутренний провод линии, единственный потребитель (`ui-board`) обновлён в этом же этапе, а общий вид `stroke` существовал лишь внутри линии с этапа 28.
- **`pnpm run duplication` красный на базе** — те же 4 старых клона (`WindowFrame.tsx`, `tool-card-labels.ts` ×2, `pack-ru.ts`), новых этап не добавил (задача `ketos-7bs`).
- **`board-geometry.e2e.ts` Т1.3 обновлён под новые док-кнопки.** Тест фиксирует порядок контролов дока слева направо; три новых (`dock-brush`, `dock-eraser`, `dock-brush-width`) добавлены в ожидание, файл после правки 35/35 зелёный. Это изменение поведения, а не ослабление проверки.
- **`tool-details.e2e.ts` — флейк полной полосы, не регрессия.** В полном прогоне `test:web` тест «expands every recorded tool through its keyed renderer» упал на измерении переполнения карточки; изолированный прогон файла — 2/2 зелёный. Доска к карточкам инструментов не прикасается.
- **`~/.ketos` не трогали**: все живые серверы, curl-проверки и GIF — на свежих `DSH_HOME` во временных папках; после проверок серверы остановлены.
- **GIF — реальный сервер ветки без модельного раунда.** Рисованию, стиранию и удалению модель не нужна; снят на свежем `DSH_HOME` без ключа провайдера, онбординг-диалоги закрыты штатными кнопками. Сырое видео, QA-кадры и скрипт — в `.playwright-mcp/stage-30-brush/` (gitignored); упавший первый прогон отброшен и не смешан с итоговым.
- **Наблюдение по гигиене дерева:** после прогонов сборки в `src/` четырёх пакетов (`llm-api-extensions`, `llm-replay`, `loader-smoke`, `session-snapshot`) появились нетрекнутые сгенерированные `.js`/`.d.ts`; `pnpm run clean` их не удалил, файлы убраны вручную. `pnpm run build` и `pnpm run typecheck` их повторно не создают, поэтому это не заведено задачей Beads, а записано здесь.
