# RaytSystem workspace integration for Ketos

## Goal

Connect the existing RaytSystem installation to the Ketos repository as a
local-first project workspace without replacing or rebuilding the existing
Graphify installation.

## Selected approach

Use the RaytSystem managed software bootstrap as the reversible installation
base, then replace its generic defaults with Ketos-specific configuration.

The RaytSystem engine remains a local tool installed from the nested
`raytsystem/` checkout. Project configuration, policies, catalog definitions,
workflow templates, skills, and the genesis ledger live in the Ketos
repository. Runtime databases, derived graphs, runs, staging, backups, exact
raw blobs, and the nested engine checkout remain local and Git-ignored.

## Graph boundary

Graphify remains the broad, persistent project map. Existing
`graphify-out/` files, configuration, hooks, and workflow are not modified.

RaytSystem uses a separate disposable graph under `.raytsystem/graph/`. It is
limited to the product-owned Ketos surfaces needed for local navigation and
impact analysis:

- `src/backend/base/ketos`
- `src/frontend/src`
- `src/kfx/src/kfx`
- `src/bundles`
- `scripts`
- `docs/localization/ru`
- `docs/superpowers/specs`
- `docs/superpowers/plans`

Selected root contracts and audit reports are added as explicit graph files.
The RaytSystem graph is never committed and is not treated as canonical truth.

## Document workspace

Only `knowledge/manual` is writable from RaytSystem. Product documentation is
indexed read-only:

- `docs/docs`
- `docs/localization/ru`
- `docs/superpowers`

The workspace root cannot be a document root, so the existing root-level audit
reports remain graph context rather than editable Documents entries.

## Skills and agents

Keep the existing Ketos `.agents/skills` unchanged. Add only the RaytSystem
`start` and `graph` adapters generated by bootstrap.

Replace the generic Software Factory catalog skills with Ketos-specific
procedures:

- builder: scoped implementation following Ketos AGENTS rules;
- reviewer: route frontend/backend review to the existing repo skills;
- tester: focused tests first, then the relevant package gate;
- security reviewer: KFX, MCP, path, secret, egress, approval, and recovery
  boundaries.

Catalog agents remain disabled because external runtime execution, Codex local,
Claude local, and external MCP execution are intentionally disabled.

## Runtime and command model

Install RaytSystem as an editable `uv tool` from `raytsystem/`. Project-facing
instructions use the global `raytsystem` command rather than `uv run
raytsystem`, because Ketos and RaytSystem are separate Python projects.

The local UI runs with:

```bash
raytsystem start --root /Volumes/Projects/ketos_canvas_mod_main
```

It binds only to `127.0.0.1`. The existing server rooted at the RaytSystem
source checkout is stopped before the Ketos-rooted server starts.

## Safety defaults

Keep all external execution fail-closed:

- `runtime_execution_enabled = false`
- `codex_local_enabled = false`
- `claude_local_enabled = false`
- `external_mcp_execution_enabled = false`
- `a2a_network_exposure_enabled = false`
- `external_notifications_enabled = false`
- `otel_export_enabled = false`
- `restricted_encryption_enabled = false`

Real-corpus promotion remains manual and hash-bound. This setup indexes project
documents and code but does not promote them into canonical knowledge.

## Git boundary

Track:

- RaytSystem project configuration;
- policies and runtime adapter catalog;
- catalog packs, agents, skills, workflow and task templates;
- managed instruction blocks;
- genesis ledger and generated empty knowledge projections;
- setup documentation.

Ignore:

- `raytsystem/`
- `.raytsystem/`
- `_raw/blobs/`
- `_raw/restricted/`
- operational SQLite files;
- locks, staging, runs, task ledger, backups and encrypted state;
- draft and outbox artifacts.

Do not change `core.hooksPath`. The generated `.githooks/pre-commit` remains an
optional local entry point because enabling it globally could bypass another
developer's Git-hook setup.

## Verification

The configured workspace must satisfy:

- `raytsystem doctor --root . --json` reports `healthy: true`;
- knowledge LINT reports no findings;
- document index reports current and lists the declared roots;
- code graph reports current and contains no `raytsystem/` or
  `graphify-out/` files;
- UI `/api/v1/system` identifies the Ketos workspace;
- UI exposes the customized skills and disabled external runtimes;
- Graphify tracked files and current metadata remain unchanged;
- unrelated pre-existing untracked files remain untouched.
