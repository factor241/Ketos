## 4. Отклонения

- **Модель — скриптовый SSE-стаб.** На хосте нет `DEEPSEEK_API_KEY`, поэтому аудит и GIF сняты против скриптового SSE-стаба на свежем `DSH_HOME`; демонстрируемые поверхности клиентские, реального провайдера запись не показывает.
- **`test:coverage` с ограниченной параллельностью.** На Node 24.21.0 полоса запускается с `--maxWorkers=4 --testTimeout=30000`: с дефолтной параллельностью на этой машине не связанные с Кетосом спеки, поднимающие процессы, получают сервисные таймауты (11 падений в 3 файлах в одном прогоне; все три файла отдельным прогоном зелёные — 47/47).
- **Плавающий `hmr-config.spec.ts`.** Четыре полных полосы на этом дереве (Node 24.21.0) дали 11/1/1/1 падений в не связанных с Кетосом спеках; три из них — сервисные таймауты в спеках, поднимающих процессы (`webworker-packer/image-loadable.spec.ts`, `fs/tool-fs-search/tests/integration.spec.ts`, `shell/bash-sandbox/tests/partial-landlock.spec.ts`), каждый файл отдельным прогоном зелёный (47/47); четвёртая и последующие — `packages/boot/app-boot/tests/hmr-config.spec.ts`, который форк уже правил против этой нестабильности (`ketos-03r`, `6b33159`: событийный `eventually()` с дедлайном 80 с, таймаут кейса 90 с, `usePolling` для кейса refresh-failures и для кейса создания при отсутствующем родителе). Два прогона упали на кейсе «observes creation when the config parent did not exist at registration» (строка 147), один — на «normalizes refresh failures and broadcasts them without escaping the watcher» (строка 218), все после 80 с ожидания; отдельным прогоном файл зелёный 6/6 за 1.45 с. Три контрольных полных прогона на Node 24.21.0 (`--maxWorkers=4 --testTimeout=30000`) дали 1, 2 и 1 падений: hmr-config упал во всех трёх — кейс «observes creation when the config parent did not exist at registration» дважды и «normalizes refresh failures and broadcasts them without escaping the watcher» один раз, каждый после 80 с ожидания `WATCHER_WAIT_TIMEOUT_MS`; второй прогон дополнительно дал `packages/context/file-reference-local/tests/search.spec.ts` (таймаут `vi.waitFor` на возврате корня). Оба файла отдельным прогоном зелёные: 19/19 за 1.5 с. Суммарно на этом дереве hmr-config падал в 6 из 7 полных полос (4 раза кейс создания, 2 раза кейс refresh-failures), в контрольных прогонах — 3 из 3.
- **Исправление hmr-теста — отдельная задача.** Этап допускает только исправления пунктов аудита, поэтому правка самого `hmr-config.spec.ts` вынесена в задачу `ketos-inp` (discovered-from `ketos-5v2.22.7`, связана с `ketos-03r` и коммитом `6b33159`).
