# @deepseek-ai/dsh-client-ui-board

[English](README.md) | 中文

## 概述

board 是 dsh 网页客户端的一个空间化主面板：一块由可移动、可缩放 agent 窗口组成的无限画布，每个窗口拥有一个 Harness 会话与聊天 composer。车道把每次工具调用渲染为一张卡片，显示已用秒数、本地化的失败状态，读不出的调用折叠为 JSON 块；待处理的审批会先显示横幅，再导航到应答 composer。dock 列出窗口并打开窗口目录，小地图镜像窗口布局，每个窗口还带有工作文件夹与文件面板。窗口之下有一层元素图层绘制宿主的看板文档（便签、笔迹、待办清单），带有所有者颜色的边缘、选中、移动与缩放。

## 使用本包

通过侧栏品牌旁的开关键打开该面板；看板的模式标牌位于同一屏幕位置并可返回标准界面，因此切换时控件不会移动（Т2.5/Т2.6）。看板主面板声明自身不保留侧边栏，因此看板被选中时外壳的侧边栏列、其控制栏与宽度手柄一并让位；画布填满主面板并从空开始。拖动背景平移，滚轮或双指滑动平移，`Ctrl/Cmd+滚轮`（触控板捏合）以指针为中心按比例缩放（0.2–2.0）；dock 的加号按钮打开窗口目录（agent 窗口、预设子菜单、连接器、设置、克隆、仪表板的不可用提示、任务与最近的聊天），其旁的「选择元素」按钮为当前聊天窗口启用检查器，其旁的参与者控件打开名册——每名参与者及其颜色与连接状态、「邀请」一次性邀请码、「连接 Ketos」的粘贴框、无通道对等端旁的「忘记」，以及当对等路由回答 404 时的未配置提示。选择器旁的画笔与橡皮擦控件把画布切换到绘制模式：使用画笔时，拖动会在任意缩放下于光标正下方画出一条所选粗细（细、中、粗）的平滑所有者颜色线条，松开时实时线条作为单个笔画元素提交；使用橡皮擦时，拖动会从自己拥有的笔画中切除部分——每次经过提交一个批次，删除原笔画并创建剩余片段——绝不触碰他人的笔画。两种模式都保持 Space、中键与 `Ctrl/Cmd+滚轮` 可用，绘制落在便签与窗口之下，按一次 Escape 即回到选择工具。笔画元素保存相对描点、粗细与是否由触控笔绘制；主体在所有 Ketos 上由这些值渲染出同一条平滑路径，其外框本身不接收指针（因此大图形绝不阻挡平移），只有线条本身接受用于选中、移动或删除的点击。窗口交互遵循同一约定：拖动标题栏移动，拖动边缘手柄缩放单轴，拖动角手柄独立缩放两轴，按住 Shift 拖动角手柄按比例缩放（两轴同一系数，对角固定），按住 Alt 释放 24 px 网格吸附；点击窗口将其提到 z 序最前，关闭按钮移除窗口。按住 Space 拖动或用中键拖动可在看板任意位置平移——浮动浮层上同样有效，中键拖动手柄时平移而非缩放——`Ctrl/Cmd+0`（以及 dock 的「显示所有窗口」控件）在指针或焦点位于看板上时把所有窗口连同其已打开的面板放进安全区域，缩放不超过 1，`Ctrl/Cmd+=`/`−` 以看板中心为基准步进缩放。滚轮落在窗口车道、打开的窗口面板、打开的菜单、便签自身的文本或 dock 上滚动该表面（dock 为横向滚动，垂直滚轮同样有效），落在画布或浮动浮层的其余部分上平移；在看板任意位置（窗口与面板也包括在内）按住 `Ctrl/Cmd` 滚轮则缩放。当前窗口的八个缩放手柄也会画在浮动浮层之上，因此滑到 dock 或小地图下方的窗口边缘依然可以抓取。手柄环落在窗口外框之外，因此画布缩小时标题栏控件即使被缩放到比条带还薄，也依然可以点击。离开可见画布的窗口停止绘制——其车道、草稿、附件与面板保持存活——视图返回时原样恢复。每次按 Escape 只执行一个动作，顺序为菜单、聚焦的编辑器、元素选择、工具、已打开的窗口面板；画笔或橡皮擦激活时按一次会回到选择工具。窗口绝不会小于最小可用布局（聊天窗口为 408×480）——标题栏、composer 与车道都无法在更小的空间内排布——而宽度、高度或对角方向的放大不受限制。低于 `detailZoomThreshold`（默认 0.4）时，窗口把详细外观换成简化卡片，只显示名称与会话状态——车道、composer 与标题栏保持挂载但被隐藏——点击卡片会把缩放回升到阈值并把窗口居中；外框手柄、屏幕空间的缩放手柄环以及窗口自身打开的菜单都随详细视图一并让位，而当屏幕步长小于 8 px 时，点阵网格把步长加倍并让点逐渐变淡。新窗口在看板安全区域内居中打开——即视口减去浮动浮层实测的边距——窗口居中也会落在安全区域中心；当窗口连同其已打开的面板大于空闲矩形时缩小缩放，因此两者都不会落到 dock、模式标牌或小地图之下。窗口整体比应用放大一档：标题、车道文本、芯片、控件与 composer 都读取声明在看板根节点上的一组度量（`--board-font-*` 以及控件、内边距与间距值），因此外框与其内容一同变大，而 dock、小地图与 portal 菜单保持应用的尺寸。窗口自身的标题栏承载两个面板控件——左侧打开「工作文件夹」面板，右侧打开文件面板——每个面板都从其边缘滑出：这是窗口管理项目与聊天、以及其文件页签的控制面。两个面板都属于各自的窗口：各自独立开合，并在布局中保存各自的宽度（左 260–360，右 280–600），与窗口同处一个层叠层级，因此外框画在其内缘之上；两者使用相同的滑出动画，`prefers-reduced-motion` 时取消动画。打开会落到可见看板之外的面板时，画布在不改变缩放的情况下平移让位；裁剪边距覆盖已打开的面板，因此面板可见时窗口绝不会被隐藏。面板是一棵「工作文件夹」树：每个已注册工区按注册顺序各占一行——刚注册、还没有任何聊天的文件夹也会列出，因为该文件夹里的第一个聊天正是从它自己的分组里创建的——外加未分组一档；面板标题栏可注册文件夹（浏览器按层列出目录、面包屑可点击、可创建嵌套文件夹，然后把选中的目录注册为项目；宿主挂载的是原生选择器时不提供目录列表，面板随即把选择交给原生选择器并注册它返回的目录）、打开搜索框，以及打开分组与排序菜单（按项目或单一列表；手动或按更新时间）。展开文件夹会就地列出其聊天及相对时间与运行标记；选择其中一个会让窗口指向它——若另一个窗口已显示该聊天，则把那个窗口带到前台而不改动本窗口——面板保持打开。每行尾部都有菜单——项目可重命名、上移下移、复制路径、打开文件夹、删除（只删注册，聊天与文件保留）；聊天可重命名、从最近完成的回合创建分支（窗口随后显示子会话）、移动与归档——每个文件夹行都带有自己的「新建会话」控件，在行上拖动同样会提交移动。这棵树比侧栏低一档密度：会话行 28px、文件夹行 30px、标题 32px、字号 13px。窗口当前会话所在的文件夹会自动展开，展开集合存放在看板 store 中，因此看板重新挂载后树会回到离开时的样子。右面板承载该会话的文件界面：带 `+` 与收起控件的标签条、「开始」页签提供「工作区文件」、文件页签列出会话工作区根目录及其路径与「重新加载」，以及每个已打开文件一个查看页签（图片、PDF、Markdown、文本；由 document-preview 注册表决定读取模式）。页签属于会话，同一路径再次打开会激活已有页签而不会重复；车道中的文件链接——产物芯片、工具卡文件芯片以及形如路径的行内代码——会打开查看页签并展开面板。每个面板都是画布之上独立的一层，高度与外框一致，并随窗口移动、缩放、平移或缩放画布而跟随；拖动其外缘可在该侧范围内调整宽度。关闭的面板不占宽度，窗口标题栏的控件可重新打开；面板自身的标题栏可再次收起。任一面板打开时小地图让位——面板是管理面——而底部 dock 始终可见（Т1.14）；关闭面板后小地图随即返回。Escape 关闭窗口已打开的面板。在 dock 或小地图中选择窗口会聚焦它并把视图居中到其上，唯一的例外是当前窗口在 dock 中的行——当视图仍在它上面时只把它提到最前；若视图已经移开，则把视图带回该窗口，因此这一行永远不会是无效手势。dock 的每一行都会显示窗口图标——聊天窗口以标题首字母构成圆圈，并按工作文件夹确定性地着色（无文件夹时为中性色），克隆显示姓名首字母，设置、连接器、仪表板与任务等窗口显示类型图标——拖动图标超过 5px 阈值即可在本组内重排（窗口之间、克隆之间，间隙中显示插入条），指针靠近边缘时条带自动滚动，完成拖动后会吞掉随之而来的点击；顺序随布局保存，并解析窗口标题、窗口类型，以及其会话通道报告的状态——会话缺失、待创建或等待会话列表时为「创建中」或「恢复中」，回合执行时为「执行中」，创建、提示词、回合或会话消失导致的失败时为「错误」，其余为「空闲」——行的本地化无障碍名称把标题与状态并列；右键点击行会打开经 portal 渲染的菜单，提供重命名（就地编辑器）与关闭窗口，关闭会移除窗口，而其聊天仍存活并留在列表中。在第二个分隔线之后，dock 的克隆条列出部署中的克隆（每个一个紧凑图标），点击其中一个会打开该克隆的编辑器窗口——若已打开则带到前台；标题栏与 dock 用聊天标题命名窗口，聊天还没有标题时回退到该类型经本地化的模板名，并跟随聊天重命名或重新绑定；点击标题栏中的名字——或双击 dock 行——可编辑窗口自己的名字，该名字覆盖聊天标题，直到被清空。窗口首次渲染时会创建自己的会话（该会话出现在侧栏列表中，绑定窗口——创建、重新指向或恢复绑定时——会打开该会话的实时流，但不改变外壳的当前会话（外壳的选择只通过显式切换移动）；聚焦窗口只会把它抬到 z 序最前）；从已保存布局恢复的窗口则重新附着到它当时显示的聊天，而宿主不再列出的聊天会让窗口停留在「缺失」状态——车道说明情况并提供「新建会话」与「选择聊天」，直到该聊天回归或选了另一个。dock 的 `+` 目录包含「新建窗口」一节——agent 与任务会打开可用的看板窗口，连接器与设置打开的窗口其主体承载本地化的「此 MVP 不可用」一行，「新建克隆」会创建一条克隆记录并打开其编辑器窗口，仪表板则给出其本地化的「MVP 暂不提供」提示——以及「最近的聊天」一节，列出最近更新的六个聊天及其目录（重新打开遵循同一「带到前台」规则）；看板的所有菜单都经 portal 渲染，并开在空间更充裕的一侧。检查器激活时点击元素会捕获一个确定性的 `tag:nth-of-type(n)` 选择器路径——锚定在看板表面，或锚定在 `body`——以及一段语言无关的描述，涵盖元素的标签、所在窗口的类型与标题、`data-board-action`、无障碍名称、工具提示，以及 60 字符的文本摘录，并把本地化的芯片追加到被寻址窗口的 composer 草稿，寻址规则与 相同，即当前聊天窗口，否则新建 agent 窗口；浮层让指针通过，在捕获阶段取得点击，因此其下方的控件绝不会被激活，遇到打开中的菜单时让位，按 Escape 取消。composer 与主聊天一致：`+` 打开操作菜单（文件与图片、目标、计划、反馈、压缩、权限、导出），`/` 按输入过滤斜杠命令并显示参数提示与描述，`@` 提示文件、目录与会话，芯片行可切换权限预设（完全访问走风险确认）以及模型与其推理等级，圆环显示上下文占用——提供方首次报告前显示空态破折号，随后为正常、警告（超过 80%）与严重（超过 95%）三态，圆弧与读数同时着色，提示以 `% · used / window` 的紧凑单位显示——麦克风按钮在引擎提供语音识别时把语音转写写入草稿；以已知命令开头的行会带着参数对会话执行——连同草稿中的图片与已上传文件，因此不接受附件的命令由宿主以自己的原因拒绝——图片遵循宿主投影出的上限（超过数量、单张大小或总大小的批次会连同本地化原因被拒绝），其他文件后台上传并以回执随行；卡片还接受拖入的文件与粘贴进输入框的文件；agent 预设芯片是 composer 中唯一的设置芯片（工作目录由窗口的聊天面板承载），面板的文件夹动作会把选中的目录注册为新聊天的项目文件夹；新窗口以看板记住的预设启动——在芯片或 dock 目录的「预设」条目中的最后一次选择会成为默认值、随布局保存，并应用到窗口新建的空白会话——宿主拒绝预设时会在 composer 下方给出本地化原因，会话已开始时芯片禁用并在提示中说明原因，无法组合会话的预设绝不会出现在菜单里；模型芯片的提示会说明当前模型与推理等级，并指出切换会保存为新会话的系统默认值；模型目录加载失败会在模型菜单内显示，窗口保持可用。Enter 发送，Cmd/Ctrl+Enter 引导正在执行的回合，Shift+Enter 换行，圆形按钮停止；每次发送都会在宿主准入之前先在车道中注册本地回声，草稿及其芯片在宿主拒绝提示时恰好原样返回一次（用户已继续输入的 composer 保留其更新的文本，并把被拒草稿作为新段落追加）；排队的消息连同其附件渲染在卡片上方的队列条中，并提供编辑（仅文本）、移除，以及回合运行时的引导，仍未等到对应队列行的排队回声渲染为「发送中」行，被拒绝的队列变更在队列条中显示宿主给出的原因，取消则保留宿主将按顺序恢复的排队工作；插话纠正——待定与持久——在车道中渲染为各自的用户气泡，持久的回合失败渲染为一张本地化卡片，其可展开详情携带提供方消息与错误码，重试操作重发失败回合的提示，而通道的通用失败行只在没有任何卡片承载该失败时出现；卡片会自行测量宽度，工具栏永不换行——权限与模型芯片的标签保留第一个词并省略其余，在卡片最窄时退化为图标——因此发送控件在任何尺寸下都可达；`Load earlier turns` 以一次补偿性滚动写入（原生滚动锚定已禁用，避免调整叠加）把更早的回合拉入车道，保持读者的位置并在加载期间禁用自身；车道把每次工具调用渲染为自己的卡片，并在运行中的调用执行期间保持其已用秒数可见，卡片表读不出的调用回退为折叠的 JSON 块，已落定的结果所属调用落在已加载窗口之外时保留其不可用行与重试控件，而空、创建中、失败、运行与受阻状态各自渲染自己的本地化行；聊天窗口的标题栏带有「展开到标准界面」按钮（Т2.1）：它把窗口未发送的草稿交给会话自己的 composer、选中该会话，并返回标准界面。任务窗口按最新在前列出部署中的克隆自主任务，每行给出状态胶囊、目标与相对时间；待启动任务提供「开始」（创建任务随后运行的会话），待启动与执行中的任务都可取消，带有会话的任务可在聊天窗口中打开该会话，执行中的任务显示其已进入的目标回合数与任务上限。从克隆的「自动驾驶」表单打开的窗口默认只显示该克隆的任务——筛选行可在「此克隆」与「全部」之间切换——并带有「目标」表单，无需离开窗口即可存储并启动任务；行内的「报告」开关展开任务的 Markdown 摘要，以及从其会话记录中折叠出的文件产物。只要窗口可见范围内仍有待启动或执行中的任务，主体就每 750ms 重新读取该列表，并在最后一个可见活动任务结束后停止。

客户端插件的 `Config` 承载滚轮行为：`wheelMode` 为 `'pan'`（默认：无修饰键的滚轮在画布或浮动浮层上平移）或 `'zoom'`（改为缩放画布）；`zoomSensitivity` 是 `factor = exp(−Δ·k)` 中的 `k`（默认 0.0023，因此完整双指捏合约 300px 的行程让缩放约变为两倍）；`detailZoomThreshold` 是窗口切换为简化卡片的缩放阈值（默认 0.4，即 R-6 决定）。同一 `Config` 还承载元素流的时序：`elementStreamRetryMinMs`（1000）、`elementStreamRetryMaxMs`（15000）与 `elementStreamHiddenCloseMs`（60000），以及窗口记录发布器的静默期与重试间隔 `windowPublishDebounceMs`（300）和 `windowPublishRetryMs`（5000），以及待办列表放置的重试间隔：`todoPlacementRetryMinMs`（1000）与 `todoPlacementRetryMaxMs`（30000）。

窗口之下的元素是宿主看板文档，而不是布局状态：一个共享图层按种类层级、绘制优先级与 id 顺序在窗口下方绘制每个可读元素，每个元素都带有其参与者的所有者颜色边缘。点击元素将其选中——一次只选中一个，聚焦窗口或点击空画布会清除选中；用主按钮拖动自己的元素会移动它并在松开时提交一个 patch 操作，未按 Alt 时吸附到 24 px 网格，屏幕上（任意缩放下）位移小于 5 px 视为点击，在文本编辑器内按下从不拖动；拖动其右下角会把它缩放到该种类的最小尺寸；Delete 或 Backspace 会删除自己选中的元素，除非焦点在编辑器、打开的菜单、窗口或按钮中（Enter 与 Space 同样不作用于按钮）。每个框架与每个缩放角都在 Tab 顺序中：聚焦框架会选中它，缩放角上的方向键按一个网格步长缩放。他人的元素可以选中，但不提供手柄也不能移动。选中元素上方的屏幕空间条承载其种类工具栏（`board.element.toolbar`），由便签、笔迹与待办阶段占用。

便签是看板的纯文本元素。`+` 目录的「添加到看板」分组在可见安全区域中心创建一张便签（任意平移与缩放），选中它并打开其 textarea 进入编辑；便签自身的滚动区域带有 `data-board-wheel="native"`，因此滚轮落在文本上滚动文本，而 `Ctrl/Cmd+滚轮` 仍缩放画布。所有者通过便签的屏幕空间工具栏菜单选择字体（常规、衬线、等宽）、字号（S/M/L）与元素缩放（50–300%）；选择缩放会同时 patch `w`、`h` 与 `data.scale`——世界矩形在新档位下保持相同内容——而选择字体或字号只 patch 各自的 data 键。文本为纯文本（无富文本格式）；编辑期间其值存放在组件本地草稿中：流补丁与新的快照绝不会覆盖 textarea 或移动光标，草稿在最后一次按键 400 毫秒后以一次 `patch { data: { text } }` 到达文档，并在离开编辑器时立即写入；`pagehide` 或标签页隐藏时以 `keepalive` 冲刷待写文本（默认文本上限使普通文本保持在 64 KiB 的 keepalive 体积限制内；若部署把 `noteTextMax` 提高太多而超过该浏览器上限，则只有防抖写入与失焦写入能送达文本）。保存被拒绝时会显示看板通知，编辑器保持打开并保留草稿，在下一次冲刷时再次发送；离开编辑器时会等待仍在进行中的保存，只有宿主接受文本后才关闭，拒绝永远不会发送空文本；便签卸载时写入待写文本，并且只在该便签仍是正在编辑的便签时结束编辑模式，正在编辑的便签不受剔除影响；只有所有者能打开便签编辑，他人的便签只读且不显示设置按钮。

待办列表元素渲染宿主拥有的某个 Beads 列表快照。`+` 目录的「添加到看板」分组在弹出框中询问列表名称，并在可见安全区域中心创建列表；输入框中的 `/todo <标题>` 创建的列表其元素携带 `pendingPlacement`，由属主的第一个已挂载看板的可见标签页放置到各自安全区域的中心——每个列表只请求一次：宿主任何应答都结束尝试，他人的列表从不请求，只有宿主不可达时才以递增间隔重试。列表主体绘制进度条（`role="progressbar"` 与已完成比例）、未完成条目和「已完成」分区；所有者通过视觉隐藏的原生复选框切换条目，SVG 勾会自行绘制，标题加上删除线，被切换的行以 FLIP 变换动画移入已完成分区，位移按列表内的布局偏移测量，因此平移、缩放与移动列表都不会让行产生动画——在 `prefers-reduced-motion` 下全部动效关闭。所有者的添加字段在回车时追加一个条目，刷新控件重新读取史诗；史诗消失的列表显示横幅并保留最后的条目，条目数达到 `todoItemsMax` 时禁用字段并显示「列表已满」提示。他人的列表只读渲染，没有复选框、添加字段与刷新按钮；`bd` 失败以本地化的看板通知呈现。

变更通过宿主的 `/api/ketos.board.events` 流到达该 Ketos 的每个标签页：先一个 snapshot 事件，随后每个已提交批次一个 patch 事件。store 在收到快照时整体替换元素切片，并丢弃修订号不更新的补丁；有操作在途的元素忽略流的回声，被拒绝的操作会显示看板通知并重新读取快照。连接中断后以递增的暂停重连，标签页隐藏超过 `elementStreamHiddenCloseMs` 时关闭流并在返回时重开，从而保持 HTTP/1.1 每源连接预算。首个快照把文档的 `selfId` 采纳为当前参与者：所有仍属于旧演示自我的已存窗口都会被改写为它，因此在首个快照之前恢复的布局仍归当前参与者所有，而其他演示所有者显示为中性的「未知参与者」。

克隆窗口编辑一条克隆记录，并在其档案被草拟期间承载草拟它的访谈。窗口状态携带该记录的 `cloneId`（随布局持久化，因此恢复的克隆窗口会重新打开对应的克隆），标题栏与主体之间有一条三页签条带：「档案」渲染卡片表单——名称、角色、简介、角色设定、方法论、首选模型路由与生命周期状态（`draft`、`interviewing`、`ready`）——旁边是修订指示与记录的更新时间。方法论字段按四个规范章节读取实时草稿：存储的标题保持规范标记，而胶囊与缺口提示按界面语言渲染，每个未填写的胶囊仍显示本地化的「空」/「无」标记；它在提示中列出缺口，并在字段为空时提供「插入模板」。技能区按行列出技能——名称与其描述，或名称不合 kebab 语法、重名、描述仍为空时的警告——行尾菜单提供编辑与删除，沿用聊天面板的行菜单约定；添加按钮打开的模态窗校验 kebab-case 名称、唯一性、100 个技能上限与各长度边界。「访谈」在与其他聊天窗口相同的对话主体中渲染窗口自己的 Harness 会话，因此访谈就是一场带普通 composer 的普通聊天，「记忆」把窗口主体切到 `clone-memory` 并渲染该克隆经 `/api/ketos.memory` 存储的记忆：`active`、`candidate` 与 `archived` 三个状态筛选胶囊、一个把查询拆成词元并按带引号前缀匹配的搜索框及其清除按钮、每条记忆一行并显示其状态、来源会话（没有来源时为「用户」）、更新时间、内容与标签、针对内容、标签与状态的就地编辑器，以及需要一次确认的删除，但没有创建控件——新记忆由 agent 通过 `clone_memory_remember` 写入，窗口则校验、编辑与删除它保存的内容；路由拒绝的读取会渲染带重试的失败行，而不是空的记忆列表；每次被接受的变更都会重新读取列表，宿主随即重建克隆 agent 的记忆快照，因此它的下一个回合能看到用户刚留下的改动。「开始访谈」（档案已存在时为「重新访谈」，旧草稿会保留到新保存取代它）按表单读到的修订号把克隆标记为 `interviewing`——在那里被拒绝就是整次失败，因此不会留下任何启动到一半的东西——然后创建会话、以访谈角色绑定它，并把该会话交给这个窗口，窗口随即切到「访谈」页签；宿主把访谈指令与草稿保存工具组合进那一个会话，并以一个开场轮次开启对话，状态为 `interviewing` 期间条带显示简短指令与已作答的交换条数。通过 `/api/ketos.clones` 保存卡片仍然按修订号校验：卡片已在别处修改时界面给出「已在别处修改」并重新读取记录，因此再次保存会覆盖更新的修订；克隆已离开名册时，窗口停留在缺失状态。每当访谈轮次落定，看板都会重新读取克隆名册，因此 agent 保存的档案会出现在表单中；被存储记录移动过的字段标为「智能体已更新」，用户未发布的文本始终保留，脏草稿把存储的修订号保留为一行待处理项，一键即可应用。访谈进行中克隆变为 `ready` 会升起一条检查提示，点击会打开「档案」页签。表单未保存的文本在 agent 修订后依然保留：存储的值会停在待处理行中，直到用户应用它们，而用户自己的保存绝不会显示为 agent 修订。删除只需一次确认，随后移除记录、其会话绑定及其编辑器窗口；表单下方的已绑定会话列表会打开任一绑定——窗口自己的访谈则改为把本窗口切到其「访谈」页签。首选模型选择器提供部署的模型目录与「部署默认」，把选择存为 `provider/model` 路由，新建的访谈会话会以它启动；该选择只作用于该克隆的会话，新普通聊天遵循的 `agent-default-model` 系统默认值保持不变。外框与 dock 以克隆命名该窗口——访谈会话生成的标题绝不会重命名该记录的窗口——直到用户重命名它。表单未保存的文本与 agent 变更标记在各页签之间保留：它们存放在看板 store 中，因此切换主体绝不会丢弃它们。

## 理解实现

**Runtime invariant:** 无已发布的 companion。面板条目把 `main` 槽位连同唯一的 engine store 一起注册，并声明它渲染的各个层；条目的销毁证明移除，同时可通过 `board.*` 槽位声明独立观察。

minimap 之上、元素选择浮层之下——每个窗口外框、聊天面板、dock 与 都通过它托管自己的 tooltip 与菜单：窗口浮层按看板缩放渲染并限制在看板盒内，屏幕坐标外框按 1 渲染，窗口菜单在平移与缩放时跟随触发元素，但在其窗口移动、缩放、被裁剪或关闭时收起。因此看板与其他面板一样跟随外壳的明暗偏好。手势只有一个归属：每次拖动（画布平移、标题栏、窗口缩放、面板缩放、行重排、dock 重新发布；关闭窗口会丢弃它的桥记录，而会话本身保持存活并仍在列表中。该映射是持久的：桥在离散事件（创建、重绑、关闭）上把它交给持久化层，settings 段以 `bindings` 承载它并以整节替换的方式写入，因此关闭窗口的配对确实会离开分节，每次采纳都会恢复每个窗口的聊天；`sessions.list` 是权威，把已绑定窗口在「恢复中」「就绪」「缺失」之间移动，并让回归的聊天重新附着；一个会话只属于一个窗口——`bind` 返回 duplicate、same、unknown 结果，面板与 dock 目录的最近聊天列表会把持有窗口带到前台，而不是打开第二个。外框与 body 注册把该 channel 暴露为 keyed hook `useWindowSession(windowId)` 以及 composer 回调（`ensureWindowSession`、`sendPrompt`、`cancelPrompt`、`loadOlderTurns`、`executeCommand`、`uploadFile`），因此一个注册即可服务所有窗口，组件只接收普通数据；`uploadFile` 通过宿主的后台上传服务暂存非图片文件，并把回执交给 composer，由提示或命令随行携带。看板外框共享寻址与放置规则：`open-window.ts` 解析命令作用于哪个聊天窗口（`resolveChatWindow`——当前聊天窗口，否则新建 agent 窗口），store 中的 `composerIntents` 队列携带追加文本与打开文件选择器两类命令，直到 `ComposerBar` 消费它们（文件选择器会等到 composer 能接受文件，窗口关闭则丢弃其排队命令），store 的 `drafts` 映射在内存中保存每个窗口未发送的 composer 草稿——切到标准界面导致看板卸载时文本、图片与已暂存文件都会保留，关闭窗口则丢弃，且布局从不携带它们，`element-capture.ts` 构造检查器芯片背后的确定性选择器与语言无关描述，`menu-placement.ts` 是每个看板浮层共用的单一规则，让列表开在更宽裕的一侧。低于 `detailZoomThreshold` 时，每个外框通过一个 `useStore` 布尔选择器把详细外观换成简化卡片，因此 20 个窗口的看板只在某个窗口跨越阈值时重新渲染；`BoardRoot` 在启动拖动的那次 pointerdown 以及每个滚轮或 Safari 手势事件上为画布表面打开 `will-change: transform`，并在最后一个事件之后 150 ms 移除，使表面只在手势进行期间保留 GPU 栅格化。当屏幕步长会低于 8 px 时，画布点阵把世界步长加倍（24 → 48 → 96），并让点朝该下限逐渐变淡。每个浮动浮层元素声明自己锚定的看板边缘（`data-board-chrome`），并通过自身与看板盒上的 `ResizeObserver` 发布自己从该边缘起的深度；store 把各贡献折叠成逐边距，`safeArea(state)` 把空闲矩形投影到屏幕与世界坐标，窗口放置与居中都会读取它（Т1.15）。因此横跨底部的宽 dock 绝不会占用左右边缘。

窗口归属是持久化布局的一部分：每个存储的窗口携带 `ownerId`——空字符串表示当前参与者——以及一条 `access` 记录（`mode` 为 `owner`、`selected` 或 `all`，外加 `people` 列表），这些字段都在 `board-settings.ts` 中带默认值，且 `version: 1` 保持不变，因此在归属出现之前保存的布局读回时会显示为当前参与者所有、仅自己可见。修复按设计只做格式校验：`client/owners.ts` 接受任何格式良好的 id，丢弃重复项与所有者本人，把列表截到 `BOARD_ACCESS_MAX_PEOPLE`，且从不校验名册成员资格，因为名册要到阶段 32 才异步到达；名册不认识的 id 保持中性色板并回退为「未知参与者」标签。所有者颜色是 22 个令牌（`BoardViews.module.css` 的 `.root` 中 `--board-owner-{1..10,unknown}-{edge,fill}`，其暗色规则重新绑定它们），由外框根节点的 `data-board-owner-color` 属性（`"1"`–`"10"` 或 `"unknown"`）选中；组件只读取 `--board-owner-edge` 与 `--board-owner-fill`，不写任何字面颜色。bezel 是 `WindowFrame` 的子层（`WindowBezel.tsx`，含 `OwnerBadge` 与 `AccessIndicator`，以及管理者的 `OwnerTransferMenu` 与 `AccessMenu`），因此随窗口一起移动、调整大小并跟随看板缩放，无需看板侧的同步：外框 `::before` 上的 2px 所有者边缘始终可见，bezel 在悬停、焦点进入或选中时以 `var(--ds-transition-duration)` 滑出，减少动态效果时取消过渡，打开的面板会让条带在其所在的一侧让位，低于 `detailZoomThreshold` 的 `simplified` 模式只渲染边缘。`owners.ts` 是唯一的参与者来源（`currentOwnerId`、`boardParticipants`、`participantOf`、`ownerColorAttr`）：名册按 `selfId` 合并文档的参与者记录与对等通道的已知节点，当前参与者自己没有名字的记录通过 `owner.self` 显示为「Я」，没有任何记录覆盖的所有者保持中性色板并显示「未知参与者」标签，只有 `DEMO_SELF_ID` 仍作为 `adoptSelfId` 在参与者出现之前保存的布局中改写的标记，而 `canManageWindow(state, window)` 是每个移交与访问动作都会检查的、只允许所有者通过的检查：`transferWindow` 保留窗口的位置与 agent，设置新所有者，并把新所有者从 `people` 中移除；`setWindowAccess` 在模式切换之间保留 people 列表；前所有者无法管理已移交的窗口，窗口也不会回来（阶段 33）。

窗口记录与元素通过 `@ketos/peer` 与第二台 Ketos 同步：文档产生的每个事务都被转发，来自对端的更新以 `peer` 来源应用且绝不回声，每次连接——首次与每次重连——两份文档交换状态向量，因此断线期间的编辑会在下一次连接时补齐。可见标签页通过 `window-publish.ts` 发布本浏览器的窗口——每个发生变化的窗口一次 `window.put`，在窗口静止 `windowPublishDebounceMs` 后发出（位置、尺寸、标题、所有者、访问或会话状态；标题依次取窗口自己的名字、克隆窗口所编辑克隆的名字、聊天标题，并截断到记录的标题上限），以及唯一产生 `window.remove` 的核对：它仅在可见标签页上、`layoutSource` 已知之后进行，且绝不删除 put 仍在途的记录。从设置服务器采纳的布局（`server`）丢弃布局已不再持有的每条自有记录；非 loopback 页面保存在内存中的布局（`memory`）只丢弃本标签页自己 put 过的记录，因此绝不删除本 Ketos 另一页面发布的窗口。每个操作单独发送：被记录预算拒绝（`ketos/limit`）的 put 会在文档记录数减少后再次发送，其他被拒绝的记录（`ketos/unreachable` 以外的任何主机代码）要等该窗口发生变化才重试，而不可达的发送在 `windowPublishRetryMs` 后重试。隐藏标签页保留改动且不删除任何记录；返回时重新声明每个窗口并核对。foreign 窗口渲染为带所有者 bezel 填充、没有菜单、拖动或缩放手柄的卡片（`window/ForeignWindowLayer.tsx`，按可见矩形裁剪，按记录的 z 绘制在元素与本地窗口之间，且每个框架仅在自己的记录变化时重新渲染）。框架页眉对每种 kind 只写一次窗口名与状态；其下的卡片补充所有者和每 30 秒重新计算的「最近更改：N」行。`ForeignChatCard`（`agent` 种类）没有输入框和编辑器：记录带有 `sessionId` 时，「显示对话记录」通过 `POST /api/ketos.peer.transcript` 读取所有者最近的消息（`transcript-api.ts`，在边界处校验，以 `fetchTranscript` 注入），显示为保留原生滚轮的可滚动纯文本列表，「刷新」在保留已有消息的同时重新读取，「隐藏对话记录」将其折叠。读取失败时说明原因——所有者已关闭对话记录、所有者不在线、超时、窗口已不存在或通用错误——所有者的拒绝还会清除已列出的消息。其他 kind 显示 `ForeignWindowCard`，即「{name} 电脑上的窗口」加 kind 标签。foreign 元素只读（没有手柄、编辑器或橡皮擦经过），`peer.stale` 在其元素与窗口上标出通道未在线（`lost` 或 `connecting`）的已知所有者，直到其恢复；窗口上的标记可获得焦点和指针，因此提示可由键盘与鼠标打开。`canManageWindow` 拒绝不在本 Ketos 布局中的窗口，因此另一台 Ketos 发布的记录在这里永不可管理，即使其 `ownerId` 是当前参与者。在首个快照指明当前参与者之前，本地窗口的所有者显示为中性的「我」，而不是未知参与者；之后，所有者不被任何记录或对等端指明的本地窗口（本 Ketos 的早期身份）在其 bezel 上提供「设为我的」，访问菜单也会把名册之外的已选人员列为未知参与者，使所有者可以移除他们。

元素切片位于同一个 store 中（`boardElements`、`boardElementsRevision`、`boardDocId`、`boardLimits`、`selfId`、`selectedBoardElementId`、`editingBoardElementId`、`pendingBoardElementOps`、`elementNotice`），并带有自己的动作（`applyBoardSnapshot`、`applyBoardPatch`、`selectBoardElement`、`createBoardElement`、`moveBoardElement`、`resizeBoardElement`、`patchBoardElement`、`setEditingBoardElement`、`removeBoardElement`、`beginBoardElementOp`、`endBoardElementOp`、`setElementNotice`）；快照整体替换切片但保留在途标记，每个请求在收到自己的应答时解除标记，过期补丁被丢弃，有操作在途的元素忽略流的回声。`apply` 通过 `client/board-doc-api.ts` 启动唯一的流副作用（快照与补丁解码、递增暂停重连、隐藏标签页关闭），并通过 `postBoardOps` 为每次手势提交一个操作批次：先把元素标记为在途，收到应答后解除标记，被拒绝时显示通知并重新读取快照。`client/board-coordinates.ts` 拥有客户端/看板/世界坐标的换算、可见世界矩形、安全区域与安全区域放置，`client/todo-placement.ts` 把可见标签页尚欠位置的聊天创建列表放置到位，`culling.ts`、`window-screen.ts` 与 store 都读取它。canvas occupant 声明 `board.elements` 并在 `board.windows` 之前渲染；元素层声明 keyed 的 `board.element.body`（没有 occupant 的种类回退到中性主体），便签、笔画与待办列表种类在此注册各自的主体；面板条目声明 keyed 的 `board.element.toolbar` 并在选中元素上方渲染屏幕空间的 `ElementSelectionBar`，便签的设置 occupant 随之注册；`client/board-element-kinds.ts` 持有各描述符，`elements/ElementFrame.tsx` 拥有选中与移动、缩放手势，`BoardViews.tsx` 拥有 Delete 与 Backspace 的守卫（编辑器、打开的菜单、窗口或检查器都会让该快捷键让位）。

无模型体验：board 是纯浏览器画布，不注册任何工具、提示词段落或会话事件，渲染的一切都是 board 本地视图状态。

## 已知限制与暂缓事项

<a id="known-limitations-and-deferred-work"></a>

这些限制属于当前包的约束。

- **窗口车道渲染正文、插话、工具卡片与回合失败** —— assistant 文本以 Markdown 呈现且流式文本可见；每次工具调用都渲染为自己的卡片（`bash`/`pwsh`/`terminal_send` 显示为终端，`read` 显示为文件窗口，`write`/`edit`/`str_replace_editor` 显示为差异，`grep`/`glob` 显示为搜索结果，`web_search`/`web_fetch` 显示为引用，`todo_write` 显示为待办清单，`read_image` 显示为图片预览，`ask_user_question` 显示为已作答的转录），而卡片表读不出的调用——未知工具、畸形的结果、落在已加载窗口之外的调用头——回退为折叠的 JSON 块。运行中的卡片显示其已用秒数，并落定为成功、失败或已停止状态，本地化失败行下方是提供方自己的错误文本。该范围之外的转录节点——压缩检查点、达到输出 token 上限的回合，以及模型重试——目前什么都不渲染。
- **待处理的审批或提问会给窗口打上横幅并导航到主面板（为 MVP 决定）** —— 应答 UI（允许或拒绝、提问流程）位于主面板的 composer 中，因此窗口显示一条本地化的 `Confirmation required`（或 `Answer required`）横幅，其按钮选择会话并把主区域切回 Conversation；在请求得到解决之前，窗口自己的 composer 保持惰性，并以横幅的标题作为其原因。随后当看板面板回来时，看板会把发起窗口带到前台并短暂高亮。窗口内不渲染任何内联审批表面。
- **看板的文件芯片只存在于草稿期间** —— 非图片文件经宿主的上传服务暂存，并在其窗口存活期间以回执随行；芯片只保留名字与重试，不保留字节或上传进度，回执在窗口关闭后无法再次发送。`@` 提及插入纯文本而非编辑器芯片。
- **展开窗口会重新上传已暂存的文件，并报告被拒绝的交接** —— 展开控件把窗口草稿交给标准界面：文本以新段落并入标准 composer 自己的文本，已暂存文件再次经过宿主上传服务，因此已为该窗口上传过的文件会被第二次上传。标准 composer 拒绝的交接——会话正在准入、composer 拒绝的文件、宿主已不再列出的会话——会把窗口草稿原样保留，并在窗口 composer 中显示本地化原因，直到下一次尝试；只有成功的交接才清空窗口被转移的部分。从标准 composer 返回的文件是没有浏览器字节的「仅 receipt」条目：再次展开会把它留在窗口中，被拒绝的发送会在其芯片上标记失败且没有重试。
- **返回控件把标准草稿带回窗口** —— 当前会话绑定到某个已打开的看板窗口时，会话页眉带有「返回窗口」按钮：它选中看板、把该窗口居中并高亮，并把标准 composer 的文本（作为窗口自身文本之后的新段落）与附件移入窗口草稿——图像带字节，文件以 receipt 形式。正在准入或上传未落定的 composer 会保留其草稿，窗口则报告草稿留在了标准界面。该按钮是唯一的返回途径：Escape 绝不返回看板。
- **窗口 composer 保有自身的提交策略（在此决定）** —— Enter 排队，Cmd/Ctrl+Enter 引导，且不读取提交偏好设置：`ui-conversation` 的 `busyEnter` 偏好位于该插件的设置命名空间，且只映射裸 Enter 手势，而看板的窗口按文档在两个手势上保留排队/引导组合。
- **命令的失败行可能使用宿主原文** —— 处理程序被拒或附件被拒时，错误在「Command failed:」之后按宿主自己的措辞显示，而未匹配的行显示看板自己的未知命令文案；失败信息保留到下一次发送。看板的命令列表在宿主注册表之外补上自己的 `/file` 与 `/model` 条目（文件选择器与模型菜单）。
- **队列编辑只替换文本** —— 宿主的编辑动作只接受非空纯文本替换，因此其他内容块本来重要的排队消息会丢失它们；行的图片缩略图通过会话范围的对话缓存解析，读取失败时保留占位符；回合失败卡片的重试操作会排队一个新回合，因为客户端没有暴露原地重试回合的 API。
- **被拒绝的队列变更会留在屏幕上，直到下一次队列操作或发送** —— 队列条在其行下方渲染宿主给出的原因；没有逐行的错误状态。
- **助手 Markdown 保持应用的正文字号** —— 共享的 Markdown 表面读取应用的字体大小设置，因此只有窗口自身的 chrome、转录文本与 composer 采用窗口缩放；要放大助手正文请调高应用的字体大小。
- **聊天面板没有取消归档，也没有删除会话** —— 归档聊天是单向的，客户端根本没有删除会话的能力，因此聊天行菜单中的删除条目是空操作；删除项目只删除注册，绝不动它的聊天与文件。
- **面板的文件夹浏览器只读取 browse 选择器** —— 挂载平台原生选择器的宿主不提供目录列表，此时该层会说明这一点，并把选择交给原生选择器；这类宿主上没有应用内浏览。
- **任一面板打开时小地图让位** —— 面板是管理面，否则小地图的条带会压住面板外缘与缩放手柄；底部 dock 在面板打开期间保持可见（Т1.14），关闭面板后小地图返回。
- **缩放手柄随当前窗口升到浮层之上** —— 手柄环只为被聚焦的窗口绘制，因此当窗口边缘落在 dock 或小地图下方时，仍需要先点击该窗口外框任意位置，其手柄才会升到这些层之上。
- **图标超出看板宽度后 dock 横向滚动** —— 条带会先增长到看板宽度减去每侧 24px 的边距，随后横向滚动，而不是裁掉图标与控件；在其上滚动滚轮即可滚动它，垂直滚轮同样有效。
- **裁剪使用固定的世界边距** —— 窗口超出可见画布 480 世界单位后，其内容停止绘制与命中测试，与其尺寸无关；它的盒子仍在布局中占位，该边距覆盖手柄与展开的聊天面板，隐藏期间窗口保持自身状态。
- **每窗口设置来自 composer** —— agent 预设芯片只在会话仍然空白时可切换（芯片会说明该原因），看板会记住最后一次选择作为新窗口的默认值，模型芯片可切换模型与其推理等级；模型选择还会保存为 `agent-default-model` 系统默认值，芯片提示会说明这一点；而克隆的首选模型只作用于该克隆的会话，不改动系统默认值。预设不会固定模型：模型是会话属性，因此同一个预设的两个窗口可以运行不同模型。已启动的会话保留其工作目录，只有仍然空白的会话才能在重新选择文件夹后重建。
- **外框的 body 分发器是 owner prop** —— 窗口层是 `board.window.body` 的唯一声明者（槽位核心允许每个键只有一个声明者），因此它向每个外框传入 `renderBody` 回调，而不是外框自己的 `renderSlot` 席位。
- **布局通过 `ui-board` settings 命名空间持久化，并带有 MVP 规模的限制** —— 窗口、其几何与顺序、dock 与克隆图标顺序（二者独立于绘制顺序，因此抬升窗口绝不会移动其图标）、平移/缩放、当前窗口、每个窗口的面板状态以及窗口 → 聊天绑定都存放在用户设置文档的 `ui-board` 段中，因此能挺过页面刷新与进程重启；同一文档的 localStorage 副本用于绘制首帧。写入带防抖（最后一次手势后 600ms，每秒至多一次），因此在该窗口内崩溃会丢失最后一次手势；同时打开两个标签页时，写入失败的一方会按冲突报告的修订号重试一次，最后由最后写入者生效。展开窗口标记与视口尺寸只在会话内有效：二者都不恢复。文档带 `version: 1`；无法识别的版本，或未通过 schema 的布局，会被忽略并给出警告；MVP 不做迁移——未来版本会从空白看板重新开始。绑定在每次采纳时与布局对账——布局已不再持有的窗口其配对会被丢弃——会话已消失的配对则保留，以便窗口报告情况并在聊天回归时重新附着。关闭窗口同样会移除其配对：看板写入整节而非合并补丁，因为 settings 服务会深度合并补丁，合并永远无法删除该键。
- **布局文档最多保存五十个窗口** —— 捕获只写入最上层的 `BOARD_LAYOUT_MAX_WINDOWS` 个，schema 拒绝更长的列表，因此窗口更多的看板在重新加载后只恢复最上层的五十个，而看板本身不设上限（验收运行打开了一百个窗口并按视图裁剪；见 `docs/ketos/perf-baseline.md`）。
- **存活克隆会话会跟随档案与记忆编辑，但保留其已注册的技能** —— 存储的档案或方法论变更会就地重新发布该段落，记忆写入会重新发布快照，因此运行中的会话在下一个回合就能看到两者，无需重启；档案文本是请求前缀的一部分，因此一次档案编辑会从第一个变化的词元起丢掉可复用的 KV 缓存前缀，而记忆写入随下一条运行时上下文消息到达并保持前缀不变；技能编辑要等 scope 被重新安装或 agent 被重建，因为模型保留其会话在创建时注册的集合；该机制由 [`@ketos/clone-core`](../../ketos/clone-core/README.zh.md) 拥有。
- **完成通知需要窗口观察到这次转换** —— 「访谈完成」由在持有访谈会话期间看到存储状态转为 `ready` 的克隆窗口升起；在没有窗口观察到的情况下发生的完成（窗口已关闭，或之后页面被重新加载）会显示就绪的档案，但不带该通知。
- **访谈报告状态与规模，而非主题进度** —— 条带显示克隆是否处于 `interviewing`、指令以及已作答的交换条数；覆盖了清单中的哪些主题留在对话里，看板不跟踪它们。
- **访谈会话只能通过其克隆窗口的「访谈」页签抵达** —— 在聊天面板中选择该聊天会把克隆窗口带到前台但不切换页签，页签条带是唯一能做到切换的控件；窗口拥有会话之前该页签处于禁用状态。
- **一个聊天只属于一个窗口，消失的聊天不会被替代** —— 另一个窗口已显示的聊天绝不会被绑定两次：选择它会把持有窗口带到前台。宿主不再列出的聊天会让其窗口停留在「缺失」状态，提供「新建会话」与「选择聊天」；MVP 从不自动创建替代会话，客户端也不提供删除会话，因此这两个动作是车道仅有的恢复途径。
- **工具与设置窗口以不可用提示代替内容** —— 连接器、设置与仪表板窗口的主体渲染本地化的「此 MVP 不可用」一行，而非真实内容；仪表板窗口在 MVP 中没有创建入口。真实的每窗口字段随拥有它们的阶段到来，而 Harness 本身并没有客户端 system prompt 编辑器。
- **dock 状态是窗口会话通道的粗略四态投影** —— 创建中、执行中、空闲或错误，不提供逐工具的进度；创建、提示词或回合失败都显示为错误。
- **dock 的重命名与关闭位于行的右键菜单中** —— 没有可见的逐行关闭按钮，右键点击行才会打开该菜单。
- **检查器芯片是普通草稿文本** —— composer 没有编辑器芯片，因此捕获的芯片以文本形式随行，携带 DOM 描述与 `:nth-of-type` 选择器，而不是截图。
- **工作目录与项目管理收拢在窗口聊天面板中** —— 会话创建后工作目录不可更改（核心引擎约束）；新聊天继承项目的文件夹或使用默认工作目录。composer 不再包含文件夹芯片；项目创建、文件夹注册、路径展示与快捷动作（「复制路径」、「在文件管理器中打开」）全部由窗口聊天面板承载。
- **任务列表是一份共享读取，被裁剪的窗口仍会轮询，任务产物来自客户端自己持有的记录** —— 每个任务窗口过滤同一份列表，并在其可见范围内仍有待启动或执行中的任务时每 750ms 重新读取一次，因此在没有任务窗口打开时结束的任务会在下次打开时显示最终状态；被画布裁剪的窗口仍会轮询，因为看板从不卸载它，而报告的产物列表折叠的是此浏览器持有的会话记录，因此窗口从未打开过的任务会话不会报告任何产物。
- **会话产物纯粹派生自已落定的工具结果** —— 看板不扫描文件系统，也不实现完整的文件管理器。产物列表动态汇总会话回合中成功的文件访问与修改工具调用（`write`、`edit`、`str_replace_editor`、`read`），按路径去重并遵循修改优先规则（编辑优先于读取）。每条产物提供路径复制以及通过 `session.openWorkspacePath` 在系统文件管理器中定位。
- **用户主目录与 Ketos 运行时状态隔离** —— 在 `~/.ketos` 或 `$DSH_HOME` 之内注册或设置工作目录在宿主和客户端均会被拦截并返回本地化校验错误；选择根目录（`/`、`C:\`）或整个用户主目录时需要用户二次确认。
- **仪表板窗口以本地化的「此 MVP 不可用」提示作答** —— 其表面属于后续阶段。
- **上下文圆环保留状态与读数，不提供组成面板** —— 它与主面板的 `ContextMeter` 对同一会话使用相同的占用值与公式，提示以紧凑单位显示 `% · used / window`，但看板窗口没有可点开的组成面板。所选模型窗口占用超过 80% 时圆弧进入警告色，超过 95% 时进入严重色；提供方尚未报告用量时显示空态破折号。
- **MVP 以十个同时流式输出的窗口为验证范围，建议最多保持 20 个活动聊天** —— 每个打开的 agent 窗口都会保持其会话订阅，并在回合运行时持续绘制流式文本（克隆窗口只在访谈运行时持有会话，其「档案」页签不持有会话）；实测看板在 10 个窗口、5 路并发流下保持 60 FPS（`docs/ketos/perf-baseline.md`）。超过 20 个活动聊天后，共享传输与逐窗口的会话订阅成为成本中心，因此请关闭当前不用的窗口——关闭窗口不会删除其会话与列表行。
- **记忆编辑以最后写入者为准** —— 记忆行没有修订号，因此用户在记忆主体中的编辑与 agent 的 `clone_memory_remember` 写入以最后落地者为准；主体在每次变更后都会重新读取列表。
- **记忆窗口不能创建记录** —— 它列出、搜索、编辑与删除，而新记忆只来自 agent 的 `clone_memory_remember` 调用，因为 `/api/ketos.memory` 没有创建操作。
- **对等名册覆盖两台 Ketos 实例** —— 名字与颜色来自每个 Ketos 自己的文档记录与对等状态，通道连接后同步文档会携带双方的记录；第三个节点不在范围内，也不存在修改所有者颜色的界面。
- **待办列表只覆盖属主自己的列表** —— 条目不能重命名、删除或重排；他人的列表只读渲染；添加字段在 `todoItemsMax` 个条目时停止。元素层本身没有撤销历史、多选，也没有窗口与元素的交错顺序，便签没有富文本格式，也没有逐便签颜色。
- **元素流每个标签页持有一个连接** —— 隐藏超过 `elementStreamHiddenCloseMs`（60 秒）的标签页会关闭流，并在返回时以新快照重开；无法到达的宿主会以递增暂停重试，该暂停只有在解码出快照之后才回到最短值（打开后未收到快照即关闭的连接会让它继续增长，主机在关闭积压的流之前发送的 `overflow` 事件同样会加长它），在重连成功之前元素切片处于过期状态。
- **元素操作是乐观的，且按字段最后写入者胜出** —— 手势先在本地生效并提交一个批次，只有宿主拒绝时才由新快照回滚；两名参与者编辑同一元素时以最后落定的字段写入为准，因为文档按键合并嵌套映射，而补丁只写入自己改动的字段。
- **已移交的窗口不会回到前所有者手中** —— 移交把窗口交给另一位参与者，并在原地收回前所有者的管理权，同时保留窗口的位置与它的 agent；把窗口交回以及按克隆移交 agent 要等后续阶段。
- **已移交的窗口只在其所在处可管理** —— 移交改变发布方 Ketos 记录中的所有者；其他每台 Ketos 都把该窗口渲染为只读卡片，从接收方管理它不在本条工作线之内。
- **超过上限的同步更新会关闭通道** —— 大于 `maxSyncUpdateBytes`（演示环境为 15 MiB）的更新不会发送：宿主记录 `board.sync.too-large`，通道以关闭码 `4n` 关闭，对端随后重拨。正常看板远低于该上限（笔迹已取整）。
- **所有者没有任何在线的对端条目时出现过期标记** —— 名册中带有该所有者身份的每个条目都是 `lost` 或 `connecting`；没有对等网络的部署以及对等名册不认识的参与者都不渲染标记；接收方继续显示手中最后的数据，任一条目重新在线后标记消失。「忘记」会从主机列表中移除没有通道的对端，其重拨随之停止；被忘记的对端重新在线，或在一次轮询将其移除后再次出现时，即使弹出层保持打开也会重新显示。
- **布局不同的两个可见标签页会删除彼此的窗口记录** —— 同一 Ketos 的两个可见 loopback 标签页布局分叉时（其中一个尚未采纳另一个最近的设置写入），各自按自己的布局核对，因此一个可能删除另一个发布的记录；发布方标签页只在该窗口变化或标签页再次可见时重新 put 该记录，有意不在删除时重新发布，因为那样两个标签页会无休止地删除并恢复该记录。
- **foreign 对话记录是有界的按需快照** —— 只显示所有者限额内的最后若干条消息，不含工具、附件或图片；只有所有者在线且授予访问时才可读取，接收方需手动重新读取，因为状态变化不会刷新已展开的列表。
- **「最近更改：N」比较两台设备的时钟** —— 该时长是所有者的时间戳与本浏览器时钟之差，因此时钟偏差会使其偏移，领先于接收方的时间戳显示为「刚刚」。
- **移出可见画布的 foreign 窗口会丢弃其对话记录** —— 层会卸载离开裁剪边距的框架，因此把已展开的对话记录平移出视野会将其折叠，再次进入视野时从折叠状态开始，需通过「显示对话记录」重新读取。
- **foreign 窗口绘制在元素与本地窗口之间的同一层** —— 记录的 z 只在 foreign 窗口之间排序，不与本地窗口或元素比较，因此便签可以位于 foreign 窗口之上，而每个本地窗口又位于该便签之上。
