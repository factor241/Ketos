# Agent Note: Board input and the popover layer

Status: implemented

English | [中文](2026-09-25-ketos-board-input-and-popover-layer.zh.md)

## Problem

The board audit found that input and popovers broke at the two seams where the board meets the shell. Input had no single decision point: a trackpad pinch (ctrl+wheel in Chromium) over a window lane, the chats panel, its rail, or the floating chrome reached the browser and scaled the whole application; a two-finger swipe only changed the scale because the handler read the sign of `deltaY`; every event applied a fixed ±10% that an inertial tail could ride to a limit; `Cmd/Ctrl+0` reset the board view anywhere in the application while `Cmd/Ctrl+=`/`−` were never board commands; and Safari's `gesture*` events had no listener, so its pinch scaled the page even over the canvas. Popovers had no host: `Tooltip` rendered `position: fixed` inside the transformed canvas, so viewport coordinates were interpreted in canvas space and the bubble landed far from its button or off the board; `Menu` portaled to `document.body` at scale 1, was bounded by the browser window instead of the board, repositioned only on `scroll`/`resize`, and a menu with submenus had neither a height cap nor a submenu flip, so long model lists and nested cards left the screen. Outside the board, an accidental pinch scaled the page anywhere in the shell.

## Decision

**One wheel classifier owns the target decision.** `wheel-zoom.ts` exposes `classifyBoardWheel(event, target, mode)` returning `'zoom' | 'pan' | 'native'`: ctrl/meta anywhere inside `[data-surface="board"]` zooms; a plain wheel over a window lane/implicit scroll surface (`[data-board-window]`, `[data-board-panel]`, `[role="menu"]`) stays native; a plain wheel over the canvas or the floating chrome follows the `wheelMode` field. `resolveBoardWheel` adds `preventDefault` and the fullscreen rule — a fullscreen frame fills the panel and is not canvas, so its pinch is prevented but the board zoom is not applied. `wheelPanDelta` translates one wheel event into the board pan (Shift swaps the axes), and `wheelZoomFactor` is `exp(−Δ·k)` with the delta normalized to CSS pixels by `deltaMode` and clamped to ±50px per event.

**The board's wheel behavior is `Config`.** The `ui-board` client plugin gained a validated `Config` with `wheelMode: 'pan' | 'zoom'` (default `'pan'`, decision R-4) and `zoomSensitivity` (default `0.0023 ≈ ln 2 / 300`, so a fingertip-to-palm pinch changes the scale about twofold), injected into the board root.

**One zoom action serves wheel, gestures, and keys.** The store action `zoomTowardPointer(delta, x, y)` became `zoomBy(factor, x, y)`: the caller owns the factor, and the action keeps the world point under the pointer fixed and leaves the pan untouched when a limit clamps the scale. `panBy(deltaX, deltaY)` applies one screen-pixel pan, and `resetView()` returns the view to pan (0, 0) and zoom 1. `keyboard-zoom.ts` resolves `Cmd/Ctrl+0`, `+=`, and `−` into board view commands only while the pointer or keyboard focus is inside the board root; `+=`/`−` step the zoom ×1.25 around the board centre; outside the board every one of them stays the browser's page zoom.

**Safari pinch shares the wheel path.** `pinch.ts` is a small state machine over `gesturestart`/`gesturechange`/`gestureend` that applies `event.scale / previousScale` on each change. The board root registers the non-passive gesture listeners beside the wheel listener and always calls `preventDefault`, so the page never sees the gesture. A gesture point is converted from screen pixels to board-root pixels through the same `boardPoint(box, event)` mapping the wheel branch uses, so an expanded app sidebar no longer offsets the zoom anchor. In fullscreen the gesture handlers only prevent the page pinch: no `zoomBy` and no pinch-state change, matching the wheel rule.

**`ui-primitives` gained a popover host.** `PopoverHost.tsx` defines the context value (`container`, `scale`, `boundary()`, `subscribe(listener)`) and `PopoverHostProvider`, which overrides only the fields it sets and inherits the nearest host otherwise. Without a provider the hook reports the browser defaults (`document.body`, scale 1, the browser window, `scroll`/`resize`), so a consumer that mounts none keeps its behavior. `Tooltip` always renders its bubble through `createPortal` and re-reads the anchor on every host signal; `Menu` in portal mode renders into the host container at `scale`, clamps its scaled size to `boundary()`, caps every list height and scrolls it — submenu-bearing menus included — and renders each submenu as its own portal node measured to open left/right and above/below with room; an anchor entirely outside the boundary dismisses the list. `PopoverHostProvider`, `usePopoverHost`, and the two public types are exported from the package entry.

**The board owns one screen-space popover layer.** The board root publishes a `BoardPopoverSurface` (`{ layer, root }`) and renders the layer outside the canvas transform at `BOARD_POPOVER_Z = 300` — above the chrome (100) and the handle ring (150), below the element-selection overlay (500). `BoardPopoverProvider` maps a window's host to `scale = zoom` (1 in fullscreen), `boundary` = the board box less a 12px inset, and `subscribe` = board pan, zoom, and window-rectangle changes; the dock and omnibar hosts use scale 1. `windowMenuDismissToken` plus `useBoardMenuDismiss` dismiss an open menu when its window moves, resizes, fullscreens, culls, or closes, while pan and zoom only move it with the trigger. Window frames, the chats panel, the dock, and the omnibar all mount the provider, and `menu-placement.ts` picks its side and alignment by the board boundary instead of the browser viewport.

**The shell blocks the page pinch outside the board.** `ui-layout` gained `pinch-guard.ts` (`installPagePinchGuard(root, block)`) and the validated `Config` field `blockPagePinchZoom` (default `true`). The guard registers non-passive `wheel` (ctrl only) and `gesture*` listeners on the shell frame's document — menus, tooltips, and dialogs portal into `document.body`, outside the frame's subtree, so a frame-bound listener misses them (П-37) — and calls `preventDefault` everywhere except inside `[data-surface="board"]`; the board handles its own pinch. `Cmd/Ctrl +/−/0` outside the board keep the browser's page zoom (decision R-2).

## Alternatives considered

- **Compensate the fixed tooltip's coordinates instead of portaling it.** Rejected: every transformed ancestor is a containing block for `fixed`, so the correction would re-derive the ancestor chain; the portal is the only stable coordinate space.
- **Put the board popover layer inside the canvas transform.** Rejected: it would inherit pan and zoom, scale text a second time, and clip cards at the canvas box.
- **Keep `Menu`'s portal in `document.body` and pass a board rectangle as a prop.** Rejected: one host context serves the browser default and the board, and threading geometry through every menu consumer duplicates the contract.
- **Attach the shell pinch guard to the frame root only.** Rejected (П-37): portals rendered in `document.body` (menus, modals) leave the frame's subtree, so their pinch events never reach a frame-bound listener; the document listener keeps the board exception local and covers the portals.
- **Detect mouse versus trackpad heuristically.** Rejected (R-4): the device signal is unreliable, so `Config.wheelMode` states the behavior explicitly.
- **Keep the fixed ±10% step and change only the sign handling.** Rejected: an inertial tail crossed the zoom range in one flick; `exp(−Δ·k)` with a per-event clamp is proportional to the gesture.
- **Apply the pinch in fullscreen.** Rejected: the fullscreen frame is not part of the canvas, and its wheel already blocks the board zoom while preventing the page pinch, so gesture events follow the same rule.
- **Keep the name `zoomTowardPointer`.** Rejected: the callers now compute a factor and a ratio, so the action takes a factor; the old name would misstate the contract.

## Consequences

In every board point — canvas, windows, chats panel and rail, floating chrome — a pinch now scales only the board around the gesture, a swipe pans it, and the scale follows the gesture magnitude; keyboard view commands apply only over the board; and an accidental pinch outside the board no longer scales the shell. Window tooltips and menus render in the board's screen space at the window's scale, clamp to the board box, follow pan and zoom, and dismiss on window lifecycle changes; the dock and omnibar popovers portal into the same layer at scale 1. What it gives up: `ui-primitives` behavior changed for the whole application — `Tooltip` always portals and `Menu` always caps and portals — so these upstream-package edits are fork divergences recorded in `docs/ketos/upstream-sync.md`, and the `ui-trajectory` test now queries the bubble in `document`; the old `zoomTowardPointer`/`setPan`+`setZoom` reset API is gone; and the shell guard listens on the shell document, so it also covers popovers portaled into `document.body` (П-37). The safe area, the window chats panel, and the `WorkspaceBrowser` seam this note once planned to absorb here moved out of the stage-23 acceptance scope: Д3.1/Д3.2 continue in [the stage-24 plan](../../../../docs/ketos/board-redesign-plan.md) as its Э1.4, while Д4/Д5 are superseded by that plan's window panels (Э4).

## Testing
