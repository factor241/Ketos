## 4. Отклонения

- **`ketos-inp` исправлен: конфиг-наблюдатель терял единственное событие создания.** Полные полосы этапа 21 и первая полоса этапа 22 падали на `packages/boot/app-boot/tests/hmr-config.spec.ts` в кейсах, где файл появляется сразу после `registerConfig`. Причина: `registerConfig` (вендоренная правка `vendor/hmr/src/index.ts`, пункт 9 журнала вендора) восстанавливает наблюдение на глубочайшем существующем предке и поллит его; первый `stat` поллера может принять единственное изменение mtime родителя (создание каталога или файла) за базовую линию, после чего событие не сообщается никогда. Под нагрузкой форк-воркеров базовый `stat` задерживается, и гонка срабатывает; микро-репродукция: 4/50 потерь при немедленном создании и 0/20 при задержке, в изоляции кейс проходил. Исправление: пока цель отсутствует, плагин опрашивает её существование (`ctx.setInterval`, интервал наблюдателя) и на первом появлении запускает тот же сериализованный refresh; chokidar ведёт последующие изменения. Правка записана в [vendor/README.md](../../../vendor/README.md#local-modifications) (пункт 9) и [upstream-sync.md](../upstream-sync.md); `ketos-inp` закрыт.
- **Полоса покрытия на Node 26.** На Node 26 полоса завершается кодом 1 из-за чужого теста `packages/experimental/agent-team/tests/team.spec.ts` (`ketos-pux`, утечка `SessionWriteLease`); эталонная полоса Кетоса — Node 24, где она зелёная (три подряд полных прогона в §5). Задача остаётся открытой вне этапов.
- **Команда полосы: литеральный `--` съедал флаги.** `pnpm run test:coverage -- --maxWorkers=4 --testTimeout=30000` передаёт vitest собственный `--`, поэтому флаги работали как фильтры файлов и не применялись — полосы этапа 21 и первые полосы этапа 22 шли с дефолтной параллельностью и таймаутом 5000 мс. Правильная форма — `pnpm run test:coverage --maxWorkers=4 --testTimeout=30000`; три итоговые полосы сняты ею.
- **Правки worktree `docs-plan-sync` перенесены по смыслу, а не `git apply`.** Файлы stage-22 отличаются от базы `stage-05`, поэтому семь незакоммиченных правок (README en/zh/i18n, Agent Note en/zh/i18n, строка отчёта этапа 5) перенесены вручную; ветка удалена (`-D`, потому что не в `main`, уникальных коммитов не было).
- **Артефакты вне MVP вынесены за пределы репозитория.** `presentation/`, `scripts/test-presentation-cdp.mjs` и `docs/ketos/ketos-context-specification.md` живут в `/Volumes/Projects/ketos-context/`; ссылок из репозитория на них не осталось (`verify-md-links` и `doc-sync` зелёные).
- **CI форка на GitHub не дал сигнала.** Workflow `CI` на ветвях стека висел в очереди (запуски отменены 2026-09-24, раннеры форку недоступны), Windows-полоса не проверялась, а упавшие проверки инфраструктурные: таймаут npm-резолва в `verify-npm-install-layout`, 404 bubblewrap в `E2E (real DeepSeek API)`, `Build PR preview` (Cloudflare без секретов), `Issue policy`/`Issue lifecycle` и `Pack npm tarballs` (последние падают и на базовом `main`), `Release (dsh)`. Приёмка MVP опирается на локальные гейты на `main` (таблица §5); починка CI форка — задача `ketos-cbn.1` (P1) в эпике плана Ф3 `ketos-cbn`.
- **План следующей фазы (Ф3 Части I) записан** — эпик `ketos-cbn` («Ф3. Воркер Temporal») с составом, приёмкой и рисками из §5 Части I; открытые задачи MVP (`ketos-pux`, `ketos-sm1`) и рекомендации аудита внесены в него.
