# @deepseek-ai/dsh-client-ui-board

[English](README.md) | 中文

## 概述

board 是 dsh 网页客户端的一个空间化主面板：一块由可移动、可缩放、可叠放的 agent 窗口组成的无限画布，每个窗口拥有一个 Harness 会话与完整的聊天 composer——预设、权限与模型芯片，斜杠命令与 `@` 菜单，以及附件。dock 列出窗口及其状态，并提供重命名或关闭菜单；Omnibox 把提示词送进当前聊天窗口的会话，没有聊天窗口可发送时先打开一个 agent 窗口；检查器把捕获到的元素芯片追加到该窗口的草稿；小地图镜像窗口布局。插件把看板注册为 `board` 面板，并使用共享的 Harness 主题绘制。

<a id="use-this-package"></a>
## 使用本包

通过侧栏面板列表中的 board 图标打开该面板；画布填满主面板并从空开始。拖动背景平移，滚轮缩放（0.2–2.0，以指针为中心），用 dock 的加号按钮在当前视图中心添加 agent 卡片（右键点击加号会打开目录菜单：agent、连接器与设置窗口）。窗口交互遵循同一约定：拖动标题栏移动，拖动边缘手柄缩放单轴，拖动角手柄按比例缩放窗口（两轴同一系数，对角固定），按住 Shift 拖动可关闭 24 px 网格吸附；点击窗口将其提到 z 序最前，关闭按钮移除窗口。按住 Space 拖动或用中键拖动可在看板任意位置平移——浮动浮层上同样有效，中键拖动手柄时平移而非缩放——`Ctrl/Cmd+0` 重置平移与缩放。滚轮落在窗口车道上滚动该车道，落在画布或浮动浮层上则以指针为中心缩放。当前窗口的八个缩放手柄也会画在浮动浮层之上，因此滑到 dock、Omnibox 或小地图下方的窗口边缘依然可以抓取。手柄环落在窗口外框之外，因此画布缩小时标题栏控件即使被缩放到比条带还薄，也依然可以点击。离开可见画布的窗口停止绘制——其车道、草稿、附件与聊天面板保持存活——视图返回时原样恢复；全屏窗口的邻居同样让位。每次按 Escape 只执行一个动作，顺序为菜单、聚焦的编辑器、元素选择、聊天面板、全屏。窗口绝不会小于创建时的尺寸（agent 窗口的默认聊天尺寸 552×648）——composer 的各行无法在更小的空间内排布——而宽度、高度或对角方向的放大不受限制。窗口整体比应用放大一档：标题、车道文本、芯片、控件与 composer 都读取声明在看板根节点上的一组度量（`--board-font-*` 以及控件、内边距与间距值），因此外框与其内容一同变大，而 dock、Omnibox、小地图与 portal 菜单保持应用的尺寸。标题栏的聊天按钮会从窗口左缘滑出面板（左缘无空间时改用右缘）：它是窗口管理项目与聊天的控制面。项目层列出所有含可见聊天的工区，外加未分组一档；其标题栏可注册文件夹（浏览器按层列出目录、面包屑可点击、可创建嵌套文件夹，然后把选中的目录注册为项目；宿主挂载的是原生选择器时不提供目录列表，该层随即把选择交给原生选择器并注册它返回的目录）、打开搜索框，以及打开分组与排序菜单（按项目或单一列表；手动或按更新时间）。每行尾部都有菜单——项目可重命名、上移下移、删除（只删注册，聊天与文件保留）；聊天可重命名、从最近完成的回合创建分支（窗口随后显示子会话）、移动与归档——在行上拖动同样会提交移动。聊天层列出某个项目的聊天及其相对时间与运行标记；选择其中一个会让窗口指向它，其标题栏可在该项目内新建聊天（项目已有空白聊天时直接复用）。面板是画布之上独立的一层：默认 300px 宽，拖动外缘可在 260–420px 之间调整（永不超过外框留出的空间），高度与外框一致，并随窗口移动、缩放、平移或缩放画布而跟随。折叠时——以及从未打开过它的每个聊天窗口——同一边缘保留一条 44px 的紧凑导轨，让面板一键可开；面板自身的标题栏承载再次收起它的按钮。面板打开时看板的整个浮动浮层——dock、Omnibox 与小地图——一起让位；面板折叠为导轨后浮层随即返回，此时导轨不再遮挡任何东西。因此没有根级浮层会压住面板的外缘、缩放手柄，或 overlay 呈现下窗口的下缘。Escape 先关面板，再退出全屏。进入全屏后，面板贴着看板面板左缘成为普通侧栏，聊天在它旁边以 768px 列居中排布。在 dock 或小地图中选择窗口会聚焦它并把视图居中到其上，唯一的例外是当前窗口在 dock 中的行——点击它只聚焦。dock 的每一行都会解析窗口标题、窗口类型，以及其会话通道报告的状态——会话缺失或待创建时为「创建中」，回合执行时为「执行中」，创建、提示词或回合失败时为「错误」，其余为「空闲」——行的本地化无障碍名称把标题与状态并列；右键点击行会打开经 portal 渲染的菜单，提供重命名（就地编辑器）与关闭窗口，关闭会移除窗口，而其聊天仍存活并留在列表中。标题栏与 dock 用聊天标题命名窗口，聊天还没有标题时回退到该类型经本地化的模板名，并跟随聊天重命名或重新绑定；点击标题栏中的名字——或双击 dock 行——可编辑窗口自己的名字，该名字覆盖聊天标题，直到被清空。窗口首次渲染时会创建自己的会话（该会话出现在侧栏列表中，聚焦窗口会使其成为当前会话）。Omnibox 在按 Enter 或 Send 时发送：它会去除草稿首尾空白，由桥把文本作为排队回合送进当前聊天窗口的会话，当前窗口不是聊天窗口时改开一个 agent 窗口；桥会等待会话创建完成，因此窗口刚打开就发送也不会丢失。其 `+` 菜单包含「新建窗口」一节——agent、连接器与设置会打开真实的看板窗口，克隆、仪表板与任务则给出各自的本地化「MVP 暂不提供」提示——以及能力条目：附件把文件选择器命令路由到被寻址窗口的 composer，听写把语音转写切换进 Omnibox 草稿并在浏览器无法启动听写时给出提示，网页搜索说明在此 MVP 中没有从客户端通往宿主侧 web 能力的路径，选择元素则启用检查器；看板的所有菜单都经 portal 渲染，并开在空间更充裕的一侧。检查器激活时点击元素会捕获一个确定性的 `tag:nth-of-type(n)` 选择器路径——锚定在看板表面，或锚定在 `body`——以及一段语言无关的描述，涵盖元素的标签、所在窗口的类型与标题、`data-board-action`、无障碍名称、工具提示，以及 60 字符的文本摘录，并把本地化的芯片追加到被寻址窗口的 composer 草稿，寻址规则与 Omnibox 相同，即当前聊天窗口，否则新建 agent 窗口；浮层让指针通过，在捕获阶段取得点击，因此其下方的控件绝不会被激活，遇到打开中的菜单时让位，按 Escape 取消。composer 与主聊天一致：`+` 打开操作菜单（文件与图片、目标、计划、反馈、压缩、权限、导出），`/` 按输入过滤斜杠命令并显示参数提示与描述，`@` 提示文件、目录与会话，芯片行可切换权限预设（完全访问走风险确认）以及模型与其推理等级，圆环显示上下文占用，麦克风按钮在引擎提供语音识别时把语音转写写入草稿；以已知命令开头的行会带着参数对会话执行——连同草稿中的图片与已上传文件，因此不接受附件的命令由宿主以自己的原因拒绝——图片遵循宿主投影出的上限（超过数量、单张大小或总大小的批次会连同本地化原因被拒绝），其他文件后台上传并以回执随行；卡片还接受拖入的文件与粘贴进输入框的文件；agent 预设芯片是 composer 中唯一的设置芯片（工作目录由窗口的聊天面板承载），面板的文件夹动作会把选中的目录注册为新聊天的项目文件夹。Enter 发送，Cmd/Ctrl+Enter 引导正在执行的回合，Shift+Enter 换行，圆形按钮停止；卡片会自行测量宽度，在窗口变窄时隐藏芯片文字或换行工具栏，因此发送控件在任何尺寸下都可达；`Load earlier turns` 会把更早的回合拉入车道，保持读者的位置并在加载期间禁用自身；车道显示正在运行的工调用及其标记，对结果所属调用落在已加载窗口之外的行给出重试控件，空、创建中、失败、运行与受阻状态各自渲染自己的本地化行；标题栏的全屏按钮让窗口铺满看板面板，按 Escape 或再点同一按钮即可返回；全屏期间其他窗口以及 dock、Omnibox、小地图都会让位，返回时恢复的是窗口保存的矩形。

<a id="understand-the-implementation"></a>
## 理解实现

**Runtime invariant:** 无已发布的 companion。面板条目把 `main` 槽位连同唯一的 engine store 一起注册，并声明它渲染的各个层；条目的销毁证明移除，同时可通过 `board.*` 槽位声明独立观察。

<details>
<summary>实现细节 — 点击展开</summary>

唯一的注册面：`apply` 以槽位方式组合看板。`main` 面板条目声明 `board.canvas`、`board.dock`、`board.omnibar`、`board.minimap` 并通过 `renderSlot` 渲染它们；canvas occupant 声明 `board.windows`；窗口层声明 keyed 的 `board.window`（每个窗口类型一份注册——实例经由 owner props 传入，因此一个 occupant 服务该类型的全部窗口）与 keyed 的 `board.window.body`（每种 body kind 一份注册），并把 body 分发器交给每个窗口外框；同一个 `apply` 还注册 `sidebar.panellist` 图标。keyed 的键就是 `WindowKind` 与 `WindowBodyKind` 联合类型，因此为未知键注册是编译错误。board 状态是一个在面板条目上声明的 `dsh-client-store` engine store——平移、缩放、视口盒、窗口映射、z 序与元素选择标志——配合纯 draft action（`setPan`、`setZoom`、`zoomTowardPointer`、`setViewport`、`addWindow`、`openWindow`、`moveWindow`、`resizeWindow`、`setWindowBodyKind`、`focusWindow`、`centerOnWindow`、`setWindowFullscreen`、`exitFullscreen`、`closeWindow`、`setSelectingElement`）。窗口 z-index 区间被限制在浮动浮层之下，且提起窗口只写入该窗口的取值，因此其他窗口保持各自的状态身份。每个层与外框都通过框架 `useStore` 席位读取同一个 handle；组件自身不持有任何订阅——标题栏拖动与每个缩放手柄都是自行读取手势起始缩放的叶子组件，因此画布缩放不会重渲染窗口 body，聊天面板也只在展开时订阅视图变换。可见文案由 locale 接管：`apply` 通过 `ctx.locale` 注册 `board` 命名空间词典，每个承载文案的条目声明该命名空间，从而在其组件上放置类型化的 `t` 席位。样式直接读取共享主题：每个组件在自身旁边拥有一个 CSS Module，内联样式只承载放置与随平移/缩放计算的度量，规则只引用 `--dsw-*` 语义别名——浮层面板使用主题的 layer-2 填充与 elevation 发丝描边（聚焦窗口重绑到业务强调色），内部分隔线为 0.5 px 发丝线，画布点阵跟随边框色阶。交互外框来自 `ui-primitives`：标题栏关闭按钮与 composer 动作使用 Harness 图标，dock 行与 composer 动作包在 `Tooltip` 中，Omnibox 的操作菜单是共享的 `Menu`，dock 控件位于 floating-fill token 上。因此看板与其他面板一样跟随外壳的明暗偏好。手势只有一个归属：每次拖动（画布平移、标题栏、窗口缩放、面板缩放、行重排）都经过 `pointer-gesture.ts`，它在 pointerup、pointercancel 或宿主组件卸载时结束，因此不会留下监听器或指针捕获。看板根节点持有唯一的非被动 wheel 监听器：跳过窗口车道与展开的聊天面板，其余位置缩放；画布容器上的 `ResizeObserver` 是已测量视口的唯一归属；离开画布的窗口通过 `canvas/culling.ts` 以 `content-visibility` 隐藏——绝不卸载。窗口会话位于 apply 侧的桥（`session-bridge.ts`）：窗口 id → 会话的映射、`sessions.create()`/`open()`/`binding()` 序列，以及 chat/会话订阅全部留在插件闭包中，绝不进入 store；每个窗口的车道状态——组装后的聊天、聊天标题、历史标志、运行中的调用、图片上限，以及回合与发送失败——通过每窗口一个身份稳定的 channel 重新发布；关闭窗口会丢弃它的桥记录，而会话本身保持存活并仍在列表中。外框与 body 注册把该 channel 暴露为 keyed hook `useWindowSession(windowId)` 以及 composer 回调（`ensureWindowSession`、`sendPrompt`、`cancelPrompt`、`loadOlderTurns`、`executeCommand`、`uploadFile`），因此一个注册即可服务所有窗口，组件只接收普通数据；`uploadFile` 通过宿主的后台上传服务暂存非图片文件，并把回执交给 composer，由提示或命令随行携带。看板外框共享寻址与放置规则：`open-window.ts` 解析命令作用于哪个聊天窗口（`resolveChatWindow`——当前聊天窗口，否则新建 agent 窗口），store 中的 `composerIntents` 队列携带追加文本与打开文件选择器两类命令，直到 `ComposerBar` 消费它们（文件选择器会等到 composer 能接受文件，窗口关闭则丢弃其排队命令），`element-capture.ts` 构造检查器芯片背后的确定性选择器与语言无关描述，`menu-placement.ts` 是每个看板浮层共用的单一规则，让列表开在更宽裕的一侧。Omnibox 的发送经过桥的 `whenReady` 等待，它在窗口拥有会话（或创建失败）时落定，因此窗口打开瞬间提交的提示词不会丢失。

</details>

<a id="model-experience"></a>
## 模型体验

无模型体验：board 是纯浏览器画布，不注册任何工具、提示词段落或会话事件，渲染的一切都是 board 本地视图状态。

#### KV Cache 效果

无效果；board 不向任何模型请求添加内容，也不消费会话日志。

## 已知限制与暂缓事项

<a id="known-limitations-and-deferred-work"></a>

这些限制属于当前包的约束。

- **窗口车道只渲染正文与工具名** —— assistant 文本以 Markdown 呈现且流式文本可见，运行中的调用显示为带标记的单行，已落定的结果折叠为单行。该范围之外的转录节点——插话提示、压缩检查点、达到输出 token 上限的回合，以及历史回合失败（车道只显示会话最近一次回合失败）——目前不渲染；完整的工具卡片与这些表面随拥有它们的阶段到来。
- **确认与提问只在主面板中回答** —— 窗口既不渲染待处理的请求，也不显示存在请求的指示，其 composer 在等待回答期间不会阻止发送；两种表面都由主面板的 composer 承载。
- **看板的文件芯片只存在于草稿期间** —— 非图片文件经宿主的上传服务暂存，并在其窗口存活期间以回执随行；芯片只保留名字与重试，不保留字节或上传进度，回执在窗口关闭后无法再次发送。`@` 提及插入纯文本而非编辑器芯片。
- **窗口 composer 保有自身的提交策略（在此决定）** —— Enter 排队，Cmd/Ctrl+Enter 引导，且不读取提交偏好设置：`ui-conversation` 的 `busyEnter` 偏好位于该插件的设置命名空间，且只映射裸 Enter 手势，而看板的窗口按文档在两个手势上保留排队/引导组合。
- **命令的失败行可能使用宿主原文** —— 处理程序被拒或附件被拒时，错误在「Command failed:」之后按宿主自己的措辞显示，而未匹配的行显示看板自己的未知命令文案；失败信息保留到下一次发送。看板的命令列表在宿主注册表之外补上自己的 `/file` 与 `/model` 条目（文件选择器与模型菜单）。
- **队列没有编辑器** —— 队列中的一条消息只提供引导与移除，无法修改其文本。
- **助手 Markdown 保持应用的正文字号** —— 共享的 Markdown 表面读取应用的字体大小设置，因此只有窗口自身的 chrome、转录文本与 composer 采用窗口缩放；要放大助手正文请调高应用的字体大小。
- **聊天面板没有取消归档，也没有删除会话** —— 归档聊天是单向的，客户端根本没有删除会话的能力，因此聊天行菜单中的删除条目是空操作；删除项目只删除注册，绝不动它的聊天与文件。
- **面板的文件夹浏览器只读取 browse 选择器** —— 挂载平台原生选择器的宿主不提供目录列表，此时该层会说明这一点，并把选择交给原生选择器；这类宿主上没有应用内浏览。
- **聊天面板打开时 dock 与小地图让位** —— 面板是管理界面，否则它们的条带会压住面板外缘与缩放手柄；把面板折叠为导轨后它们就会返回，外框的聊天按钮可再次展开面板。
- **面板打开时整个浮动浮层让位** —— 展开的聊天面板是管理面，dock、Omnibox 与小地图一起停止渲染，因此不会有根级浮层压住面板的外缘、缩放手柄，或 overlay 呈现下窗口的下缘；面板折叠为导轨后浮层返回。
- **缩放手柄随当前窗口升到浮层之上** —— 手柄环只为被聚焦的窗口绘制，因此当窗口边缘落在 dock、Omnibox 或小地图下方时，仍需要先点击该窗口外框任意位置，其手柄才会升到这些层之上。
- **窗口数量超出面板高度后 dock 会滚动** —— 每窗口一行在 900px 面板中大约十来个窗口后便放不下，因此导轨改为滚动，而不是裁掉行以及添加／重置控件。
- **裁剪使用固定的世界边距** —— 窗口超出可见画布 480 世界单位后，其内容停止绘制与命中测试，与其尺寸无关；它的盒子仍在布局中占位，该边距覆盖手柄与展开的聊天面板，隐藏期间窗口保持自身状态。
- **每窗口设置来自 composer** —— agent 预设芯片只在会话仍然空白时可切换，模型芯片可切换模型与其推理等级；模型选择还会保存为 `agent-default-model` 系统默认值。已启动的会话保留其工作目录，只有仍然空白的会话才能在重新选择文件夹后重建。
- **外框的 body 分发器是 owner prop** —— 窗口层是 `board.window.body` 的唯一声明者（槽位核心允许每个键只有一个声明者），因此它向每个外框传入 `renderBody` 回调，而不是外框自己的 `renderSlot` 席位。
- **布局仅限会话** —— `apply` 创建 board store 时不带 persist key，因此平移、缩放与窗口排列在页面刷新后重置。
- **工具与设置窗口只有外框没有内容** —— dock 的 `+` 目录与 Omnibox 的「新建窗口」一节会打开 agent、连接器与设置窗口，其主体仍为空；克隆、仪表板与任务窗口在 MVP 中没有创建入口。真实的每窗口字段随拥有它们的阶段到来，而 Harness 本身并没有客户端 system prompt 编辑器。
- **dock 状态是窗口会话通道的粗略四态投影** —— 创建中、执行中、空闲或错误，不提供逐工具的进度；创建、提示词或回合失败都显示为错误。
- **dock 的重命名与关闭位于行的右键菜单中** —— 没有可见的逐行关闭按钮，右键点击行才会打开该菜单。
- **检查器芯片是普通草稿文本** —— composer 没有编辑器芯片，因此捕获的芯片以文本形式随行，携带 DOM 描述与 `:nth-of-type` 选择器，而不是截图。
- **Omnibox 的网页搜索与克隆、仪表板、任务窗口以本地化的「此 MVP 不可用」提示作答** —— 这些表面属于宿主或后续阶段。
