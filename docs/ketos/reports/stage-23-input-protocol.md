# Этап 23, Д0.3: ручной протокол ввода — тачпад, мышь, Safari

> Подэтап Д0.3 плана [«Аудит доски Кетос»](../board-audit-plan.md). Протокол фиксирует поведение ввода, которое нельзя достоверно воспроизвести синтетическими событиями: инерционный хвост тачпада, жесты Safari (`gesturestart`/`gesturechange`/`gestureend`) и реальные `deltaMode` колёс мыши.
>
> Исходное состояние — `main` @ `этап 23`. Таблица заполняется заново после подэтапов Д1–Д6 и перед приёмкой Д7.1; формулировки сценариев при этом не меняются, чтобы наблюдения сравнивались между этапами.

## 1. Как заполнять

- Стенд: `pnpm ketos web` — команда из [mvp-e2e.md](../mvp-e2e.md) (алиас `ketos --profile web`). Открывать напечатанный командой URL с токеном (`http://127.0.0.1:3080/?token=…`); страница без токена отвечает 401.
- Подготовка: активная панель — доска, открыто хотя бы одно окно агента, окно браузера 1440×900, масштаб страницы 100%, видны сайдбар приложения «Рабочие папки» и плавающие панели доски (док, омнибар, мини-карта).
- Браузеры: Chrome (Chromium) и Safari на macOS; Firefox — при наличии. Каждый сценарий выполняется в каждом браузере отдельно, ячейки заполняются независимо.
- Устройства: настоящий тачпад (пинч, свайп, инерция) и настоящая мышь с колесом (колесо, `Ctrl`+колесо, средняя кнопка); синтетические события через DevTools не подходят.
- Запись результата — дословно: «работает / не работает + что именно произошло». Для зума фиксируются направление, примерное число шагов и упор в предел 0.2 или 2 (`board-settings.ts:55-58`); для пинча вне доски — менялся ли масштаб всего интерфейса (сайдбар, шрифты), а не только доски.
- Масштаб страницы возвращается к 100% через меню браузера («Вид → Фактический размер» в Chrome): `Cmd/Ctrl+0` перехвачен доской (П-05). Если сценарий изменил масштаб страницы, перед следующим сценарием вернуть 100% и перезагрузить страницу.
- Ячейка `«код»: …` заполнена чтением кода и ручной проверки не требует; ячейка `требуется ручная проверка` пуста и заполняется наблюдением. При повторном заполнении после Д1–Д6 кодовая ячейка переписывается наблюдаемым результатом.
- Маршрутизация событий: в Safari пинч приходит жестами трекпада (`gesture*`), в Chrome и Firefox — как `wheel` с `ctrlKey`, а свайп — как `wheel` без модификатора; в Firefox реальное колесо присылает `deltaMode = 1` (строки), в Chrome — пиксели.

## 3. Что подтверждено кодом в исходном состоянии

| Факт | Проблема | Доказательство |
|---|---|---|
| Обработчиков `gesturestart`, `gesturechange`, `gestureend` нет нигде в клиенте | П-04 | Поиск по `packages/client` и `apps/web` не находит ни одного слушателя `gesture*`; Safari-пинч доске не виден |
| `Cmd/Ctrl+0` перехватывается всегда, пока доска смонтирована | П-05 | `BoardViews.tsx:93-100`: слушатель `keydown` на `globalThis`, условие «`metaKey` или `ctrlKey` и `key === '0'`», без проверки `pointerInsideRef` (объявлен в `:41`, используется только веткой пробела в `:101`) |
| Обработчиков `Cmd/Ctrl+=` и `Cmd/Ctrl+−` для доски нет | П-06 | Поиск по `packages/client` и `apps/web` не находит веток для `=`, `-`, `Equal`, `Minus`, `NumpadAdd`, `NumpadSubtract`; масштаб доски меняют только колесо и кнопки |
| Пинч-зум страницы вне доски не блокируется | П-07 | Ни `wheel` с `ctrlKey`, ни `gesture*` не слушаются на корне приложения; `touch-action` в клиентских стилях не задан; в плане это подтверждено браузерным замером над сайдбаром |
| Колесо над холстом зумит, над окном и панелью — нет | R3, П-01, П-02, П-08 | `wheel-zoom.ts:14-18` отдаёт окну и панели их прокрутку; `BoardViews.tsx:79-86` зумит по знаку `deltaY`; `store.ts:338-345` — шаг ±10%, `deltaX` игнорируется |
| Рейка не помечена `data-board-panel` | следствие R3, сценарий 4 | `WindowChatsPanel.tsx:451` ставит `data-board-panel-rail`, а `wheel-zoom.ts:17` проверяет только `data-board-panel` |

## 4. Повторное заполнение после Д1–Д6

- После Д1.1–Д1.3 переписываются сценарии 1–10: пинч в любой точке доски масштабирует только доску, свайп перемещает её, жесты Safari работают, инерция не доводит масштаб до предела одним жестом.
- После Д1.4 переписываются сценарии 11–13: над доской `Cmd/Ctrl+0/=/−` управляют доской, над сайдбаром — браузером; `Cmd+0` над сайдбаром возвращает масштаб страницы 100%.
- После Д1.5 переписывается сценарий 6: пинч над сайдбаром не меняет масштаб страницы.
- После Д2–Д6 таблица перезаполняется без ожидаемых изменений: эти этапы не меняют ввод, и расхождение с состоянием после Д1 считается регрессией.
- Перед Д7.1 таблица заполняется целиком для итогового состояния; отклонением считается любое расхождение с ожидаемым поведением из раздела 4 плана (П-01 … П-08).
